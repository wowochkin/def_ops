# Штаб на LLM (`services/staff`)

Немецкое командование в переигровке Берлинской операции ведёт локальная
модель — Qwen3.8 в LM Studio (протокол OpenAI). Облачных вызовов нет.
План — `docs/plans/simulation.md`.

Сейчас здесь **этап 0**: клиент модели и проверка её качества на
контрольных обстановках до основной разработки.

## Проверка модели на Mac

1. **LM Studio:** загрузите Qwen3.8 (MLX, 4 или 8 бит). Во вкладке
   Developer нажмите Start Server: адрес по умолчанию `http://localhost:1234`.
   Длину контекста задайте не меньше 16 000 токенов: промпт и размышление
   занимают несколько тысяч.
2. **Прогон** из корня репозитория:
   ```
   npm install
   npm run llm:eval
   ```
   Без параметров берётся первая загруженная модель, размышление `medium`,
   все шесть обстановок по одному разу. Один прогон занимает от нескольких
   минут до получаса, в зависимости от модели.
3. **Сравнение вариантов:**
   ```
   # две сборки модели и три режима размышления, по 2 повтора
   npm run llm:eval -- --model qwen3.8-27b-mlx-4bit,qwen3.8-27b-mlx-8bit --thinking off,medium,high --repeat 2
   # одна обстановка
   npm run llm:eval -- --only 04
   ```
   Идентификаторы моделей — как в LM Studio (список выводится при запуске,
   если имя указано неверно).
4. **Результат** — каталог `evals-out/<время>/`:
   - `report.md` — сводка по скорости и качеству, затем по каждой обстановке:
     что было в истории, ответ модели (оценка обстановки, замысел, приказы,
     доклады наверх, риски), автоматические признаки и строки для оценки
     эксперта;
   - `results.json` — все ответы и замеры целиком.

## Контрольные обстановки (`evals/`)

| № | момент | развилка |
|---|---|---|
| 01 | вечер 15.04 | оборона против кюстринского плацдарма: отвести ли войска с первой позиции |
| 02 | вечер 17.04 | прорыв на Зееловских высотах: куда и как вводить резервы |
| 03 | вечер 20.04 | угроза окружения 9-й армии: держать Одер или отходить |
| 04 | вечер 25.04 | котёл под Хальбе: к Берлину или на запад к 12-й армии |
| 05 | вечер 28.04 | Берлин: оборона Цитадели или прорыв |
| 06 | утро 18.04 | ловушка: невыполнимый приказ о контрнаступлении |

Автоматические признаки ищут в ответе ожидаемые элементы решения по
ключевым словам. Это подсказка для экспертов, а не оценка: решение
оценивают люди. Формальная проверка строже: ответ должен разобраться по
схеме, приказы должны отдаваться только своим формированиям из обстановки.

## Настройки

| переменная | по умолчанию | смысл |
|---|---|---|
| `DEFOPS_LLM_URL` | `http://localhost:1234/v1` | адрес сервера; из Docker на Mac — `http://host.docker.internal:1234/v1` |
| `DEFOPS_LLM_MODEL` | первая загруженная | идентификатор модели |
| `DEFOPS_LLM_THINKING` | `medium` | `off` / `low` / `medium` / `high` — глубина размышления |
| `DEFOPS_LLM_TIMEOUT_S` | `600` | предел на запрос |
| `DEFOPS_LLM_MAX_TOKENS` | `16000` | предел длины ответа вместе с размышлением |
| `DEFOPS_LLM_TEMPERATURE` | 0,6 с размышлением / 0,7 без | |
| `DEFOPS_PROMPTS_DIR` | `services/staff/prompts` | промпты; правка действует со следующего запроса |
