# Тактическая карта: движок знаков и редактор

Шаг 1 продукта: движок, который рисует условные знаки военно-исторических карт
(стрелки ударов, линии фронта, рубежи с зубцами, окружённые группировки, знаки
объединений, подписи) в географических координатах, и редактор для их нанесения.

**Библиотека знаков** — 238 элементов в 18 логических категориях (действия войск;
линия фронта и положение войск; рубежи и разграничительные линии; районы и
группировки; соединения и объединения; пункты управления и связь; артиллерия и
огневые средства; танки и бронетехника; авиация, ПВО и десант; флот;
фортификационные сооружения; инженерные заграждения; переправы и дороги; тыл и
обеспечение; разведка и охранение; особые отметки; подписи; топографическая основа).
У каждого элемента — описание, три варианта оформления, учёт
принадлежности и ссылка на первоисточник со страницей. Полный перечень —
[docs/library.md](docs/library.md), PDF-справочник — [docs/library.pdf](docs/library.pdf),
наглядный справочник — `/library.html`.

Уставные знаки — система **РККА 1942–45** по первоисточнику TM 30-430 «Handbook on
U.S.S.R. Military Forces», гл. XII (1946): штабы флажками по ступеням, ромбы танков
по типам, ДОТ/ДЗОТ, заграждения, разграничительные линии с кружками и крючками;
свои — красным, противник — синим.

Знаки, которых в первоисточнике нет (знаки исторических карт, флот, партизаны,
разграничительные линии армий и фронтов), помечены «сверить».
Система знаков одна; варианты оформления меняют только начертание. Нормативное
оформление — только «Уставные знаки РККА». Остальные два — не системы знаков, а
манера исторических карт, воспроизведённая по образцам из `apps/editor/demo/reference/`:

| Оформление | Образец | Что воспроизведено |
|---|---|---|
| **Инфографика** | «Разгром берлинской группировки» | сплошные стрелки и стрелки с растворяющимся хвостом, стрелки танковых соединений (белый контур и ромб), укрепления с зубцами, полоса наступающих, окружённые группировки (штриховка и крест «уничтожено»), контрудары, ж/д, населённые пункты |
| **Историческая карта** | карта Берлинской операции из атласа; схема штурма Рейхстага | стрелки-клинья с градиентом вдоль оси, открытым хвостом-вырезом и объёмным бликом (по периодам и сторонам: 16–19 апр., 20–25 апр., 26 апр.–8 мая, Войско Польское, контрудары противника, союзники), тонкие стрелки, танковые корпуса (ромб и полоса), речная флотилия, линии фронта по датам (многослойные), оборонительные рубежи, овалы танковых армий и кавкорпусов, резервы «Р», города-крепости, авиация, даты встреч, дата в рамке |; позиции подразделений по датам (сплошная, двойная, пунктир, точки, штрихпунктир; засечки на концах), объёмные стрелки атак, оборона противника, противотанковый ров с водой, Знамя Победы, огневые точки |

## Запуск

```bash
npm install

# только редактор (работает и без сервера — карты хранятся в браузере)
npm run dev                 # http://localhost:5173/  · справочник знаков: /library.html · сверка: /compare.html

# платформа целиком для разработки: шлюз :8080, документы :8101, рендер :8102, реестр :8103
npm run dev:services        # в отдельном терминале; редактор сам подключится через /api
                            # без БД: карты — в файлах ./data, реестр — в памяти;
                            # с БД: DATABASE_URL=postgres://… npm run dev:services
# PostGIS для разработки:  docker run -d -p 5433:5432 -e POSTGRES_DB=defops -e POSTGRES_USER=defops -e POSTGRES_PASSWORD=defops postgis/postgis:16-3.4-alpine

# всё одной командой из собранного редактора (шлюз отдаёт и фронтенд, и API)
npm start                   # http://localhost:8080/

# в контейнерах
docker compose up --build   # http://localhost:8080/ ; PostgreSQL + PostGIS поднимается рядом (том db-data)
                            # AUTH=keys API_KEYS="ключ:организация" — обязательные ключи; DB_PASSWORD — пароль БД
                            # за корпоративным прокси: сертификаты — в deploy/extra-ca/*.crt, HTTP(S)_PROXY — из окружения
                            # Docker Hub отвечает 429: образы берутся с зеркала Google и переименовываются, например
                            #   docker pull mirror.gcr.io/library/node:22-alpine && docker tag mirror.gcr.io/library/node:22-alpine node:22-alpine
                            #   docker pull mirror.gcr.io/postgis/postgis:16-3.4-alpine && docker tag mirror.gcr.io/postgis/postgis:16-3.4-alpine postgis/postgis:16-3.4-alpine

npm test                    # ядро + сквозные тесты сервисов через шлюз (с DATABASE_URL — ещё и на PostgreSQL)
npm run typecheck
npm run docs:library        # пересобрать docs/library.md из описания библиотеки
npm run docs:pdf            # PDF-справочник docs/library.pdf (нужен запущенный редактор)
```

## Архитектура

Монорепозиторий: ядро-библиотека, микросервисы за API-шлюзом и редактор.
Подробно — [docs/architecture.md](docs/architecture.md), контракт API —
[docs/openapi.yaml](docs/openapi.yaml).

```
packages/core          движок знаков: модель, слои, геопривязка, SVG, GeoJSON (без зависимостей от окружения)
packages/service-kit   каркас микросервиса: роутинг, ошибки, журналы, health/ready, организация, межсервисные вызовы
packages/api-client    типизированный клиент API (браузер и Node)
packages/db            PostgreSQL: пул, миграции по схемам сервисов, транзакции
services/gateway       API-шлюз: API-ключи → организации, маршрутизация, CORS, статика редактора
services/documents     хранение карт: ревизии, оптимистичная блокировка, слои, события (SSE); PostgreSQL или файлы
services/registry      реестр объектов: формирования, сооружения, пункты; характеристики во времени, PostGIS
services/render        SVG/GeoJSON по документу, импорт GeoJSON, каталог знаков (без состояния)
apps/editor            редактор (React); карта подключается через адаптер MapEngine (сейчас — MapLibre)
deploy/, docker-compose.yml
```

**Слои.** Каждый объект лежит в слое; слои можно скрывать, блокировать,
менять им прозрачность и порядок, переименовывать, удалять (с переносом
объектов). Новые объекты ложатся в активный слой или — в режиме «авто» — по
смыслу знака (основа, противник, свои войска, линии фронта, населённые
пункты и подписи). Скрытый слой не мешает привязке хвостов стрелок. В SVG
слои экспортируются группами Inkscape/Illustrator, в API — управляются
отдельно (`/documents/{id}/layers`), а внешняя система может «владеть» своим
слоем и заливать в него данные в GeoJSON.

**Реестр объектов и время.** Знак на карте можно связать с объектом реестра
(«150 сд», «Рейхстаг»): характеристики хранятся один раз и видны со всех карт.
У типа объекта — схема полей (номер, ступень, род войск; во времени — подчинение,
командир, численность, положение…), организация может добавлять свои поля и типы.
Изменения записываются фактами «с даты» со ссылкой на источник. Под картой —
шкала времени: карта показывает обстановку на выбранный момент, знаки появляются
и исчезают по своим периодам и меняют положение по датам; правка на карте меняет
положение, действующее на этот момент. Реестр отвечает и на вопрос «какие объекты
были в этом районе на 25 апреля» (PostGIS). Модель — [docs/data-model.md](docs/data-model.md).

**Другие карты и системы.** Любая XYZ/WMS-подложка добавляется в редакторе
без кода; другой картографический движок подключается реализацией интерфейса
`MapEngine`; обмен с внешними системами — REST, GeoJSON и поток событий.

## Ядро

**Координаты и масштаб.** Объекты хранятся в долготе/широте. Размеры знаков
задаются в пикселях на опорном масштабе документа (`refZoom`), поэтому при зуме
карта ведёт себя как отпечатанный лист: всё масштабируется согласованно, и
пропорции знаков не меняются. SVG строится один раз в мировых координатах и
переносится на карту одним аффинным преобразованием; при панорамировании и зуме
геометрия не пересчитывается.

**Стрелки.** Ось — сглаженная кривая через опорные точки. Ширина меняется от
хвоста к шейке (характер сужения настраивается), у наконечника задаются размах,
длина, стреловидность «усов» и кривизна граней. Заливка вдоль изогнутой оси
(цвет и прозрачность) строится поперечными срезами внутри клипа по контуру,
поэтому градиент идёт точно по кривой, без швов. Есть контур (с открытым
торцом хвоста или без), осевая линия, объёмный блик и украшения на оси
(ромб, полоса, засечка, «птички»).

**Привязка хвоста к линии фронта.** Если стрелка начинается у линии или
контура, её хвост хранит ссылку на объект и положение на нём (доля длины).
Основание хвоста идёт вдоль линии фронта (с учётом угла подхода, чтобы ширина
сохранялась), кромки тела плавно выходят из линии, а сам хвост слегка заходит
под линию. При правке линии фронта все привязанные стрелки следуют за ней.

**Линии** — набор параллельных слоёв со смещением от оси: у каждого слоя цвет,
толщина, пунктир, зубцы (шаг, длина, сторона, наклон, штрих или треугольник) и
засечки на концах. Так собираются многоцветные линии фронта атласа, рубежи,
позиции подразделений, ж/д.

## Редактор

- Слева — палитра знаков по категориям с выбором оформления, с живыми миниатюрами (рисуются тем же движком).
- Стрелка: щелчки от хвоста к острию; первый щелчок у линии/контура привязывает
  хвост (Alt — без привязки); двойной щелчок или Enter — завершить, Backspace —
  убрать последнюю точку, Esc — отмена.
- В режиме выбора: перетаскивание объекта и узлов, «+» на серединах сегментов —
  новый узел, двойной щелчок по узлу — удалить. Хвост стрелки можно перетащить
  на другую линию (зелёная ручка — привязан). Круглые оранжевые ручки — ширина
  хвоста и размах/стреловидность наконечника.
- Справа — инспектор (все параметры знака, слой), панель слоёв и растровые
  подложки (скан карты с привязкой за углы и прозрачностью).
- Ctrl+Z / Ctrl+Shift+Z, Ctrl+D — дублировать, Del — удалить.
- Сохранение на сервер (Ctrl+S) с ревизиями и разрешением конфликтов, открытие
  с сервера, живые обновления при правке другим пользователем или системой.
- Файлы: документ JSON, импорт/экспорт GeoJSON, экспорт SVG (слои — группами)
  и PNG со встроенными шрифтами, автосохранение в браузере.
- Подложка: «бумага», OpenStreetMap, OpenTopoMap, спутник или своя XYZ/WMS.

## Демо-карты

«Файл / примеры…» → реконструкции фрагментов образцов. Координаты сняты с
образцов и переведены в географию аффинной привязкой по населённым пунктам
(МНК). Оригинал подложен растром: включите его в списке подложек и сравните.
