# Выставочный стенд на Windows без интернета

Целевая машина: Windows 10 x64, NVIDIA RTX 4060 Ti с 16 ГБ видеопамяти и три телевизора.
Объём оперативной памяти и модель устройства, к которому подключены телевизоры, нужно уточнить на месте.
Код содержит отдельный Windows-путь озвучки, но реальный прогон на этой конфигурации ещё не выполнен.
Скорость, качество голоса и размещение языковой модели вместе с TTS в 16 ГБ нельзя подтвердить тестами на Mac.

## 1. Сначала проверить подключение телевизоров

В Windows открыть **Параметры → Система → Дисплей → Определить**. Система должна видеть три разных дисплея.
Включить **«Расширить эти экраны»**, расположить их в том же порядке, что на стойке, и проверить разрешение каждого.
Перетащить обычное окно по всем трём экранам: на каждом должна показываться своя часть рабочего стола.

Обычный HDMI-сплиттер размножает один сигнал и не создаёт три независимых дисплея. Если Windows видит только
один экран, настройка приложения этого не исправит: нужны отдельные видеовыходы либо устройство, которое
действительно предоставляет независимые дисплеи. Совместимость конкретного сплиттера/хаба определяется его моделью.
См. [настройку нескольких мониторов Microsoft](https://support.microsoft.com/en-us/windows/hardware/display-graphics/how-to-use-multiple-monitors-in-windows)
и [пояснение о сплиттерах](https://support.microsoft.com/en-gb/windows/hardware/display-graphics/troubleshoot-external-monitor-connections-in-windows?nochrome=true).

В меню оператора «Экраны» назначить роли «Штаб ИИ», «Карта», «Ход операции» и проверить
назначения кнопкой «Показать номера экранов». Панель показывает, сколько экранов запрошено и доступно;
список обновляется автоматически и кнопкой «Обновить подключения». Меню можно вызвать из любого окна:
удержать левый верхний угол три секунды или нажать `Ctrl+Alt+Shift+O`; ввод ПИН откроется в управляющем окне.
Настройку повторить после изменения кабелей, разрешения или масштаба Windows.
Проверять нужно и отключение с повторным подключением одного телевизора.
В настройках звука Windows выбрать нужный телевизор или отдельные колонки устройством вывода и проверить
звук после переподключения HDMI: система может изменить устройство по умолчанию.

## 2. Что положить в комплект

Подготовка требует интернета на отдельной машине; на выставке используются уже скачанные файлы.

| Состав | Что именно переносится |
|---|---|
| Приложение | Установщик Windows x64, собранный из нужной версии проекта; Node, редактор, сервисы и данные ядра уже внутри |
| WebView2 | Автономный установщик включён в сборку Tauri через `offlineInstaller`; его загрузка происходит при сборке |
| Python | Установщик Python 3.12 x64; окружение `.venv` создаётся на Windows, не копируется с Mac |
| Голосовые пакеты | Папка wheels, подготовленная `services/voice/setup.ps1`, вместе с её `manifest.json` |
| Голосовые модели | Папка, подготовленная `prepare_models.py`: Qwen3 ru-stress-cf BF16, речевой токенизатор, Smart Turn v3.0 ONNX, GigaAM и токенизатор, контрольные суммы |
| Звук | FFmpeg для Windows, включая `ffmpeg.exe` в `PATH`; образцы голосов и все клипы предзаписи |
| NVIDIA | Подходящий установленный драйвер; работоспособность CUDA проверяется на целевой машине |
| Языковая модель | Windows-версия LM Studio либо уже используемого совместимого сервера, его локальная среда выполнения и заранее скачанные совместимые веса |
| Карты | `cartography.json` и вся папка `tiles`; для переноса через интерфейс можно использовать пакеты локальных карт |
| Данные стенда | `expo/voice/manifest.json`, `expo/voice/clips`, `voice/voices`, нужные `voice/roles.json` и `voice/tts.json` |

В языковой модели сохраняется выбранная для стенда модель; переход на другую здесь не предусмотрен.
Mac-веса в формате MLX не становятся совместимыми с Windows от простого копирования. Для LM Studio необходимо
заранее установить подходящую Windows-среду и вариант весов поддерживаемого формата.
Локальный сервер LM Studio может работать без сети после подготовки, но скачивание моделей и сред выполнения
требует интернета: [документация LM Studio](https://lmstudio.ai/docs/app/offline).

`scripts/offline-bundle.sh` собирает Docker-серверы. Он не заменяет этот комплект: в нём нет настольного ядра,
языковой модели, TTS-весов, образцов и предзаписи стенда.

## 3. Сборка приложения

Если готового установщика нет, собрать его **на Windows x64** из согласованной версии исходников:

```powershell
npm ci
npm run desktop:build
```

Машине сборки нужны Node, Rust и инструменты сборки Tauri для Windows — MSVC/Windows SDK.
Node и нативные зависимости картографии в установщике берутся с этой машины; сборка на Mac не даёт готового
Windows-комплекта. На выставочном ПК компиляторы не нужны, если туда переносится готовый установщик.
Результат находится в каталоге `target/release/bundle` рабочего пространства Cargo.
Настройка `offlineInstaller` увеличивает установщик, зато установка WebView2 на стойке не требует скачивания:
[документация Tauri](https://v2.tauri.app/distribute/windows-installer/).

Исходники голосовой службы входят в ресурсы приложения. При первом запуске они копируются в
`%APPDATA%\ru.defops.desktop\voice-service`. Окружение `.venv` и веса устанавливаются отдельно.
После копирования исходников приложение можно закрыть и продолжить подготовку окружения.

## 4. Подготовка Python-зависимостей на Windows с интернетом

Установить Python 3.12 x64. Команды ниже выполняются из папки `services\voice` исходников.
В установленной программе вместо неё можно использовать `%APPDATA%\ru.defops.desktop\voice-service`.
Путь комплекта приведён как пример; можно выбрать другой диск с достаточным свободным местом.

```powershell
$Kit = "D:\DefOpsKit"
.\setup.ps1 -PrepareWheelhouse "$Kit\voice-wheels"
.\setup.ps1 -Wheelhouse "$Kit\voice-wheels"
```

Первая команда собирает пакет wheels и манифест контрольных сумм. Вторая устанавливает его без обращения
к индексам пакетов. Это отдельные операции: `-PrepareWheelhouse` не устанавливает подготовленные пакеты в окружение.
Если PowerShell блокирует запуск скрипта, для одного вызова можно использовать
`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -Wheelhouse "D:\DefOpsKit\voice-wheels"`.

Закреплены Python-пакеты из `requirements-win.txt`: Torch/torchaudio 2.7.1 с CUDA 12.8, qwen-tts 0.1.1,
transformers 4.57.3 и остальные прямые зависимости. GigaAM собирается из закреплённого commit.
Точные собранные wheels фиксируются контрольными суммами. FlashAttention устанавливать не требуется;
Qwen использует SDPA. Совместимость всех wheels и драйвера нужно подтвердить установкой на Windows.

## 5. Подготовка и проверка весов голоса

На машине с интернетом, после установки пакетов:

```powershell
.\.venv\Scripts\python.exe prepare_models.py --models-dir "$Kit\models\voice"
.\.venv\Scripts\python.exe prepare_models.py --check --models-dir "$Kit\models\voice"
```

Первая команда скачивает закреплённые версии и записывает манифест. Вторая только читает файлы и проверяет SHA256;
она не обращается к сети и не загружает модели в память.

Структура папки:

```text
models/voice/
  manifest.json
  qwen3-ru-stress/       # исходный checkpoint и speech_tokenizer/
  smart-turn/smart-turn-v3.0.onnx
  gigaam/v3_e2e_rnnt.ckpt
  gigaam/v3_e2e_rnnt_tokenizer.model
```

Используется [исходное дообучение ru-stress-cf](https://huggingface.co/siriusfreak/qwen3-tts-12hz-1.7b-ru-stress-cf),
которое поддерживает знак ударения U+0301 и клонирование по образцу с расшифровкой.
Это тот же fine-tune, для которого на Mac используется MLX-квантизация. Формат BF16 отличается,
поэтому тембр и следование ударениям следует прослушать на Windows. Smart Turn берётся из
[официального ONNX-комплекта Pipecat](https://huggingface.co/pipecat-ai/smart-turn-v3/tree/main).

## 6. Установка на выставочный компьютер без интернета

1. Установить Windows-приложение, Python 3.12 x64, NVIDIA-драйвер и FFmpeg. Проверить, что команда `ffmpeg -version`
   работает в новой консоли PowerShell.
2. Запустить и закрыть приложение, чтобы появилась папка `voice-service`. Установить голосовые зависимости:

   ```powershell
   $Data = Join-Path $env:APPDATA "ru.defops.desktop"
   Set-Location (Join-Path $Data "voice-service")
   .\setup.ps1 -Wheelhouse "D:\DefOpsKit\voice-wheels"
   ```

3. Перенести подготовленную папку `models\voice` в `$Data\models\voice`. Перенести предзапись в
   `$Data\expo\voice`, образцы с расшифровками — в `$Data\voice\voices`, настройки ролей — в `$Data\voice\roles.json`.
   В папке каждого образца должны лежать `ref.wav` и `ref.json` с текстом.
   Обязательные образцы стенда: `chief-10s`, `zhukov-14s`, `konev-12s`.
4. Если переносится `voice\tts.json`, в нём должен быть выбран `qwen3-ru-stress`.
   Пустой Windows-профиль выбирает его сам. Сохранённый другой движок даёт ошибку, без молчаливой замены.
5. Перенести `cartography.json` и всю папку `tiles` в `$Data` либо импортировать пакеты локальных карт.
   На новом профиле окна открыть полный режим, выбрать локальную подложку и включить «Офлайн».
   Выбор подложки хранится в профиле WebView; одной копии файлов для выбора карты недостаточно.
6. Установить и запустить подготовленный Windows-сервер языковой модели. Загрузить нужную модель и включить
   локальный API на `127.0.0.1:1234` или `127.0.0.1:1235`. Наличие файла весов ещё не означает, что модель загружена.
   В полном режиме приложения проверить выбор основной модели: стенд использует именно её. Отдельный выбор
   модели для голоса относится к полной версии и не подменяет основную модель стенда. Эти настройки хранятся в профиле WebView и не переносятся вместе
   с `cartography.json` или папкой TTS. Проверить реальный ответ в автономном сеансе.
7. Запустить приложение. Оно поднимает службу голоса автоматически; на Windows включён автономный режим.
   Синтез идёт на CUDA, распознавание и определение конца фразы — на CPU.

Для ручного запуска службы с явными путями:

```powershell
$Data = Join-Path $env:APPDATA "ru.defops.desktop"
$env:DEFOPS_VOICE_BACKEND = "torch"
$env:DEFOPS_VOICE_OFFLINE = "1"
$env:DEFOPS_VOICE_MODELS = Join-Path $Data "models\voice"
Set-Location (Join-Path $Data "voice-service")
.\.venv\Scripts\python.exe server.py --data (Join-Path $Data "voice")
```

Сначала убедиться, что служба на порту 47645 ещё не запущена: не создавать второй экземпляр на той же видеокарте.
Приложение подключается к уже работающей службе. В `/health` должны быть `state: ready`, `backend: torch`,
`engine: qwen3-ru-stress`, `offline: true`. Отсутствующие CUDA или веса вызывают ошибку с причиной.
Переменные окружения текущей консоли не сохраняются для запуска ярлыком, поэтому постоянные нестандартные пути
нужно задать в окружении Windows либо в подготовленном скрипте запуска.

## 7. Проверка перед показом

Из исходников, без запуска или сброса игры:

```powershell
npm run expo:preflight -- --data "$env:APPDATA\ru.defops.desktop" --out "D:\DefOpsKit\preflight.json"
```

В установленном приложении тот же скрипт входит в `server\dist\expo-preflight.mjs`; его можно запустить
встроенным `node.exe`, указав полный путь к скрипту и те же параметры. `--assets-only` пропускает проверки
работающих голосовой и языковой служб, но не подтверждает готовность живой генерации.

Проверка читает данные и локальные службы: предзапись, три образца, каталог и файлы каждой локальной карты,
Python/FFmpeg, NVIDIA, независимые дисплеи, SHA256 моделей, состояние голоса и API языковых моделей.
Она не генерирует текст или звук, не скачивает веса и не сбрасывает текущую игру.
Отчёт также содержит объём RAM. Для локальной карты проверяется настоящий XYZ-тайл либо `ohm.mbtiles`,
но это не доказывает полноту покрытия. Ответ API языковой модели не подтверждает, что веса загружены
и генерация работает; это проверяется отдельно во время автономного прогона.

После устранения ошибок полностью отключить интернет, перезагрузить компьютер и пройти приёмку:

- открыть стенд и проверить все 12 сцен интро, назначение трёх экранов и звук;
- пройти оба фронта через три решения до окончания разбора;
- убедиться, что карта двигается плавно, генерация итога начинается на плашке «Готовим итог», речь доигрывает;
- прослушать новые комментарии и топонимы, сравнить голоса Жукова и Конева с подготовленными образцами;
- во время LLM/TTS наблюдать расход GPU-памяти и RAM, проверить отсутствие нехватки памяти;
- отключить и вернуть телевизор, проверить роли, полный экран, масштаб и доступ к меню оператора;
- закрыть и снова открыть приложение, убедиться, что выбранные карты и экранные настройки сохранились.

Успешный preflight не заменяет этот прогон. При нехватке 16 ГБ видеопамяти сначала измеряется потребление
конкретной языковой модели и TTS; другая модель или квантование не подставляются автоматически.

### Работа LLM и Qwen TTS в 16 ГБ

Для первого прогона Bonsai вместе с Qwen TTS BF16 выставить в настройках загрузки Bonsai:
Context Length — 4096, Max Concurrent Predictions — 1, Evaluation Batch Size — 512,
Flash Attention — включён. Это стартовая конфигурация проверки на стенде, а не гарантия расхода памяти.
Лимит выходных токенов комментария не уменьшает контекст, заданный при загрузке модели.

Сохранить параметры через My Models → шестерёнка модели как её настройки по умолчанию,
затем один раз перезагрузить Bonsai. Без управляемого профиля LLM и TTS остаются загруженными
между решениями. В управляемом профиле Windows приложение переключает их по этапам, как описано ниже.
Смена образца командующего сама по себе не перезагружает уже загруженные веса Qwen. При перезапуске
Python-службы Qwen загружается заново. [Настройки загрузки модели](https://lmstudio.ai/docs/app/advanced/per-model),
[параллельные запросы](https://lmstudio.ai/docs/app/advanced/parallel-requests).

Проверять `/health` голосовой службы и `nvidia-smi` именно во время задержки. `synthesis.stage: generating`
означает, что вызов синтеза уже начат; `elapsed_s` показывает его длительность. Почти заполненная VRAM
требует проверки расхода LLM, TTS и окон карты. В Windows драйвер может использовать системную память
при нехватке видеопамяти, снижая скорость; один снимок общей загрузки не доказывает, что это произошло.
[Описание NVIDIA](https://nvidia.custhelp.com/app/answers/detail/a_id/5490).

Для запросов к LM Studio использовать фактический порт из Developer: `1234` и `1235` не взаимозаменяемы.

### Управляемый профиль NF4 и Flash Attention

Профиль `%APPDATA%\ru.defops.desktop\voice\torch-profile.json` содержит три поля:

```json
{"managed":true,"quantization":"nf4","attention":"flash_attention_2"}
```

Допустимые значения квантования: `nf4`, `int8`, `bf16`; внимания: `flash_attention_2`, `sdpa`.
Без файла сохраняется прежний BF16/SDPA с постоянной загрузкой TTS. На Mac этот Windows-профиль не применяется.
NF4 использует bitsandbytes и BF16-вычисления; слои звукового кодека и вспомогательных декодеров не квантуются.
Исходные веса ru-stress и словарь сохраняются. Меньший объём весов сам по себе не гарантирует ускорения.

В управляемом режиме выбранная LLM загружается во время выбора решения. Анимация карты заканчивается
до генерации комментария. После ответа LLM приложение выгружает именно использованный экземпляр,
загружает и прогревает TTS и воспроизводит комментарий целиком. После комментариев 1/2 возвращается LLM;
после комментария 3 TTS остаётся для всей подготовки итога. Готовый PCM переживает выгрузку весов,
а CPU-служба, распознавание и словарь продолжают работать. В плашке итога отображается только
«Готовим итог — N%»: процент считается по уже подготовленным фразам. Во время загрузки модели
он остаётся нулевым, после каждого готового пакета увеличивается.

Применение обновления — через `release/defops-gpu-handoff/UPDATE.cmd` после закрытия приложения.
Тот же патч добавляет в меню оператора, вкладку «Сеанс», переключатели «Комментарии после решений»
и «Итоговый разбор». Они независимы от общего режима ИИ и сохраняются в настройках стенда.
Выключенный этап не запускает автоматическую генерацию и синтез. Без разбора итог сразу показывает
полные показатели и конечную карту операции. Изменение относится к следующим этапам; начатая
подготовка завершается. Пересборка EXE для этих настроек не требуется.
Установщик использует только вложенные wheels, проверяет SHA256, не обновляет Torch/Transformers и
не меняет выбранную LLM в LM Studio. Дополнения размещаются в `portable/runtime/addons/voice-gpu`.
До активации запускается нативная проверка CUDA, NF4, голосового образца, освобождения памяти и WAV.
Для Flash Attention проверяется настоящее вычисление ядра, а не только импорт или флаг конфигурации.
Если проверка Flash не проходит, отчёт явно указывает SDPA; неудача самого NF4-синтеза не активирует профиль.
В журнале отдельно видны загрузка, прогрев, синтез, длительность звука и расход памяти.

Для возврата прежних файлов и профиля используйте команду отката из обновления; словарь, база знаний,
предзаписи и назначения голосов при обновлении не перезаписываются. Совместимость нативного FA2 wheel
с Torch 2.7.1+cu128 подтверждается только на Windows: сборка кандидата выполнена под Torch 2.7.0.

Если CUDA-проверка уже завершилась успешно, применение файлов можно продолжить через
`release/defops-gpu-apply/APPLY.cmd`. Этот запускатель использует встроенный Python и сохранённые
результаты из `D:\k\gpu-checks`, проверяет SHA256 исходного пакета и RECORD установленных дополнений.
Node, pip, загрузка моделей и повторный синтез не используются. Исходную распакованную папку
обновления и каталог проверки нужно сохранить. Если предыдущая транзакция была прервана после
изменения файлов, сначала восстанавливается её резервная копия, затем применяется обновление.
Журнал — `D:\k\gpu-checks\apply-*.log`, UTF-8 с BOM; каждый этап виден в окне и сразу записывается
на диск. Для отката применяется `APPLY.cmd rollback "путь резервной копии"`.

### Температура и пакетная озвучка итогов

Для уже установленного управляемого GPU-профиля доступно обновление
`release/defops-tts-batch.zip`. Распаковать его на локальный диск, закрыть DefOps и запустить
`UPDATE.cmd`. Перед проверкой выгрузить Bonsai в LM Studio, чтобы TTS получила свободную
видеопамять; сервер LM Studio можно оставить включённым. По умолчанию комплект находится в `D:\k`; другой путь можно передать третьим
аргументом PowerShell-запускателя `UPDATE.ps1` через параметр `-Kit`.

В меню оператора → «Сеанс» → «Генерация и озвучка» появились «Температура голоса» (0–1,
по умолчанию 0,2) и «Размер пакета» (1, 2 или 4, по умолчанию 4). Нулевая температура
включает жадный выбор в обоих декодерах. Параметры относятся к следующему этапу; уже
подготовленная речь проигрывается с исходными настройками без повторного синтеза.
«Потоки CPU для TTS» — 1, 2, 4 или 8, по умолчанию 2. Это внутренняя CPU-параллельность
PyTorch (`torch.set_num_threads`), отдельная от размера GPU-пакета и числа моделей. Inter-op-пул
не меняется. CPU-значение фиксируется на этап и применяется перед синтезом; уже готовый PCM
повторно не рассчитывается. Переключатель действует на Windows/PyTorch. Более высокое число
потоков не означает гарантированно более быстрый синтез.
[API PyTorch](https://docs.pytorch.org/docs/stable/generated/torch.set_num_threads.html).

«Озвучивать комментарии» оставляет 3,5 секунды на чтение готового текста, если голос выключен.
«Догенерировать озвучку итога» разрешает синтез только фраз, которых нет в готовой предзаписи.
Если переключатель выключен, итог открывается сразу. Типовые и общие фразы звучат из готовых клипов,
остальные показаны текстом. Если синтез завершился ошибкой, доступные записи и весь текст остаются.

Готовые реплики итогов поставляются вместе с редактором в `expo-debrief/`. Команда
`npx tsx scripts/expo-debrief-voice.ts` подготавливает и проверяет записи на машине сборки.
В Windows обновление `defops-expo-hybrid` для установленного r2 заменяет редактор с выбранными дублями
и шлюз со словарём ударений. После закрытия DefOps достаточно запустить `UPDATE.cmd`.
Установщик сохраняет резервную копию редактора, шлюза и манифеста. Пользовательские ударения из профиля
имеют приоритет над словарём сборки. Профиль NF4, настройки и библиотека сохраняются.
Новые файлы готовятся рядом с файлами приложения, чтобы в Windows унаследовать разрешения их каталога.
Окно установки показывает проверку файлов, ход копирования и момент замены редактора.

Комментарий готовится после карты отдельно. Недостающие фразы итога готовятся одним запросом с
последовательными пакетами. На Mac голосовой движок готовит фразы внутри пакета последовательно.

Установщик не скачивает модели или зависимости и не пересобирает EXE. Он сохраняет текущие
NF4/int8/BF16 и FlashAttention/SDPA, проверяет SHA256 файлов, затем сравнивает синтез одной
короткой фразы с настоящим пакетом из четырёх на комплектном Python/CUDA. Проверяются четыре
непустых WAV, один пакетный вызов модели, температура, действительное переключение CPU-потоков 1/2/4/8 и освобождение видеопамяти. Только после
успеха создаётся резервная копия и обновляются интерфейс и голосовой сервис. При ошибке
применения восстанавливаются прежние файлы. Словарь, образцы, роли, предзаписи, выбранная LLM
и база знаний не заменяются.

Журнал `D:\k\gpu-checks\tts-batch-update-*.log` показывает этапы; каталог
`tts-batch-*` содержит четыре WAV и `batch-result.json` со временем и расходом памяти.
Замер коротких фраз не предсказывает длительность всего разбора. CUDA-ускорение подтверждается
только запуском на целевой Windows-машине. Команда отката выводится после успешного обновления:
`UPDATE.cmd rollback "путь резервной копии"`.

При успешном синтезе и последующей ошибке «Состав файлов не совпадает с манифестом:
payload/voice-source/» применяется `release/defops-tts-batch-resume/RESUME.cmd`.
Он использует прежнюю папку `D:\k\defops-tts-batch` и готовый результат из `gpu-checks`:
заново загружать модель, прогревать её и синтезировать звук не нужно. Источник результата
сверяется с текущим payload, профилем и сборкой; дополнения проверяются по RECORD.
Установщик удаляет только Python-байткод известных модулей, созданный прежней проверкой;
неизвестные дополнительные файлы остаются ошибкой целостности. В новых запусках байткод
запрещён флагом `-B`: переменная `PYTHONDONTWRITEBYTECODE` сама по себе не работает при `-I`.
В полном исправленном пакете продолжение запускается через его `RESUME.cmd`.

Чтобы определить, какая часть TTS занимает время, перенести на локальный диск папку
`release/defops-tts-profile`, закрыть DefOps, временно выгрузить Bonsai в LM Studio и запустить
`MEASURE.cmd`. Установка обновлений перед замером не требуется. Запускатель использует сборку
из `D:\k\LAST-BUILD.txt`; при другом корне комплекта — `MEASURE.cmd -Kit "путь"`.
Он не устанавливает зависимости и не меняет приложение, настройки, словарь или веса.
Оставшийся после закрытия приложения собственный голосовой процесс останавливается;
чужой процесс на том же порту вызывает отказ. После замера приложение запускается обычным способом.

Один запуск загружает и прогревает Qwen, затем измеряет одну фразу и пакет из одинаковых
фраз с текущими температурой и числом CPU-потоков. Размер пакета берётся из настроек оператора;
при значении 1 дополнительный пакет не запускается. Отчёт разделяет обработку образца,
генерацию аудиокодов, кодек и прочие расходы, показывает RTF, точность компонентов и память GPU.
Кодек обрабатывает также аудиокоды образца голоса; длительность итогового WAV указана после
его вырезания. Синхронизация CUDA выполняется на границах этапов, без вмешательства в цикл
каждого токена. Это полное время вызовов с CPU и ожиданием GPU, а не отдельное время CUDA-ядер.

Результаты: `D:\k\gpu-checks\tts-phase-*\report.txt`, `report.json`, `measure.log` и WAV.
Для разбора нужны оба отчёта. Исходники набора проверяются по SHA256 до загрузки среды;
при отличии установленного сервиса отчёт прямо указывает, что измерена версия из набора.
Замер на одной машине не подтверждает скорость на другом GPU и не сравнивает качество разных квантований.

### Постоянные образцы трёх голосов

Патч `release/defops-voice-cache` устраняет повторное кодирование голосовых образцов после
unload/load TTS и перезапуска службы. Перенести папку на локальный диск Windows, закрыть DefOps,
временно выгрузить Bonsai в LM Studio и запустить `UPDATE.cmd`. Нужен уже установленный пакетный
патч, в том числе применённый через `defops-tts-batch-resume`. Новых зависимостей, сети или сборки EXE нет.

Один запуск подготавливает начальника штаба и образцы `zhukov-14s`, `konev-12s`, выгружает
GPU-модель и проверяет, что новый экземпляр службы читает все три записи с диска без повторного
кодирования. До успеха этой проверки исходники приложения не заменяются. При повторном запуске
уже сохранённые записи используются заново. Прогресс выводится каждые 15 с; результаты —
`D:\k\gpu-checks\voice-cache-*\cache-result.json`, общий журнал — `voice-cache-update-*.log`.

Кэш — CPU-тензоры и `ref.wav.qwen-prompt.safetensors` рядом с каждым образцом. Формат содержит
данные без исполняемых объектов и сохраняет исходную точность. Изменение WAV по содержимому,
расшифровки, профиля, локальных весов или библиотек требует пересчёта. Повреждённый файл также
пересчитывается. При отсутствии прав записи обычный сервис продолжает с CPU-кэшем до перезапуска,
а установочная проверка требует сохранения всех трёх образцов. Дополнительные голоса создаются
при первом использовании; другие голоса не вытесняются при выборе нового. Удаление/отмена образца
чистит и его кэш. GPU-память после unload освобождается; загрузка весов и короткий прогрев остаются.

Заменяются только `models_torch.py`, новый `prompt_cache.py` и их контрольные суммы в приложении.
Словарь, предзаписи, образцы, роли и настройки не заменяются. Предусмотрены резервная копия,
автоматический откат при ошибке и восстановление прерванного обновления. Команда ручного отката
выводится после применения: `UPDATE.cmd rollback "путь резервной копии"`.

### Постоянно прогретая NF4 TTS рядом с Bonsai

Перенести `release/defops-tts-resident` на локальный диск Windows. Закрыть DefOps, оставить сервер
LM Studio включённым и **оставить Bonsai загруженной**; в разделе «ИИ» должен быть выбран этот экземпляр.
Запустить `UPDATE.cmd`. Сборка определяется по `D:\k\LAST-BUILD.txt`; нужны рабочий комплект CUDA
с bitsandbytes и локальные веса. Модели и зависимости не скачиваются, EXE не пересобирается.

Короткая проверка запрашивает ответ Bonsai до загрузки TTS. После прогрева она подтверждает
сохранение одной NF4 TTS и того же экземпляра Bonsai двумя генерациями текста, отдельной репликой
TTS и коротким пакетом. Минимум перед загрузкой TTS — 6 ГиБ
свободной памяти, минимальный наблюдавшийся запас во время проверки — 1,5 ГиБ. Это бюджет для
проверки, а не имитация трёх телевизоров. При недостатке памяти профиль не применяется; уменьшить
занимаемую Bonsai видеопамять можно настройкой GPU offload в LM Studio. После изменения модели или
параметров загрузки совместную работу нужно проверить снова. Проверка использует нативный API
LM Studio и подтверждает, что оба запроса выполнил один уже загруженный экземпляр Bonsai.

Патч синхронизирует постоянный профиль (`managed: false`, NF4) в приложении и переносимой библиотеке,
оставляет текущий backend внимания и размер пакета (1, 2 или 4), устанавливает два CPU-потока TTS.
Кэш голосов готовится на копиях образцов и переносится после активации; редактор ждёт фактического окончания карты и комментария и продолжает без
дополнительной паузы. TTS загружается и прогревается до готовности голосовой службы; веса остаются
в GPU между решениями и итогом. LM Studio не получает команды выгрузки от стенда в этом режиме.
При замене сохраняется резервная копия; команда ручного отката выводится после успешной установки.

Результаты — `D:\k\gpu-checks\tts-resident-*\report.txt` и `resident-result.json`: времена, TTS-память,
запас GPU и общий расход до загрузки TTS (Bonsai, Windows и другие процессы). Короткий тест не
подтверждает целевое время полного разбора. Для отдельного замера после установки закрыть DefOps,
оставить Bonsai загруженной и запустить `MEASURE.cmd` из этой же папки. Он синтезирует восемь полных
реплик алгоритмического итога без обрыва по времени и сообщает, уложился ли синтез в 30 секунд.

В пакетном обновлении `defops-tts-batch` фотографии в заставке, обстановке и справке показываются целиком,
а полная подпись получает отдельное место и не вытесняет изображение за границы экрана.

Клонирование в Qwen Torch использует полную фразу в начальном контексте (`non_streaming_mode=True`)
и `repetition_penalty=1.5`, как рабочий ICL-путь предзаписи на Mac. Температура talker и code predictor —
`0.2`; голос берётся из назначенного образца. Дефолты библиотеки Torch для подачи текста и защиты
от повторов отличаются от MLX, поэтому задаются явно. Это не ограничение длины или времени:
результат ожидается целиком до завершения генерации. Качество и завершение фразы проверяют на целевой
Windows-машине; тест вызова API без GPU подтверждает только передачу этих параметров.

Если после освобождения видеопамяти синтез остаётся долгим, собрать снимки `/health`, `nvidia-smi`,
частот GPU, PID и времени запуска Python, его стека и последних строк `startup.log` прямо во время задержки.
Диагностический сборщик не запускает новые запросы синтеза и не меняет модели. Для чтения стека отдельного
процесса Windows может потребовать запуск сборщика от имени администратора. Поле `chars` в состоянии
синтеза — длина входного текста; это не счётчик сгенерированных символов и не процент готовности.
Если стек показывает расчёт Qwen, но причина задержки ещё неясна, дополнительная проверка
`COUNT.cmd` снимает три значения `cur_len` из циклов генерации и действующие числовые параметры.
В Qwen есть внешний цикл аудиокадров и внутренний цикл кодов одного кадра: их счётчики рассматривают
раздельно. По изменению внешнего счётчика можно отличить медленный расчёт от генерации лишнего аудио.
В журнал сохраняются только разрешённые числовые значения и флаги, без текстов и тензоров.
Проверка не запускает синтез, не задаёт новые ограничения и не перезапускает модели.
