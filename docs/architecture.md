# Архитектура платформы

## Принципы

1. **Ядро без окружения.** Вся предметная логика — модель документа, слои,
   геопривязка, рендер знаков, GeoJSON — в `@def-ops/core`. Ядро не знает ни
   о браузере, ни о сервере, ни о конкретной карте. Один и тот же код рисует
   знаки в редакторе, на сервере (сервис рендера) и в любом другом модуле.
2. **Сервисы по ответственности.** Каждый сервис владеет своей задачей и
   данными, общается только по HTTP/JSON, не имеет состояния в памяти,
   которое нельзя потерять (кроме шины событий — см. ниже).
3. **Единая точка входа.** Снаружи доступен только шлюз: аутентификация,
   организация (tenant), маршрутизация. Внутренние сервисы закрыты сетью.
4. **Открытые форматы обмена.** Документ — JSON (OpenAPI-схема в
   `docs/openapi.yaml`), для внешних систем — GeoJSON (RFC 7946),
   для полиграфии — SVG со слоями.
5. **Заменяемые части за интерфейсами:** хранилище (`DocumentStore`),
   картографический движок (`MapEngine`), подложки (`BasemapSpec`),
   шина событий (`EventBus`).

## Данные и время

Каждый сервис владеет своей схемой в общей базе PostgreSQL + PostGIS и сам
накатывает миграции при старте (`@def-ops/db`); в чужие схемы не ходит.
Документ карты хранится целиком (jsonb) с ревизиями; реестр — таблицами
объектов и фактов с периодами действия (`tstzrange`) и геометрией. Время
знаков на карте (период присутствия, положение по датам) хранится в самом
документе, характеристики объектов во времени — в реестре. Подробно —
[data-model.md](data-model.md).

## Слои

Документ содержит упорядоченный список слоёв (`layers`, снизу вверх); каждый
объект ссылается на слой (`layerId`). У слоя: имя, назначение (`role`:
основа, фронт, свои, противник, подписи, прочее), видимость, блокировка,
прозрачность, источник (`source` — внешняя система, `readOnly`) и
произвольные атрибуты `meta` для интеграций (гриф, владелец, классификация).

- Порядок отрисовки задаётся слоями; внутри слоя — порядком объектов.
- Скрытый слой не рисуется, но его линии продолжают служить опорой для
  привязанных хвостов стрелок (геометрия стрелок не «ломается»).
- Заблокированный слой и слой внешней системы с `readOnly` не правятся в редакторе.
- Новые объекты ложатся в активный слой; в режиме «авто» — по смыслу знака
  (`roleForPreset`): реки и дороги — в основу, рубежи и контрудары — к противнику,
  линии фронта — во фронт, подписи и населённые пункты — наверх.
- В SVG каждый слой — группа `inkscape:groupmode="layer"`: файл открывается
  в Inkscape/Illustrator со слоями.
- Внешняя система может создать свой слой и полностью заменять его
  содержимое (`PUT /documents/{id}/layers/{layerId}/features` с GeoJSON) —
  остальная карта не затрагивается; открытые редакторы получают событие и
  обновляются.

## Организации (multi-tenancy)

Шлюз сопоставляет API-ключ с организацией (`API_KEYS="ключ:орг,…"`,
`AUTH=keys`) и выставляет `X-Tenant-Id` сам — заголовок от клиента не
принимается. Сервис документов хранит данные каждой организации отдельно
(`<DATA_DIR>/<организация>/…`); чужие документы недоступны (404).
В режиме разработки (`AUTH=open`) ключ не обязателен.

## Совместная работа

Каждое сохранение увеличивает `revision` (ETag). Клиент передаёт
`If-Match: "<ревизия>"`; если документ успели изменить — 409, редактор
предлагает перезаписать или загрузить свежую версию. Хранится до 50 последних
ревизий (`GET /documents/{id}/revisions`). События изменений идут потоком
SSE (`/api/events`); если у пользователя нет несохранённых правок, редактор
подгружает новую ревизию автоматически.

## Подключение других карт

- **Подложки без кода:** любой XYZ/WMS-сервис добавляется в редакторе
  («Подложка → своя»), включая ведомственные тайловые серверы.
- **Другой картографический движок:** реализовать интерфейс `MapEngine`
  (`apps/editor/src/engine/types.ts`: перевод координат, вид, события,
  подложка, наложения) и зарегистрировать в `engine/registry.ts`.
  Знаки рисуются движком платформы поверх любой карты.
- **Другие системы:** REST API (`docs/openapi.yaml`), GeoJSON в обе стороны,
  поток событий, клиент `@def-ops/api-client`.

## Что заменить при промышленной эксплуатации

| Сейчас | Затем | Где менять |
|---|---|---|
| растры подложек в документе | объектное хранилище (S3) | `ImageOverlay.url` |
| шина событий в памяти | NATS / Kafka / Redis Streams (или LISTEN/NOTIFY PostgreSQL) | `services/*/src/events.ts` |
| API-ключи из переменной | OIDC/Keycloak, роли и права на слои | `services/gateway` |
| tsx в контейнере | сборка сервисов в JS (esbuild) | `deploy/Dockerfile` |
