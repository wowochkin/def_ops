# База знаний ↔ моделирование, часть 3: правила модели из базы — нормативы, происхождение, калибровка в коридорах

## Цель

Нормативы (`packages/sim/data/rules/norms.json`) живут отдельно от базы знаний, калибровка подбирает множители в
границах, зашитых в код (`CALIB_SPACE`), а у чисел правил нет происхождения. Часть 3:

1. **В** — нормативы становятся фактами базы двух новых видов (значение правила и итог прогона), с извлечением из
   документов, ручной правкой и проверками части 2;
2. **Б** — у каждого входа правил и профилей видно происхождение: норматив базы или допущение («Основа правил»);
3. **А** — калибровка подбирает внутри коридоров, заданных нормативами, и учитывает нормативы-итоги в мериле.

Это часть 3 из 4; часть 4 — советник, посредник и штаб противника на той же базе.

## Решения, принятые с заказчиком

| Вопрос | Решение |
|---|---|
| Что главное | Всё, в порядке В → Б → А |
| Источник против калибровки | Источник задаёт коридор, калибровка подбирает внутри |
| Ширина коридора | Значение или диапазон источника с допуском по надёжности: A ±10 %, B ±20 %, C ±35 % |
| Нормативы-итоги | В мериле калибровки с малым весом (1/8, если итогов у операции не меньше 3), иначе — только проверка |
| Что получает происхождение | Все числа правил и профилей (~50 входов), таблицы — целиком |
| Подход | Нормативы — факты базы, сборщик «база → правила»; наборы правил остаются файлами |

## 1. Нормативы в базе

Новые виды формальной части (`packages/knowledge/src/schema.ts`, `Claim`):

```ts
| { kind: 'param'; param: string; value?: number; range?: [number, number]; unit?: string; side?: 'su' | 'de'; why?: string }
| { kind: 'outcome'; measure: 'pace' | 'loss' | 'frontage' | string; scenario: string; subject?: string; from: string; to: string; range: [number, number]; unit: string }
```

- `param` — путь параметра правил или профиля (как `rules`/`measure.expr` в `norms.json`: `defense.terrain.forest`,
  `advanceMax`, `pocket.capitulateHours`, `profiles.de.quality`); `side` — норматив одной стороны.
- `outcome` — то, что сейчас `measure` нормативов-итогов (`pace`, `loss`, `frontage`, …), с операцией, соединением,
  периодом, диапазоном.
- Допущение — `param` без источника и надёжности, `why` — почему допущение и чего не хватает.
- Сид: `npm run kb:seed` превращает строки `norms.json` в факты записей, на которые они ссылаются (`kb`), иначе — в
  запись «Нормативы модели» по разделу. `norms.json` — исходник встроенных нормативов; главная — база.
- Документы и ручная правка (часть 2): извлечение получает виды `param`/`outcome`; форма факта — поля этих видов,
  параметр выбирается из перечня входов; проверки: число в цитате, параметр известен (иначе сомнение «неизвестный
  параметр»), диапазон упорядочен, у `outcome` — соединение и даты.

## 2. Сборщик «база → правила»

**Перечень входов** (`packages/sim/src/rule-inputs.ts`): ~50 входов правил и профилей — путь, название, единица, как
прочесть значение из набора правил или профиля, группа (бой, оборона и местность, движение, подвоз, усталость,
окружение, профили); таблицы `advance`, `attackerLoss`, `defenderLoss` — по входу на таблицу. Для подбираемых —
ключ множителя (`CalibKey`) и пересчёт коридора норматива в коридор множителя:

- прямые: `prepared`, `fortPerLevel`, `urbanAdvance` (`advanceTerrain.urban`), `terrFoot`, `terrMobile`;
- через таблицу: `advance` ← `advanceMax` (коридор / наибольший темп исходной таблицы); `attackerLoss`,
  `defenderLoss` ← нормативы суточных потерь при соотношении (коридор / значение таблицы);
- `terrainExp` ← поправки местности: `ln(коридор) / ln(исходная поправка)`, пересечение по видам местности;
- `fortAdvance` ← `fortAdvanceKm`; `movement` ← темпы марша профилей.

**`compileRules(entries, rules, profiles, pins) → { corridors, provenance, outcomes, conflicts }`**
(`packages/knowledge/src/compile-rules.ts`):

- выбор норматива — `resolve` части 1 (закрепление → надёжность → свежесть); коридор — значение `v` → `[v(1−t), v(1+t)]`,
  диапазон `[a, b]` → `[a(1−t), b(1+t)]`, `t` = 0,10 / 0,20 / 0,35 для A / B / C; без норматива или допущение —
  `CALIB_SPACE`; коридор источника шире `CALIB_SPACE` — берётся коридор источника с пометкой «шире прежних границ»;
- `provenance` — у каждого входа выбранный факт (запись, источник, надёжность, цитата) или «допущение»;
- `outcomes` — нормативы-итоги по операциям;
- `conflicts` — несколько нормативов на параметр с непересекающимися коридорами (закрепляются, как в части 1).

Изменение базы → пересборка; изменились коридоры или итоги — запись в журнал операций и «данные изменились» в
панели пересчёта. Наборы правил не меняются.

## 3. Калибровка, отчёт, агентная модель

- Нынешняя модель (`calibrate.ts`, стенд и `npm run sim:calibrate`): границы поиска — коридоры сборщика; мерило при
  ≥ 3 нормативах-итогах операции: `7/8 × нынешнее + 1/8 × (1 − доля итогов в допуске) × 50`; откалиброванный набор
  записывает коридоры, по которым подбирался (норматив, допуск).
- Отчёт: у множителя — коридор, источник/допущение, итог; в пределах 2 % от края — «упирается в границу — проверьте
  источник»; нормативы-итоги до и после.
- Агентная модель: параметры `agents-v0.json` с соответствующим нормативом — в перечне входов; подбор
  («Агентная модель» → «Калибровка») не пробует множители вне коридора; итоги — в оценке прогона ядра с тем же
  весом и порогом.
- `npm run sim:norms` и `docs/norms-check.md` — по собранному из базы; для встроенных нормативов результат прежний.
- Допущения (строки `norms.json`): вес итогов 1/8, порог 3 итога, допуски A/B/C, порог «упирается» 2 %.

## 4. Интерфейс

- «Моделирование» → «Модели» → набор правил → блок «Основа правил»: итог (доля входов на A/B/C и допущениях; отдельно —
  подбираемые калибровкой), входы по группам (значение, значок надёжности или «доп.», коридор; щелчок — источник,
  страницы, цитата, запись; у откалиброванных — исходное значение и множитель), расхождения с закреплением, итоги с
  результатом последней проверки.
- «Калибровка»: коридор у каждого множителя с источником; пометка «упирается в границу».
- Запись базы: формальные факты новых видов словами; форма факта — поля `param`/`outcome`.

## Проверка

Тесты: сид нормативов (каждая строка — факт, допущения без надёжности); коридоры по надёжности и диапазону; пересчёт
в множитель (прямой, через таблицу, показатель местности); шире прежних границ; выбор, расхождения, закрепления;
происхождение всех входов; мерило с итогами и без; агентная калибровка в коридоре; `sim:norms` по собранному равен
прежнему отчёту для встроенных нормативов; извлечение и проверки новых видов на записанных ответах. Прогон:
калибровка Берлинской операции в коридорах против `ww2-berlin-cal` (мерило обучения и проверки, упёршиеся
множители, итоги в допуске до/после) — сохраняется отдельным набором; цифры в описание — только из него. Описание
(часть I — «Основа правил», коридоры в калибровке; часть II — «Калибровка», «Данные»), снимки, `kb:seed`, `sim:norms`,
`model:index`, `docs:system`.
