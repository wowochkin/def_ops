# Голосовое управление: ядро, запуск и раздел «Командование»

Цель — управлять системой голосом целиком: запустил, прошёл калибровку, дальше всё голосом. Эта спецификация —
первый подпроект: голосовое ядро в приложении, запуск вместе с системой, калибровка, голоса, переходы между
разделами и полное голосовое управление разделом «Переигровка → Командование». Остальные разделы — следующими
спецификациями на том же реестре действий.

Основа — голосовой стенд `scripts/voice-bench` (talk_server.py): Silero VAD → Smart Turn → GigaAM v3 e2e →
Qwen3.6 в LM Studio → Qwen3-TTS 1.7B с клонированием. Что найдено на стенде и переносится: калибровка порогов,
пауза до ответа от 20 мс с переспросом Smart Turn, ответ крупными кусками (первая фраза сразу, короткая — вместе со
следующей), договаривание одного кадра после «конца» синтеза, затухание 10 мс, паузы между кусками по знаку,
образец голоса 10 с с естественной паузой в конце, повтор пустого ответа LM Studio.

## Кто пользуется (сквозное требование)

Пользователи — преимущественно люди старшего возраста и при этом эксперты-историки и военные. Непонятное
сразу вызывает отторжение; эксперты будут критиковать сам инструмент. Отсюда — требования ко всем ступеням:

**Понятно без обучения.**
- Панель голоса: шрифт не меньше 18 px, высокая контрастность, состояние простыми словами («Слушаю», «Скажите:
  Штаб, …», «Говорит начальник штаба»), без технических слов (VAD, порог, Smart Turn). Регуляторы
  чувствительности — в свёрнутой «Тонкой настройке»; главный путь — калибровка.
- Постоянная подсказка: «Не знаете, что сказать? Скажите: Штаб, что я могу?»
- Формулировки не заучиваются: команды понимаются в разных словах; не понял — переспрашивает своими словами и
  предлагает 2–3 варианта, а не повторяет сообщение об ошибке.
- Без спешки: синтез не ускоряется, «повтори» работает всегда, на подтверждение — 15 с.

**Честно о возможностях.**
- «А ты можешь…?» — ответ по реестру действий: есть — «Да, скажите …»; есть, но сейчас недоступно — почему и когда
  станет доступно; нет — прямо: «Этого система не предусматривает». Возможности, которых нет в реестре, не
  придумываются.
- Вопросы об устройстве («как считается бой», «откуда эти потери») — к ассистенту модели с базой знаний и описанием
  системы, со ссылкой на источник; чего нет в описании — «в описании этого нет», не догадка (ступень 2).
- Критика инструмента («это неверно», «так не было») — без споров и оправданий: на чём основано, и предложение
  записать замечание в журнал замечаний (ступень 2).

## Решения (согласованы)

| Вопрос | Решение |
|---|---|
| Первый раздел | Переигровка и командование |
| Роли голоса | **Начальник штаба** — ведёт диалог, докладывает, зачитывает советника, исполняет распоряжения. **Посредник** — докладывает итоги хода и оценку (по умолчанию образец Жукова) |
| Голос начальника штаба | Архивная запись штабиста (пришлёт пользователь); до неё — запасной образец |
| Запуск | Приложение само запускает голосовой сервис при старте; уже запущенный вручную — подхватывает |
| Когда исполняется | Слушает всегда, исполняет только обращённое к штабу; 12 с после ответа — разговор без обращения; необратимое — после «да» |
| Устройство | Голосовой сервис — только звук; разбор реплик, реестр действий, модель с инструментами — в приложении (TypeScript). Частые короткие команды — правилами, остальное — моделью |
| Голоса | Выбор образца для каждой роли; запись нового голоса с микрофона (например, гостя), проверка, назначение роли |
| Полнота | Всё, что в разделе делается мышью, делается и голосом; кнопки и голос вызывают одно действие реестра; тест полноты |
| Подсказки | «Что можно сказать» из реестра, подсказки по ходу, «Штаб, что я могу сказать?», знакомство после первой калибровки |
| Тур | Голосовой тур по разделу с подсветкой элементов интерфейса |
| Сбой LM Studio | До трёх попыток (сразу, через 1 с, через 3 с); правила работают и без модели |

## 2. Голосовой сервис

**Запуск.** `launch.mjs` после остальных сервисов запускает `services/voice/.venv/bin/python -m server --port 47645
--data <папка данных>/voice`, если окружение есть (папка задаётся `--voice-dir` или `DEFOPS_VOICE_DIR`). Сервис
необязательный: его остановка не останавливает приложение, нет окружения — не запускается. Порт занят отвечающим
голосовым сервисом (запущен вручную) — приложение подключается к нему. Шлюз отдаёт `/api/voice`: порт и состояние
(«не установлен» / «загружается» / «готов» / «ошибка …»). Модели грузятся 20–40 с — остальное приложение работает
сразу, панель показывает «Голос загружается».

**Протокол** (`ws://127.0.0.1:47645/ws`; двоичное — звук, текст — JSON):

| Окно → сервис | |
|---|---|
| двоичные кадры | микрофон, int16, 16 кГц, по 512 отсчётов |
| `hello {settings}` | пороги (vad, barge_vad, barge_ms, end_ms) из настроек окна |
| `say {id, role, text}` | сказать текст голосом роли; куски, паузы, договаривание — в сервисе |
| `stop {id?}` | замолчать (всё или фразу) |
| `played {id}` | окно доиграло фразу |
| `settings {…}` | пороги |
| `calib {step: noise\|speech\|echo\|over\|finish\|cancel, sec}` | калибровка, как на стенде |
| `voice {op: list\|record-start\|record-stop\|preview\|save\|assign\|delete, …}` | голоса |

| Сервис → окно | |
|---|---|
| `ready {voices, roles, loaded}` | готовность |
| `level {p, busy}` | уверенность речи (~10 раз в с) |
| `speech {state: start\|end}` | речь началась / кончилась |
| `utterance {id, text, audio_s, stt_ms, continues?}` | распознанная реплика; `continues` — склеена с прежней |
| двоичные: `[0x01][id u32][rate u32][pcm int16]` | звук фразы `say` |
| `say-done {id}`, `barge {id}` | договорил / перебили |
| `calib_step`, `calib_result`, `voice_*` | калибровка и голоса |
| `error {text}` | |

**Склейка реплики после паузы.** Новая речь началась не позже 2 с после конца прежней реплики, а ответ на прежнюю ещё
не звучит или звучит меньше 1,5 с → сервис перебивает ответ и отдаёт `utterance` с текстом обеих частей и
`continues: <прежний id>`. Окно бросает обработку прежней реплики (запрос к модели отменяется, начатое действие
не исполняется: необратимое и так ждёт подтверждения).

**Синтез.** Сервис получает текст целиком или кусками (`say` по мере ответа модели) и сам делит на куски для
синтеза, как на стенде: первая фраза сразу, короткая (< 30 знаков) — со следующей (ждать ≤ 0,4 с), дальше — по
запасу звука (< 1 с) или 300 знаков; договаривание 1 кадра, затухание 10 мс, паузы по знаку. Числа и сокращения
словами делает окно (`speech.ts`) до отправки: тексты действий и модели проходят одну нормализацию.

**Заготовка звука.** Фразу, известную заранее, окно отдаёт `prepare {id, role, text}`: сервис синтезирует её целиком
сейчас (куски до 300 знаков, по очереди с другими заготовками; между кусками нить синтеза успевает живые фразы и
Smart Turn) и отвечает `prepared {id, audio_s}` или `{id, error}`. `say` того же текста тем же голосом играет готовый
звук без синтеза; заготовка ещё идёт — её куски уходят в окно по мере готовности. Так озвучивается разбор хода:
синтез заканчивается до того, как за решение берётся языковая модель штаба противника, и не делит с ней машину.

**Голоса.** Образцы — `<данные>/voice/voices/<id>/{ref.wav, ref.json}` (текст, дата, источник), роли —
`roles.json`. Встроенные: образцы стенда (Жуков 10 с — роль «посредник»; до записи штабиста — он же у
начальника штаба). Запись нового голоса:
1. на экране предупреждение (голос будет использоваться системой, хранится только на этом компьютере) и текст для
   чтения 15–20 с;
2. запись; сервис обрезает тишину по краям, оставляет 0,4 с естественной паузы в конце;
3. проверка: громкость, отношение сигнал/шум, распознанное против текста (доля ошибок по словам ≤ 15 %) — иначе
   «перечитайте» с причиной;
4. пробная фраза новым голосом → «Сохранить» → назначить роль. Удаление — одной кнопкой (файлы стираются).

## 3. Голос в окне

**Панель** (поверх любого раздела, сворачивается в значок): состояние — «жду обращения» / «разговор» / «слушаю» /
«думаю» / «говорит» / «голос загружается» / «голос не установлен»; уровень речи с порогами; лента реплик (не
обращённые к штабу — серым, «не мне»); «Что можно сказать» (из реестра для текущего раздела и состояния);
калибровка (как на стенде, четыре шага); голоса; регуляторы стенда.

**Разбор реплики** (`dispatch.ts`):
1. *Обращение.* В начале фразы «штаб» или «товарищ полковник/генерал» с запасом на огрехи распознавания
   («штап»). Без обращения и вне окна разговора (12 с после ответа штаба) — реплика только в ленте.
2. *Правила* (мгновенно, без модели): «да»/«так точно», «нет»/«отставить», «стоп»/«тихо», «повтори»,
   «вариант N»/«N-й», «дальше»/«назад»/«хватит» (тур), «открой <раздел>», «что я могу сказать».
3. *Модель с инструментами* — остальное. Запрос OpenAI-совместимый с `tools` через `/llm/v1`; модель — новая
   настройка «Голос» в разделе «ИИ» (по умолчанию как в «ИИ», размышление выключено). В системном тексте: роль
   начальника штаба, правила озвучки (как на стенде), краткая обстановка от раздела. Инструменты — действия
   реестра, доступные сейчас. Цикл: ответ текстом — потоком в `say` кусками; вызов инструмента — проверка
   параметров (ошибка — модели, до двух поправок), необратимое — в подтверждение, иначе исполнение и результат
   модели для короткого доклада.
4. *Подтверждение.* «Делаю ход на шестое апреля, шесть ноль-ноль. Подтверждаете?» — ждёт «да»/«нет» 15 с, потом
   «Отменено». Пока ждёт, другие команды не исполняются (кроме «стоп»).
5. *Сбой LM Studio* (ошибка, пустой ответ, нет ответа 20 с): повтор сразу, через 1 с, через 3 с; со второй попытки —
   заготовленная фраза «Связь с моделью прервалась, повторяю запрос»; после третьей — «Связи с моделью нет».

Даты и время в параметрах разбираются правилами (на стенде модель ошибалась в датах): модель передаёт слова, окно
переводит их в время игры.

**Реестр** (`registry.ts`):

```ts
interface Action<P = unknown> {
  id: string;                    // 'command.turn'
  section: Section | 'global';
  title: string;                 // для подсказок и тура
  describe: string;              // для модели
  params?: JsonSchema;
  say?: string[];                // примеры фраз: «штаб, делай ход»
  irreversible?: boolean;
  confirm?(p: P): string;        // текст подтверждения
  available(): true | string;    // строка — почему недоступно (для модели и подсказок)
  run(p: P): Promise<string | void>;   // строка — что доложить
}
useAction(action)                         // регистрация из компонента (живёт, пока компонент смонтирован)
<ActButton action="command.turn" …/>      // кнопка, вызывающая действие; data-action для тура и проверки
act('command.variant.pick', { n: 2 })     // вызов из обработчика
```

Кнопки и прочие элементы управления раздела вызывают действия реестра — голос и мышь исполняют один код.

## 4. Раздел «Командование»

**Полный охват** — всё, что делается в разделе мышью:
- вход в игру: момент на шкале переигровки, сторона, «принять командование», режим противника, модель штаба
  противника;
- обстановка: доклад по донесениям и своим войскам, разведка, цели, журнал по дням;
- приказы соединениям: кому, задача, цель (место), отмена приказа;
- распоряжения: базы и приоритет подвоза, переправы (навести/снять), ввод резервов (армия целиком/не вводить),
  разграничительные линии (предложить, принять);
- решение по полям (оценка, замысел противника, замысел, доклад, риски, ходатайство в Ставку): надиктовать или
  поручить начальнику штаба составить;
- советник: варианты (сколько), подробнее о N, выбрать N («в распоряжение» / «только решение»), вопрос, остановить,
  повторить запрос;
- ход (необратимо); после хода — доклад посредника;
- поправки посредника, «как действовал противник», показать всех (без тумана войны);
- разбор операции: разделы, остановить, выгрузить .md;
- карта: показать место/соединение, приблизить/отдалить, слои, уровень карты, легенда; карточки соединений и разведки;
- выход из командования.

Обстановка для модели — сжатая (ход, время, донесения за ход, цели, варианты советника, ожидающее подтверждения).

**Места.** По названию из словаря театра и `TurnView.places` (поправка названий как на стенде), соединения — по
названию и номеру («восьмая гвардейская»); относительно названия — «N километров <сторона света> <места>».
Произвольная точка голосом не задаётся: начальник штаба предлагает ближайшие названные места.

**Посредник.** После хода — 3–5 фраз от лица посредника: что изменилось, главные события, продвижение к целям; по
донесениям хода и целям, моделью; перебить можно.

**Проверка полноты.** Тест разбирает исходники раздела (CommandView и вложенные панели, вход в командование в
ReplayView): каждый обработчик элемента управления (`onClick`, `onChange`, `onSubmit` и т. п.) вызывает действие
реестра (`act`, `ActButton`, `useAction`). Исключения — короткий список с причиной в тесте (перетаскивание карты
мышью — у голоса свои «приблизь/покажи»).

## 5. Подсказки и тур

- **«Что можно сказать»** — список в панели из `say` доступных действий; недоступные — с причиной серым.
- **По ходу**: после вариантов советника — «Скажите: подробнее о втором, или — выбираю второй»; при
  подтверждении — «Скажите да или нет».
- **«Штаб, что я могу сказать?»** — 5–7 главных команд для текущего состояния голосом.
- **Знакомство** после первой калибровки: как обращаться, окно разговора, три примера, предложение тура.
- **Тур** («Штаб, покажи раздел»; предлагается при первом входе в раздел): шаги из `tours/command.ts` — элемент
  (`data-action`), текст, пример фразы. Начальник штаба проговаривает шаг; остальной экран притемнён, вокруг
  элемента светящаяся рамка, плавно переезжающая к следующему; внизу подпись и пример фразы. Следующий шаг — когда
  договорил; «дальше», «назад», «подробнее», «хватит». Недоступный элемент — шаг объясняет, когда он появится.

## 6. Ошибки

- Голосовой сервис не установлен — панель: «Голос не установлен: services/voice/setup.sh» (один раз).
- Упал — панель предлагает перезапустить (через шлюз), приложение работает без голоса.
- LM Studio — повторы (раздел 3); правила работают без модели.
- Действие упало — начальник штаба докладывает кратко («Не вышло: …»), подробность — в ленте.

## 7. Проверка

- **pytest** (`services/voice/tests`, `npm run test:voice`; в `npm test` не входит — нужен Python-окружение голоса): калибровка, склейка реплики, деление на куски и
  склейка коротких фраз, договаривание кадра, проверка записи голоса, протокол на поддельных моделях.
- **vitest**: обращение и огрехи распознавания, окно разговора, правила, подтверждение и его истечение, повторы при
  сбое LM Studio, цикл модели с инструментами против поддельной LM Studio, нормализация чисел, места, полнота
  раздела, шаги тура ссылаются на существующие действия.
- **Сквозная** (Playwright, поддельный микрофон, сервис `--fake`, поддельная LM Studio): запуск → калибровка →
  «Штаб, открой переигровку» → принять командование → «Штаб, дай три варианта» → «выбираю второй» → «сделай ход» →
  «да» → посредник; тур с подсветкой; снимки.
- **На Mac** (пользователь): живой звук и задержки, голоса, запись нового голоса, ложные срабатывания на разговор
  в комнате — короткий список к каждой ступени.

## 8. Ступени

1. **Голосовое ядро**: `services/voice` (перенос стенда, протокол, склейка, голоса и запись нового голоса), запуск
   из `launch.mjs`, панель, калибровка, правила, переходы между разделами, «что можно сказать».
2. **Реестр и модель**: реестр, модель с инструментами, подтверждение, повторы; командование — обстановка,
   советник, ход, посредник.
3. **Полный охват командования**: остальные действия, места, проверка полноты, тур, знакомство.

Каждая ступень — рабочая сама по себе, с тестами, описанием системы (`docs/system.md`, раздел «Голосовое
управление»; снимки; PDF и Word) и списком проверки на Mac.

## Вне этой спецификации

Остальные разделы (редактор, моделирование, карты, база знаний, библиотека, «ИИ») — следующие подпроекты на том же
реестре. Произвольные точки карты голосом. Голосовое управление на Windows и Linux (стек — MLX, только Apple Silicon).
