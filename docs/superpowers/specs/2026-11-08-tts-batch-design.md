# Температура и пакетная подготовка итоговой речи

Пользователь одобрил настройку температуры и пакетную генерацию итоговых фраз. Цель — убрать восемь последовательных обращений к Qwen, сохранив подготовку всего звука до показа итога. Новых ограничений длины/времени синтеза нет. Реальное ускорение требует Windows/CUDA, локальные тесты его не доказывают.

В меню оператора → Сеанс → Генерация и озвучка: температура 0–1 с шагом 0,1 (по умолчанию 0,2), пакет 1/2/4 (по умолчанию 4). Ноль означает greedy для talker и code predictor. Настройки сохраняются в ExpoSettings.generation.temperature / batchSize; прежние файлы получают defaults без признака порчи. Температура применяется к живым комментариям и разбору; пакет — к подготовке разбора. Предзаписи не перегенерируются.

Управление GPU, Qwen ru-stress, словарь, образцы, NF4/FlashAttention, полный текст и penalty1.5 сохраняются. Не создавать несколько моделей/потоков GPU: один вызов generate_voice_clone получает список текстов. На Mac допустим совместимый последовательный fallback внутри базового Models. Для Windows genuine batch обязателен. Восемь фраз с batch4 — два model.generate_voice_clone вызова, один подготовленный voice prompt на образец.

Синтез-параметры привязаны к запросу, не к глобальному состоянию сервиса. PCM-кэш различает температуру; say использует ту же температуру, что prepare. Настройки начатого комментария/разбора фиксируются, изменения оператора относятся к следующему этапу. Подготовленные фразы воспроизводятся без повторного синтеза.

Готовность: реальные счётчики после завершения пакета (4/8, 8/8), только затем result. Отмена/разрыв не публикуют ложную готовность и не оставляют будущие пакеты в очереди. Начатый CUDA-вызов может завершиться в executor, его поздний результат отбрасывается. Ошибка одного пакета явно завершает подготовку ошибкой; модель/точность не подменяются.

Уточнения пользователя: плашка ожидания содержит только «Готовим итог — N%», без информации о файлах, стадиях и времени; процент=floor(done/total*100). В тот же патч включается исправление фотографий: фото и подпись помещаются в границы сцены, в том числе на заставке в одноконной раскладке, на боковых экранах и при смене изображения.

Поставка: отдельный автономный Python-патч для уже установленного NF4/FA2 комплекта. Никаких пересборок EXE/переустановки зависимостей. Встроенный Python проверяет короткий пакет на CUDA перед активацией новых исходников и интерфейса; журнал содержит реальные размеры/время/VRAM. Без Windows не утверждать ускорение. Словарь, база знаний, предзаписи и настройки голосов сохраняются.


## Дополнения пользователя

CPU для TTS — отдельная настройка оператора 1/2/4/8, по умолчанию 2. Это intra-op CPU-параллелизм PyTorch в единственной нити TTS, не число CUDA-моделей и не число WS-запросов. Параметр на запрос (`cpu_threads`), захватывается вместе с температурой до этапа. Не перезапускает модели и не задаёт inter-op параллелизм. Mac/старый сервис не принимает нестандартный выбор молча; значение по умолчанию сохраняет совместимый режим. Исполнительный параметр не инвалидирует уже готовый PCM. Native probe проверяет реальный get_num_threads после 1/2/4/8 и при синтезе с 2.

Два независимых флага `commentVoice` и `debriefVoice` (по умолчанию true) управляют только аудио. Исходные `comments` и `debrief` сохраняют управление всем этапом. Комментарий без голоса всё ещё приходит из LLM после карты, показывается на время чтения и завершает этап перед итогом. Итог без голоса пропускает подготовку PCM, но алгоритм и последовательный текстовый разбор остаются; настройки звука фиксируются до следующего этапа.
