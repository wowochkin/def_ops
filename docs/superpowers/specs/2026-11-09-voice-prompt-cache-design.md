# Постоянный кэш образцов Qwen

Запрос пользователя: три голоса подготавливаются один раз и затем используются без повторного
кодирования после выгрузки TTS. Замер Windows показал 21,92 с на подготовку образца при 0,30 с
на декодирование новой фразы. Требуется убрать повторную подготовку, сохранив освобождение GPU.

Решение: кэш аудиокодов и speaker embedding в CPU-памяти и в локальном файле рядом с ref.wav.
Каждый голос создаётся при первом использовании; остальные записи не вытесняются при смене роли.
Повторная загрузка GPU-модели читает готовые CPU-тензоры; перезапуск службы читает файл.
Первичный синтез прогрева модели остаётся: готовый образец не заменяет прогрев GPU.

Кэш содержит только данные, без pickle и исполняемых объектов. Используется уже установленный
safetensors, запись — во временный файл с атомарной заменой. Тензоры сохраняют точность без
квантования; Qwen сам переносит их на GPU в generate. Контрольная сумма данных проверяется при чтении.
Неполный/повреждённый кэш пересчитывается. Невозможность записи оставляет CPU-кэш рабочим и пишет
предупреждение. Изменения WAV (по содержимому), расшифровки, версии кэширования/библиотек,
профиля и идентификатора локальных весов делают запись недействительной.

Удаление/отмена образца очищает его CPU/дисковый кэш; незавершённое кодирование не возвращает
удалённую запись в кэш. Посторонние файлы не удаляются. UI, порядок LLM/TTS и параметры синтеза
не меняются. Mac MLX сохраняет прежний путь. Windows получает небольшой офлайн-патч с резервной
копией и откатом без пересборки EXE/установки зависимостей. Нативный CUDA-результат не объявляется
из локальных CPU-тестов; в патч включается проверка сохранения кэша между загрузками.

Технические решения о safetensors, ленивой подготовке и CPU-кэше приняты при реализации
в рамках запроса; дополнительных настроек от пользователя не требуется.
