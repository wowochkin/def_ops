# База знаний ↔ моделирование, часть 2: документы → факты всех видов, проверки, очередь, правка фактов

## Цель

После части 1 модель берёт из базы только факты с формальной частью (`claim`), а такие факты есть лишь во встроенной
базе (сид). Загруженные документы дают текстовые факты, положения, линии и объекты инфраструктуры — до сборщика они не
доходят или идут в модель в обход него; численность по датам, пополнения, подчинённость, ввод, события и потери из
документов не извлекаются; править факты вручную нельзя.

Часть 2 замыкает контур «документ → база → модель»:

1. любой вход — текст, скан, таблица, пакет внешнего агента, ручная правка — даёт **кандидатов-фактов** с формальной
   частью и доказательством;
2. **общие проверки** решают: в базу сразу (проверено автоматически), в очередь «На проверку» или отбросить;
3. принятое попадает в модель **только через сборщик части 1**;
4. факты базы **правятся вручную**, встроенные — исправлением с источником.

Это часть 2 из 4. Часть 3 — правила модели из базы (нормативы со значениями, калибровка в их границах); часть 4 —
советник, посредник и штаб противника на той же базе.

## Решения, принятые с заказчиком

| Вопрос | Решение |
|---|---|
| Из чего пополняется база | Всё важно: тексты с текстовым слоем, сканы архивных документов, таблицы и JSON, пакеты внешнего агента |
| Как извлечённое попадает в модель | По уверенности: прошедшее все автоматические проверки — сразу; сомнительное — в очередь на проверку человеком |
| Чем распознавать сканы | Только моделью со зрением на сервере моделей (без Tesseract); модель выбирается в настройках |
| Правка встроенных фактов | «Исправить» создаёт факт пользователя с источником и пометкой «исправляет встроенный»; встроенный исключается |
| Таблицы | Шаблон читается напрямую; любая другая таблица — через предложенное моделью и подтверждённое сопоставление столбцов |
| Внешний агент | Приложение составляет md-задание по пробелам базы с форматом ответа; пакет загружается обратно |
| Устройство | Единый конвейер «кандидат → проверки → база» вместо отдельных очередей |
| Участие языковой модели | Извлечение и сопоставление столбцов; проверки 1–7 — код; восьмая — перекрёстное прочтение цитаты моделью (выключается); в очереди — подсказки по кнопке |
| Модели | Три роли с выбором модели: разбор документов, чтение сканов, перекрёстная проверка |

## 1. Кандидат-факт

`packages/knowledge/src/candidate.ts`:

```ts
type Origin = 'text' | 'scan' | 'table' | 'agent' | 'manual';
type Evidence =
  | { kind: 'quote'; doc: string; chunk: number; quote: string }
  | { kind: 'scan'; doc: string; page: number; quote: string; box?: [number, number, number, number] }  // доли страницы
  | { kind: 'row'; doc: string; row: number; cells: Record<string, string> }
  | { kind: 'agent'; ref: string; quote?: string }     // шифр, ссылка на карточку документа, выписка
  | { kind: 'manual'; note?: string };

interface Candidate {
  id: string;
  claim: Claim;                       // виды части 1; subject — id, если сопоставлено, иначе ''
  names: { subject?: string; parent?: string; place?: string; between?: [string, string] };  // как в источнике
  key: string; value: string;         // текстовая часть факта (как сейчас)
  source: string; pages?: string; reliability?: Reliability;
  origin: Origin;
  evidence: Evidence;
  op?: string;                        // операция, к которой относится документ
  checks: CheckResult[];
  verdict: 'auto' | 'review' | 'drop';
  state: 'pending' | 'accepted' | 'rejected';    // для очереди
  corrects?: string;                  // ключ встроенного факта (entry#index + отпечаток), если это исправление
}
type CheckResult = { check: CheckId; level: 'ok' | 'doubt' | 'fail'; why?: string };
type CheckId = 'quote' | 'numbers' | 'subject' | 'place' | 'date' | 'plausible' | 'duplicate' | 'cross';
```

## 2. Проверки

`packages/knowledge/src/checks.ts` — чистые функции (кроме `cross`).

| # | Проверка | ok | doubt | fail |
|---|---|---|---|---|
| 1 | `quote` — цитата | текст: найдена в части документа; скан: есть в расшифровке и без «?» в числах; таблица: строка есть; агент: выписка есть или есть ссылка | скан: числа помечены «?» | текст: цитата не найдена; таблица: строки нет |
| 2 | `numbers` — числа в цитате | каждое число claim есть в цитате (без учёта пробелов, точек, неразрывных пробелов между разрядами) | — | число не найдено |
| 3 | `subject` — соединение | `matchFormation` / запись базы — ровно одно | не найдено или больше одного | — |
| 4 | `place` — место (position, boundary-пункты) | найдено на театре (`locatePlace`) или есть координаты | не найдено | — |
| 5 | `date` — дата | ISO; для операции — от начала минус 7 суток до конца | вне пределов операции | не дата |
| 6 | `plausible` — правдоподобие | в пределах | за пределами | — |
| 7 | `duplicate` — повтор | — | — | тот же claim и тот же источник уже в базе (молча, счётчик) |
| 8 | `cross` — перекрёстное прочтение | ответ модели совпал | не совпал (с объяснением модели) | — |

Правдоподобие (`plausible`), пороги — допущения, строки в `packages/sim/data/rules/norms.json`:
- численность по ступени: дивизия ≤ 20 000, корпус ≤ 60 000, армия ≤ 150 000, фронт / группа армий ≤ 1 200 000;
- потери за период ≤ численности соединения (последний факт численности или сценарий);
- потери за сутки ≤ трети численности;
- вышестоящий — выше по ступени, чем соединение;
- пополнение ≤ половины численности соединения.

Перекрёстное прочтение (`cross`): отдельный запрос модели роли «перекрёстная проверка» получает **только цитату** и
вопросы с вариантами — чья это численность/потери (называет соединение), наши или противника, факт или план/приказ,
за какой период / на какую дату, что означает каждое число (люди, танки, убито, ранено…). Сравнение с claim — кодом:
расхождение в стороне, «плане», соединении (после сопоставления) или в значении числа → doubt. Выключено в
настройках → проверка не выполняется, и всё, что извлечено моделью из текста или скана (`origin` text/scan), идёт в
очередь (doubt «перекрёстная проверка выключена»); таблицы, пакеты агента и ручная правка — как обычно.

Итог: есть `fail` → `drop` (виден в итогах документа с причиной); иначе есть `doubt` → `review`; иначе → `auto`.
Ручная правка (`manual`) проходит проверки 3–7; `doubt` у ручной правки — предупреждение в форме, сохранить можно.

## 3. Входы

`packages/knowledge/src/extract.ts` (схемы и сборка кандидатов) и `apps/editor/src/kb/ingest.ts` (поток разбора).

**Текст** (PDF с текстовым слоем, docx, txt, md, html): части по ~3000 знаков с перекрытием (как сейчас), с
продолжением с места остановки. Схема ответа: `items` (текстовые записи — как сейчас) и `claims[]` — вид, сырые
названия, дата или период, значения, вышестоящий, место, координаты (если в тексте), цитата. `positions`,
`boundaries`, `infrastructure` в схеме заменяются видами `position`, `boundary`, `crossing` в `claims`; прочая
инфраструктура (дороги, рубежи) остаётся текстовыми фактами записи операции.

**Скан** (PDF без текстового слоя — меньше 50 знаков на страницу, JPG, PNG): страница → картинка (pdfjs → canvas);
высокая страница (таблица) режется на 2–4 полосы с перекрытием 10 %. Запрос к модели роли «чтение сканов»: дословная
расшифровка полосы (неразборчивые знаки — «?») и `claims` с цитатой — куском расшифровки и местом на странице (`box`).
Расшифровка и картинки страниц хранятся при документе. Нет модели со зрением — документ сохраняется со статусом
«ждёт распознавания», сообщение о выборе модели.

**Таблица** (CSV, XLSX — чтение через библиотеку в браузере, выбор — в плане; JSON шаблона):
- шаблон (`docs/facts-template.md` + образцы CSV и JSON, скачиваются из приложения): столбцы `kind, subject, date,
  date_to, personnel, tanks, guns, killed, wounded, missing, total, parent, place, lat, lon, approx_km, source, pages,
  reliability, quote, note`;
- не шаблон → модель роли «разбор документов» получает заголовки и первые 10 строк и предлагает смысл каждого столбца
  (или «пропустить») и вид фактов; пользователь подтверждает или правит в окне сопоставления; дальше строки
  разбираются кодом, без модели;
- «дни в столбцах» (заголовки — даты, строки — соединения): сопоставление «столбцы-даты → значение вида X» даёт по
  кандидату на ячейку;
- строка с ошибкой (дата не дата, число не число) → `drop` с номером строки.

**Пакет агента** — JSON `{ format: "def-ops-facts", version: 1, source: {...}, facts: [...] }` (тот же шаблон, что у
таблицы) и при необходимости архив/папка со сканами, на которые ссылаются `evidence`.

**Задание для агента** (`packages/knowledge/src/agent-task.ts`, кнопки в «Подсказках, что искать» и в «Основе
модели»): md-файл по операции — назначение; пробелы (соединения и даты без фактов численности, потерь,
подчинённости, положений — из `compileOperation` и полноты базы); где искать (из подсказок); общие правила по образцу
`docs/tsamo-agent-task.md` (только документ с шифром и ссылкой; тексты не переписывать — пересказ до 300 знаков,
цитата до 25 слов; координаты WGS84 и радиус неопределённости; время как в документе; «пустой результат — тоже
результат», перечень просмотренного); точный формат ответа (`def-ops-facts`).

**Ручная правка**: форма по виду факта (поля claim, источник, страницы, надёжность, заметка); без источника — факт
«допущение» (`reliability` нет). «Исправить» у встроенного факта — форма с его значениями, сохранение создаёт факт
пользователя с `corrects` и закрепление «не брать» встроенного (`pins`, как в части 1).

## 4. Хранение

- `Fact` (`schema.ts`) получает необязательные поля:
  - `check?: { by: 'auto' | 'human'; at: string; results: CheckResult[] }`;
  - `evidence?: Evidence`;
  - `corrects?: string`.
- Принятые факты — в записях слоя пользователя (как сейчас). Запись выбирается по сопоставлению соединения; нет
  записи, но соединение есть в сценарии — запись создаётся; нет нигде — кандидат ждёт в очереди («соединение не
  найдено»: указать вручную или создать запись).
- IndexedDB `def_ops_kb` версии 7: новое хранилище `candidates` (заменяет `proposals`, `infra`, `positions`,
  `boundaries` для новых документов); при документе — `pages` (картинки страниц) и `transcripts` (расшифровки).
- **Перенос** при открытии базы версии 7: принятые положения, линии, объекты-переправы из прежних хранилищ → факты с
  claim, `check.by = 'human'`; для чего claim не собрать (место или соединение не найдены) — текстовый факт, как был.
  Отклонённые и ждущие — кандидатами с прежним состоянием. Записи-предложения (`proposals`) — кандидатами без claim
  (текстовые, принимаются как сейчас).
- Выгрузка/загрузка материалов (`exportUser` / `importUser`, `version: 2`) включает кандидатов, `check`, `evidence`;
  картинки страниц и расшифровки — нет (документ загружается заново); файл `version: 1` загружается с переносом.
- Положения и линии из документов больше не пишутся в правки операции напрямую (`acceptPositions`,
  `acceptBoundaries`, `saveInfra` для переправ) — они факты базы и идут через `compileOperation`.
- Встроенный факт изменился при пересборке сида (отпечаток части 1 не совпал) → исправление с `corrects` получает
  пометку «встроенный факт изменился — пересмотрите» в записи и в «Основе модели».

## 5. Выбор факта

`resolve` (часть 1) без изменений, кроме последнего звена после «более свежего документа»: «проверено человеком»
(`check.by = 'human'`, факты сида — тоже) > «проверено автоматически» > без `check`. Факт с `corrects` выигрывает у
исправленного встроенного благодаря закреплению «не брать».

## 6. Интерфейс

- **Загрузка** («Знания» и «Моделирование» → «Материалы»): одна кнопка для PDF, docx, txt, md, html, JPG, PNG, CSV,
  XLSX, JSON; рядом надёжность, заметка, операция; диапазон страниц для больших документов. Тип входа определяется
  сам. Ход разбора: «часть / страница N из M; принято автоматически X, на проверку Y, отброшено Z»; стоп и
  продолжение.
- **Окно сопоставления столбцов**: заголовки с тремя строками примера; у каждого — предложенный смысл (список);
  вид фактов; «Разобрать».
- **Итоги документа**: три счётчика; отброшенное с причинами; принятое таблицей со ссылками на записи; «Откатить
  документ» — снимает автоматически принятые из него факты (принятые человеком остаются с пометкой «документ
  откачен»).
- **Вкладка «На проверку»** в «Знаниях» со счётчиком: карточка кандидата — вид и значения (правятся на месте),
  соединение (выбор из сценария и записей, предложенное первым), дата, источник; справа доказательство — цитата с
  подсветкой чисел / картинка страницы с выделенным местом и расшифровкой / строка таблицы; сверху причины сомнения;
  «Принять», «Отклонить», «Почему сомнение», «Предложи исправление» (модель по кнопке, принимает человек); групповые
  действия — «принять все, где сомнение только в …», «отклонить все из документа»; фильтры по документу, виду,
  соединению, причине.
- **Запись → «Формальные факты»**: значок «авто / человек / встроенный»; у своих — «изменить», «удалить»; у
  встроенных — «исправить»; «+ Факт».
- **«Основа модели»**: в итоге — разбивка «проверено человеком / автоматически / встроенное»; у источника числа —
  как принят и доказательство; кнопка «Задание для агента».
- **Настройки → «Модель и штабы»**: роли «разбор документов» (`kbModel`, есть), «чтение сканов» (`scanModel`, новое;
  кнопка «Проверить» — тестовая картинка с числом; не видит — «эта модель не видит изображений»), «перекрёстная
  проверка» (`crossModel`, новое; выключатель `crossCheck`, по умолчанию включён; совет брать другую модель, чем для
  разбора).

## 7. Ошибки и крайние случаи

- Сервер моделей недоступен / таймаут — разбор останавливается на текущей части, сделанное сохранено, «Продолжить» —
  с места остановки.
- Зацикливание или ответ не по схеме — как у штаба противника (`degenerate`, повтор без схемы); вторая неудача —
  часть «не разобрана», видна в итогах.
- Скан без модели со зрением — документ «ждёт распознавания».
- Несопоставленные столбцы пропускаются и перечислены в итогах.
- Один факт в двух документах — два факта с разными источниками; resolve выбирает, расхождение видно.
- Документ на сотни страниц — фоновый разбор, диапазон страниц.

## Проверка

- Юнит-тесты: каждая проверка (числа «4 910» / «4910» / «4.910», неоднозначное соединение, правдоподобие по ступеням,
  повтор); итог кандидата; разбор шаблона CSV/XLSX/JSON; «дни в столбцах»; перенос прежних хранилищ и выгрузки
  `version: 1`; «исправить» и пометка после изменения встроенного; звено «человек > авто» в resolve; задание для
  агента (пробелы операции в тексте).
- Языковая модель в тестах — записанные ответы (разбор текста, скана, перекрёстная проверка, сопоставление столбцов).
- Сквозная проверка на Берлинской операции: выписка (текст), таблица потерь по дням (CSV), пакет агента (JSON) —
  сколько принято автоматически, в очереди, отброшено; как изменились «Основа модели» и сверка численности. Цифры в
  описание — только из этого прогона. Скан — на 1–2 страницах, если есть модель со зрением; иначе на записанном ответе,
  с пометкой в описании.
- Снимки: загрузка с ходом разбора, итоги документа, очередь с картинкой страницы, окно сопоставления, редактируемые
  «Формальные факты», настройки трёх ролей.
- По правилам репозитория: `docs/system.md` (части I и II), `npm run kb:seed`, нормативы (`norms.json`, пороги
  правдоподобия — допущения; `npm run sim:norms -- --doc docs/norms-check.md`), `docs:system`, `typecheck`, `test`.

## Вне части 2

- Нормативы со значениями из базы и калибровка в их границах — часть 3.
- Советник, посредник и штаб противника на пользовательской базе — часть 4.
- Распознавание без модели со зрением (Tesseract и т. п.).
- Поиск в «Памяти народа» из приложения — остаётся внешнему агенту по заданию.
