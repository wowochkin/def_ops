# Постоянный кэш образцов Qwen — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans; выполнение в текущей сессии.

**Goal:** повторно использовать три подготовленных голоса после unload/load TTS и перезапуска службы.
**Architecture:** CPU-тензоры + атомарный safetensors рядом с ref.wav; отдельный модуль хранения,
интеграция только в TorchModels. Подготовка по первому обращению, проверка источника и сброс при удалении.
**Tech Stack:** Python3.12, PyTorch2.7.1/CUDA, safetensors, существующий Windows runtime.
**Spec:** docs/superpowers/specs/2026-11-09-voice-prompt-cache-design.md

## Global Constraints
- Без новых зависимостей, MLX на Windows и изменения синтеза/LLM-порядка.
- CPU-кэш не удерживает GPU или модель; unload сохраняет подготовленные данные.
- Ошибка/повреждение кэша не ломает синтез, изменение источника исключает прежние данные.
- Прежние незакоммиченные доработки сохраняются; коммит/публикация не запрошены.

## Review Focus
- Переключение всех трёх голосов, unload/load и новый процесс не вызывают повторное кодирование.
- Новое содержимое WAV при прежних размере/mtime, новый текст или модель не используют старый кэш.
- Повреждённая/частичная запись и отсутствие прав записи не ломают обычный синтез.
- Удаление/отмена во время подготовки не восстанавливает данные удалённого образца.
- CPU-тензоры сохраняют dtype/значения, проходят реальный pinned Qwen wrapper, не держат GPU-модель.
