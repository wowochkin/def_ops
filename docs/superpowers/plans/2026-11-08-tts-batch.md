# Температура и пакетная подготовка — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Tasks use checkbox tracking.

**Goal:** Настройка температуры и настоящий CUDA batch для итоговых фраз, совместимые с текущим Windows-комплектом.
**Architecture:** Параметры на запрос; один executor и одна модель. Подготовка блокирует итог до всех пакетов, PCM повторно используется при say.
**Tech Stack:** Python3.12, Qwen TTS0.1.1, Torch2.7.1+cu128/Transformers4.57.3; TypeScript/React.
**Spec:** docs/superpowers/specs/2026-11-08-tts-batch-design.md

## Global Constraints
- Температура0–1, default0.2; batchSize1/2/4, default4. При0 оба sampler greedy.
- Не менять модель боя, Mac-движок, веса, точность, FA2, full-text/penalty1.5; не добавлять synth timeout/caps.
- Комментарии после карты; весь итог заранее; GPU handoff сохранён; никакого eager LLM/TTS overlap.
- Сохранить dirty tree; без коммитов. Патч не трогает словари/предзаписи/роли.

## Frozen Interfaces
- WS ready adds optional `capabilities:{prepare_batch:true,tts_temperature:true}`.
- WS prepare/say add optional `temperature:number`; absent retains old engine defaults. Prepared-cache key includes temperature.
- WS request `{type:'prepare-batch',id:number,role,texts:string[],voice_id?:string,temperature?:number,batch_size?:1|2|4}`; cancel `{type:'cancel-prepare-batch',id}`.
- WS response `{type:'prepared-batch',id,done:number,total:number,audio_s?:number[],error?:string}`: intermediate done<total, final done=total; error terminal. `audio_s` original text order when final.
- Python `Models.tts_batch(texts:list[str],ref,*,temperature:float|None=None)->list[np.ndarray]`: base/fake compatible fallback, Torch single true batched call. `tts_stream` accepts optional keyword temperature; omit keyword when None for legacy mocks.
- Client `prepare(role,text,voiceId?,signal?,temperature?):Promise<boolean>`; `say(id,role,text,more?,voiceId?,temperature?)`.
- Client `prepareBatch(role,texts,voiceId?,signal?,options?:{temperature?:number,batchSize?:1|2|4,onProgress?:(done:number,total:number)=>void}):Promise<boolean>`; `supportsPrepareBatch` boolean from current ready, reset on disconnect.
- Old service: default0.2 compatibility may prepare sequentially; non-default temperature must fail explicitly rather than silently ignore.
- ExpoSettings.generation adds required temperature:number/batchSize:1|2|4; normalize older objects, defaults0.2/4.
- expoSpeaker option `synthesis?:()=>{temperature:number,batchSize:1|2|4}`. stageSpeaker prepare callback may return selected temperature; LiveVoice.say optional temperature carries it to client so in-flight comments retain params.
- Stage freezes debrief synthesis options for preparing/result within same session; next comment/debrief reads saved settings.

## Review Focus
- Cancel mid CUDA batch, disconnect, old response after new session: no stale ready or future queued batch.
- Cache hit/duplicates/different temperatures: original order, no wrong PCM reuse, no re-synth during playback.
- Mixed lengths and same reference in pinned qwen0.1.1: proper batch prompts/audio counts and no cross-session mutation.
- Temperature0 invalid/NaN/string; legacy clients/old service and Mac fallback; no silent ignored settings.
- CUDA memory failure/unsupported backend: explicit error, no fake progress/precision fallback; native speed unverified until run.

## Приёмка

Нативная производительность CUDA остаётся неподтверждённой до автоматической проверки на Windows. Полный npm сохраняет два сбоя сравнения ядра expo-turns; они зафиксированы в журнале, без изменения модели. Финальная упаковка дополняется новым уточнением пользователя об одно-/многопоточности.
