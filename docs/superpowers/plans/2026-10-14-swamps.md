# Исторический слой: болота по штриховке — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** распознавать штриховку болот на подложенной исторической карте (по образцу «болото» или по цвету, выученному на современных болотах растра театра и OSM `natural=wetland`), сверять с современными болотами (на карте и сейчас / только на карте / только сейчас), показывать сводку и предпросмотр и записывать болота в местность театра.

**Architecture:** признаки окна штриховки — новый модуль `packages/sim/src/overlay-hatch.ts` (чистые функции над массивом классов пикселей тайла); `OverlayAccumulator.addTile` для классов из `legend.hatch` считает пиксели не поштучно, а окнами-болотами; современные болота (разбор OSM-мультиполигонов, маска на сетке поправки, `WetlandLearner`, `mergeMarsh`) — в `packages/sim/src/overlay-network.ts` рядом с дорогами и водой; запись — `applyOverlay` (порядок классов и флажок `marshGone`); поток `apps/editor/src/sim/overlay-worker.ts` учит цвет болот в первом проходе вместе с дорогами и водой; интерфейс — `apps/editor/src/HistLayer.tsx`.

**Tech Stack:** TypeScript, vitest, React; Rust и сборщик театра (`build_theatre.py`) не меняются.

**Spec:** `docs/superpowers/specs/2026-10-14-swamps-design.md`

## Global Constraints

- Пороги штриховки (`HATCH` в `overlay-hatch.ts`): доля чернил окна `0,03 ≤ ink ≤ 0,40`; `hRun ≥ 2 · vRun` и `hRun ≥ 3` px; `rows ≥ w / 6`; окно оценивается, если непрозрачных пикселей не меньше половины (`px ≥ 0,5 · w²`). Окно ≈ 120 м на местности по метрам на пиксель уровня тайлов, не меньше 12 и не больше 48 пикселей. Порог клетки «болото» — 0,3 (как сейчас в `legendFromSamples`).
- Окна кладутся по тайлу с шагом `w` от левого верхнего угла; последнее окно в строке и столбце прижимается к краю тайла (перекрывает предыдущее), за край тайла не выходит; тайлы не склеиваются (как `dropBlobs`).
- Чернила класса-штриховки определяются по его правилам легенды **независимо** от порядка классов (пиксель остаётся и в своём первом классе: вода того же цвета — водой, дорога в болоте — дорогой).
- Обучение цвета болот: окно «внутри» — центр в клетке современного болота (растр ∪ OSM); «снаружи» — центр не в болоте, расширенном на соседнюю клетку, и не в воде растра; корзина цвета (`colorBin`) присутствует в окне, если её пикселей ≥ 3 % окна; цвет узнан, если внутри ≥ 15 % окон и `≥ 2,5 × снаружи + 0,05` (как у воды и дорог) **и** не меньше половины окон «внутри» с этим цветом проходят `isHatch`; нужно ≥ 20 окон внутри и ≥ 20 снаружи; берутся до трёх цветов.
- Сверка областей: современное болото — связные клетки (по восьми соседям) растра «болото» ∪ полигонов OSM; «нет на карте» — если болото карты меньше чем в 10 % его клеток в охвате (как водоёмы); клетки «на карте и сейчас» / «только на карте» — поклеточно.
- `TERRAIN_CLASSES` не меняется (`marsh` — индекс 2, код растра `m`); новых классов местности нет.
- Запись: болото карты — поверх открытой местности, леса и высот, не поверх воды и застройки (ни существующих, ни карты: порядок `water → urban → marsh → forest`). «Убрать болота, которых нет на карте» (`marshGone`) по умолчанию выключено; снимается только клетка растра «болото» (болото, которое есть только в OSM, в растре не болото — его нечего снимать); класс — самый частый среди соседей из «открытая» и «лес» (радиус до 3 клеток), иначе открытая.
- Правило модели не меняется (поправки болота те же) — строки в `norms.json` нет.
- Язык интерфейса, описания, коммитов — русский; в описании нет дат и упоминаний ассистента и веток. По правилам репозитория (часть II, раздел 17.2): описание, снимок, `kb:seed`, `model:index`, `docs:system`, `docs:guide`; перед коммитом `npm run typecheck` и `npm test`.

## Review Focus

1. Образец «болото» того же цвета, что образец «вода» (или выученный цвет воды): пиксель относится к первому подходящему классу, и без независимых чернил штриховка не набрала бы ни одного пикселя. Штриховка этого цвета — болото, заливка — вода и не болото. Тест — задача 1.
2. Край карты и край тайла: тайл наполовину прозрачен, окно целиком прозрачно (`px = 0` — без `NaN`), 256 не кратно `w` (последнее окно прижато к краю). Болото только там, где карта есть, и каждый пиксель сплошь заштрихованного тайла лежит в каком-нибудь окне. Тест — задача 1.
3. OSM-мультиполигон: внешнее кольцо из двух путей, один из них в обратном направлении; кольцо, которое не замыкается; член отношения без геометрии; отношение с двумя внешними кольцами; незамкнутый путь `natural=wetland`. Кольца склеиваются, плохие пропускаются без исключения. Тест — задача 2.
4. В охвате нет современных болот или их мало (< 20 окон): цвет не узнан, легенда без `marsh`, поток не падает, дороги и вода считаются как раньше, в сводке — «не узнан». Тест — задача 2 (обучение) и задача 4 (`combineLegends` без болот).
5. «Убрать болота, которых нет на карте» на сплошном массиве болот (соседи в радиусе 3 — тоже болото), за рамкой `clip` и при выключенном флажке. Клетка не становится снова болотом или водой, за рамкой не меняется, без флажка изменений нет. Тест — задача 3.

**Interfaces — Produces:**
- `export interface HatchStats { ink: number; px: number; hRun: number; vRun: number; rows: number; w: number }` — `ink` — доля пикселей класса `ink` среди непрозрачных (`px`), при `px = 0` — 0; `hRun`/`vRun` — средняя длина серии по строкам/столбцам окна (0 без чернил); `rows` — строк окна с чернилами; `w` — сторона окна (нужна `isHatch` для `rows ≥ w/6`).
- `export const HATCH: { minInk: 0.03; maxInk: 0.4; aniso: 2; minRun: 3; rowsShare: number /* 1/6 */; minOpaque: 0.5; groundM: 120; minPx: 12; maxPx: 48 }`
- `export function hatchWindow(cls: Int8Array, size: number, x0: number, y0: number, w: number, ink: number): HatchStats` — `cls[i] === -2` — прозрачно (не в `px`).
- `export function isHatch(s: HatchStats, o?: { minInk?: number; maxInk?: number; aniso?: number }): boolean` — ложь при `px < minOpaque · w²`.
- `export function hatchPx(lat: number, z: number): number` — сторона окна: `round(120 / (156543.03 · cos(lat) / 2^z))`, зажато в 12…48.
- `export function hatchMask(cls: Int8Array, size: number, w: number, ink: number): Uint8Array` — 1 у каждого непрозрачного пикселя окна, прошедшего `isHatch`.
- `OverlayLegend` += `hatch?: string[]` — классы, считаемые по штриховке.
- `legendFromSamples(samples, tol = 1, mins = {}, hatch: string[] = [])` — `hatch` переносится в легенду (только классы, у которых есть образцы).
- `export function combineLegends(...ls: OverlayLegend[]): OverlayLegend` — `pixels` объединяются (ключ — у первой легенды, где он есть), `cells` — по классам без повторов, `hatch` — объединение; `id`/`name` — первой.
- `addTile`: для каждого класса `k` из `legend.hatch` — массив чернил (1 — пиксель подходит к правилам класса, независимо от `pixelClass`; −2 — прозрачно), `hatchMask(…, hatchPx(lat центра тайла, z), 1)`; в подсчёте клетки пиксель окна-болота прибавляется к `counts[k]` (один раз), пиксели класса `k` вне окон — нет; остальные классы считаются как прежде.
