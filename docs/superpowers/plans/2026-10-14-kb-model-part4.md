# База знаний ↔ моделирование, часть 4 — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** советник, посредник, штаб противника, Ставка и штабы агентной модели берут знания из одной базы: справка по роли (встроенная база, слой пользователя, закрепления, отбор по операции, смысловой поиск) с правилом «что может знать роль»; доктрина — формальные факты вида `doctrine` (сид из трёх сводов, извлечение, ручная правка); штабы получают правила своей стороны, подходящие к обстановке, и ссылаются на них (`basis`); видно, на чём решение.

**Architecture:** `packages/knowledge` — вид `doctrine` (`schema.ts`, `resolve.ts`, `checks.ts`, `extract.ts`), политика ролей и справка (`role-reference.ts`), отбор доктрины к обстановке (`doctrine.ts`: `doctrineFor`, `TRIGGER_GROUPS`, слова факта). Окно (`apps/editor/src/kb/kb.ts`) строит справку и доктрину по своей базе; поток игры (`game-worker.ts`) просит их сообщением `kbRef` и ждёт `kbRefResult` до 8 с, иначе считает по сиду (`apps/editor/src/sim/kb-ref.ts`). `services/staff` — триггеры обстановки (`live/triggers.ts`), нумерация справки и доктрины в одну последовательность `R1…` и разбор `basis` (`live/kb-blocks.ts`), новые слоты промпта штаба и блок доктрины Ставки. Ядро агентной модели (`crates/agents-core`) принимает текст доктрины из окна (`doctrine_text`) и подставляет его в промпт штаба на модели; числа доктрины ядра не меняются.

**Tech Stack:** TypeScript, vitest, React; Rust (`crates/agents-core`, `crates/agents-tauri`), тесты Rust — `npm run agents:test`.

**Spec:** `docs/superpowers/specs/2026-10-14-kb-model-part4-design.md`

## Global Constraints

- Язык интерфейса, описания, промптов, коммитов — русский; в описании нет дат и упоминаний ассистента-разработчика и веток.
- Пределы: доктрина в промпте — не больше 8 правил и 4000 знаков; справка штабу противника и Ставке — не больше 5 записей по 700 знаков; посреднику — как сейчас, не больше 8 записей по 900 знаков; ожидание справки от окна — `KB_REF_TIMEOUT_MS = 8000`. Это пределы промптов, не правила модели: в `norms.json` не вносятся.
- `fill()` (`services/staff/src/fill.ts`) падает на незаполненном и на неиспользованном слоте: шаблон `staff.live.md` и `buildSituation` меняются в одном шаге, оба новых слота заполняются всегда (без базы — «(правил нет)», «(справок нет)»).
- Без `doctrine_text` ядро агентной модели даёт ровно прежний текст промпта (байт в байт); числа доктрины ядра — по-прежнему из `agents-v0.json`.
- Схема решения штаба для проверки на контрольных обстановках (`DECISION_SCHEMA` без справки) не меняется: `basis` — только когда штабу дана справка или доктрина.
- `packages/sim` и `packages/knowledge` не зависят друг от друга; `services/staff` уже зависит от `@def-ops/knowledge` — новые типы (`RoleRef`, `DoctrineRule`, `DoctrineTrigger`) берутся оттуда.
- Тексты книг в репозиторий не попадают: записанный ответ модели для теста извлечения — на придуманном пересказе в духе наставления.
- По правилам репозитория: описание, снимки, `kb:seed`, `model:index`, `docs:system`, `docs:guide`; перед каждым коммитом `npm run typecheck` и `npm test`, после правки Rust — `npm run agents:test`.

## Review Focus

1. Значения правил в сводах доктрины разнородны: строки, `null`, логические, списки из 3–5 чисел, списки строк, словари по армиям (`breakthrough_km: { su_47a: 4.3, … }`, `coordination: { su_5ua: "su_2gta" }`). В факт идут только числа и пары чисел, словари чисел — плоскими ключами `ключ.подключ`; остальное отбрасывается без `NaN` и без падения сида. Тест — задача 1.
2. Закрепление `'none'` на ключе правила доктрины — правило не попадает в отбор совсем (не заменяется следующим по надёжности); закрепление на факт другой стороны или другого правила не действует. Тест — задача 3.
3. Штабу, Ставке и посреднику не должно доставаться будущее: запись с `period.from` позже момента хода и запись из документа операции с положениями, потерями, событиями не проходят фильтр роли, даже если категория разрешена. Тест — задача 3.
4. Окно ответило на `kbRef` после истечения 8 с или ответило ошибкой: запоздалый ответ игнорируется (обещание не разрешается второй раз, запрос убирается из ожидающих), ошибка — сразу запасной путь по сиду. Тест — задача 4.
5. Ссылки `basis` от модели в произвольном виде: `"[R1]"`, `"R 2"`, кириллическая `"Р3"`, повторы, `"R0"`, `"R12"` при 5 справках, слова без номера — остаются только существующие номера, по одному, в порядке первого упоминания. Тест — задача 5.

### Task 3: Справка по роли и доктрина к обстановке

**Files:**
- Create: `packages/knowledge/src/role-reference.ts`
- Modify: `packages/knowledge/src/doctrine.ts` (`doctrineFor`, триггеры), `packages/knowledge/src/index.ts`
- Test: `packages/knowledge/tests/role-reference.test.ts`, `packages/knowledge/tests/doctrine-for.test.ts`

**Interfaces:**
- Consumes: `gather` (`qa.ts`), `foreignTo` (`operations.ts`), `category` (`schema.ts`), `claimFacts`/`resolve`/`subjectOf` (`resolve.ts`), `stems` (`search.ts`), Task 1.
- Produces:
  - `type Role = 'advisor' | 'umpire' | 'staff' | 'stavka' | 'review'`; `interface RoleScope { role: Role; side?: 'su' | 'de'; operation?: string; moment?: string; history?: boolean }`; `interface RoleRef { id: string; title: string; text: string }`.
  - `roleFilter(scope: RoleScope): (e: Entry) => boolean`. Общее: не `group 'model'`, не `sources`, не `foreignTo(e, scope.operation)`. `advisor`: `history` — любая категория, иначе только `gameSafe`. `review`: любая категория. `staff`/`stavka`/`umpire`: только `organization`, `equipment`, `terrain`; не запись `origin 'document'`, у которой есть факт с `claim.kind` не из `param`/`doctrine`; не запись с `period.from` позже `scope.moment`.
  - `roleReference(index: Index, byId: Map<string, Entry>, queries: string[], scope: RoleScope, o: { limit: number; chars: number; hits?: (Hit[] | undefined)[] }): { refs: RoleRef[]; text: string }` — по каждому запросу `gather` (пул 400, `hits[i]` — готовая выдача, фильтр `!!e && roleFilter(scope)(e)`), без повторов записей, всего ≤ `limit`; `text` записи режется до `chars`; при `scope.side` у записи `organization` группы `su`/`de` к заголовку — « — своя сторона» / « — противник»; `text` справки — `[R1] заголовок\nтекст`, через пустую строку; нет записей — `refs []`, `text ''`.
  - `type DoctrineTrigger = 'encircled' | 'penetration' | 'pressure' | 'attack' | 'reserves'`; `TRIGGER_GROUPS: Record<DoctrineTrigger, Record<'su' | 'de', string[]>>` = `encircled { de: ['withdrawal', 'counterattack'], su: ['bypass'] }`, `penetration { de: ['counterattack', 'reserves'], su: ['reserve', 'stop'] }`, `pressure { de: ['withdrawal', 'layout'], su: ['stop', 'regroup'] }`, `attack { de: ['counterattack'], su: ['echelons', 'commit', 'tempo', 'depth'] }`, `reserves { de: ['reserves'], su: ['reserve', 'commit'] }`; без триггеров — `DEFAULT_GROUPS = { de: ['layout'], su: ['frontage', 'echelons'] }`.
  - `interface DoctrineRule { entry: string; index: number; key: string; claim: DoctrineClaim; reliability?: Reliability; title: string; line: string }` (`title` — заголовок записи, `line` — `doctrineWords` и « [A]» при надёжности).
