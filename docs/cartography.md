# Картография: карты-подложки в закрытом контуре

Сервис `services/cartography` (порт 8104, через шлюз — `/api/cartography/...`)
хранит карты-подложки **у себя**, чтобы платформа работала в локальном контуре
без интернета. Карта — тайловая пирамида XYZ (Web Mercator) на диске сервиса;
редактор показывает её как растровый источник MapLibre.

Откуда берутся карты:

1. **Загрузка тайлов внешнего сервиса**, пока он доступен (например,
   отсканированные исторические планы Берлина): тайлы прямоугольника на
   нужных уровнях скачиваются и складываются на диск как есть.
2. **Нарезка привязанного растра**: скан карты + опорные точки (или четыре
   угла) → пирамида тайлов.
3. **Пакет из другой установки**: архив `.tar` с описанием карты и тайлами —
   так карты переносят в закрытую сеть.

У карты может быть **граница** (`coverage`) — контур, за которым тайлы
прозрачны: обрезать поля и легенду скана или ограничить подложку районом.

Математика (масштаб, тайловая сетка, привязка по точкам) — общая, в
`packages/core/src/cartography.ts`; сервис её не дублирует.

## Хранение

| Что | Где |
|---|---|
| описания карт и задания | PostgreSQL, схема `cartography` (`STORAGE=postgres`, по умолчанию при `DATABASE_URL`) или память (`STORAGE=memory`) |
| охват и граница карты | ещё и геометрией PostGIS (`maps.bounds`, `maps.coverage`) — для будущих запросов «какие карты есть на район» |
| тайлы | `TILES_DIR/{организация}/{карта}/{z}/{x}/{y}.{png,jpg,webp}` (по умолчанию `./data/tiles`, в Docker — том `tiles-data`) |
| тайлы, обрезанные по границе (кэш) | `TILES_DIR/{организация}/{карта}/_masked/{ключ границы}/…` |
| загруженный скан до нарезки | `TILES_DIR/.uploads` (удаляется после задания) |

Запись тайлов атомарная (временный файл + переименование). Объём пирамиды
(`stats: { tiles, bytes }`) пересчитывается по окончании каждого задания.
Данные организаций разделены во всём: чужая карта, тайл, задание, событие — 404
или не видны.

## Карта (`MapSource`)

```jsonc
{
  "id": "…", "name": "План Берлина 1945", "description": "…",
  "attribution": "etomesto.ru",           // подпись источника — показывать на карте
  "date": "1945",                          // состояние местности
  "kind": "xyz | raster | package",        // как получена
  "format": "png | jpg | webp", "tileSize": 256,
  "minzoom": 10, "maxzoom": 16,
  "bounds": [13.2, 52.4, 13.6, 52.6],      // запад, юг, восток, север
  "coverage": [[13.3, 52.45], …] | null,   // граница (кольцо ≥ 3 точек)
  "opacity": 1,
  "sourceUrl": "https://…/{z}/{x}/{y}.png",// для XYZ — откуда загружено
  "controlPoints": [ … ], "georef": { "kind", "width", "height", "rmsMeters", "residuals", "nativeZoom" },
  "stats": { "tiles": 1234, "bytes": 5678901 }
}
```

`POST /cartography/maps` создаёт описание (обязательно только `name`).
`PATCH` меняет `name, description, attribution, date, coverage, opacity,
bounds, minzoom, maxzoom`; остальное меняют только задания. `DELETE` удаляет
карту вместе с тайлами (выполняющиеся задания карты отменяются; история
заданий остаётся).

## Офлайн-сценарий

**В сети (там, где есть интернет):**

```bash
API=http://localhost:8080/api; KEY='X-Api-Key: ключ'
# 1. карта
ID=$(curl -s -H "$KEY" -H 'Content-Type: application/json' $API/cartography/maps \
  -d '{"name":"План Берлина 1945","attribution":"etomesto.ru","date":"1945"}' | jq -r .id)
# 2. загрузка тайлов района (шаблон адреса — из описания слоя на сайте-источнике)
curl -s -H "$KEY" -H 'Content-Type: application/json' $API/cartography/maps/$ID/import/xyz -d '{
  "url": "https://tiles.example.org/berlin1945/{z}/{x}/{y}.jpg",
  "bounds": [13.25, 52.45, 13.55, 52.58], "minzoom": 10, "maxzoom": 16,
  "headers": { "Referer": "https://tiles.example.org/" }, "rate": 2 }'
# 3. ход задания
curl -s -H "$KEY" "$API/cartography/jobs?mapId=$ID"
# 4. пакет для переноса
curl -s -H "$KEY" -o berlin-1945.tar $API/cartography/maps/$ID/package
```

**Перенос** архива `berlin-1945.tar` носителем в закрытый контур.

**В закрытом контуре:**

```bash
curl -s -H "$KEY" -H 'Content-Type: application/x-tar' --data-binary @berlin-1945.tar \
  $API/cartography/maps/import-package        # → 201 { map, job }
```

Пакет становится новой картой (новый `id`, `kind: "package"`); граница,
привязка, подпись и даты переносятся из `map.json`. Пакет читается потоком —
размер ограничен только `MAX_PACKAGE_MB` и диском. Неудачный импорт (не архив,
нет `map.json`, обрыв) не оставляет полузагруженной карты.

**Подключение в редакторе:** `GET /api/cartography/maps/{id}/tilejson`
(TileJSON 3.0) или `GET /api/cartography/maps/{id}/style` — минимальный стиль
MapLibre с одним растровым источником, **без шрифтов и спрайтов** (их негде
взять без интернета). Клиент: `api.cartography.tileUrl(map)`.

### Формат пакета

```
map.json                  — описание карты (MapSource), первым файлом
tiles/{z}/{x}/{y}.{ext}   — тайлы как хранятся (без обрезки по границе)
```

Обычный tar: можно собрать и проверить стандартными средствами
(`tar tf berlin-1945.tar | head`). Посторонние файлы при импорте пропускаются,
тайлы с неверным адресом или не-изображения отбрасываются (счётчик `errors`).

## Загрузка тайлов внешнего сервиса

`POST /cartography/maps/{id}/import/xyz`, тело — `XyzDownloadRequest`:

| Поле | |
|---|---|
| `url` | шаблон: `{z} {x} {y}`, `{-y}` (TMS), `{s}` (поддомен), `{quadkey}`; только http(s) |
| `bounds`, `minzoom`, `maxzoom` | район и уровни (0…22) |
| `subdomains` | для `{s}`, по умолчанию `a, b, c` |
| `headers` | только `Referer`, `Accept`, `Accept-Language`, `Origin` |
| `rate` | запросов в секунду, по умолчанию 4, не больше 20 |

- Число тайлов считается заранее; больше `MAX_TILES_PER_JOB` (50 000) —
  **422** `too_many_tiles` с полями `tiles` (сколько получилось) и `limit`.
- Не больше 3 одновременных запросов (`XYZ_CONCURRENCY`), повтор при сбое сети,
  429 и 5xx — до 3 раз с удвоением паузы (учитывается `Retry-After`).
- `User-Agent: def-ops-cartography/0.2 (+offline archive)`.
- **Продолжение:** тайлы, уже лежащие на диске, не запрашиваются. Прерванную
  (или отменённую) загрузку можно запустить тем же запросом.
- 404/410/204 — тайла на источнике нет: `skipped`. Прочие ошибки — `errors`
  (задание завершается `failed`, если не загружено ни одного тайла).
- Формат определяется по сигнатуре (PNG/JPEG/WebP), а не по `Content-Type`;
  тайл сохраняется как получен. Не-изображение (страница ошибки) — ошибка.
- Пустой карте задание присваивает охват, уровни и формат запроса; у карты с
  тайлами они расширяются.
- `XYZ_ALLOWED_HOSTS` — список разрешённых хостов источников (через запятую);
  пусто — любые.

## Нарезка скана (привязка растра)

**Одним запросом:** тело — само изображение, привязка — параметр `georef`
(URL-кодированный JSON `RasterTileRequest`):

```bash
curl -s -H "$KEY" -H 'Content-Type: image/jpeg' --data-binary @plan.jpg \
  "$API/cartography/maps/$ID/import/raster?georef=$(jq -rn --argjson g '{
     "controlPoints": [
       {"px": 412,  "py": 388,  "lngLat": [13.3777, 52.5163]},
       {"px": 5120, "py": 610,  "lngLat": [13.4545, 52.5194]},
       {"px": 4980, "py": 4410, "lngLat": [13.4510, 52.4880]},
       {"px": 530,  "py": 4302, "lngLat": [13.3790, 52.4870]}
     ]}' '$g|@uri')"
```

- Тело: `image/png`, `image/jpeg`, `image/webp`, `image/tiff`, до
  `MAX_UPLOAD_MB` (200 МБ). Пиксели — как изображение видно (с учётом поворота
  EXIF), `(0, 0)` — левый верхний угол, `(ширина, высота)` — правый нижний.
- Привязка — **опорные точки** `controlPoints` (≥ 3 для `affine`, ≥ 4 для
  `projective`; по умолчанию при ≥ 4 точках — `projective`) или **углы**
  `corners` (левый верхний, правый верхний, правый нижний, левый нижний).
  Лишние точки уравниваются по методу наименьших квадратов.
- **Ответ 202 сразу**: задание и итог привязки — `georef.rmsMeters` и невязка
  каждой точки `georef.residuals` (м), чтобы увидеть грубую ошибку до нарезки.
  Те же данные потом — в `job.result.georef` и в карте (`georef`, `controlPoints`).
- Уровни: `maxzoom` по умолчанию — `nativeZoom` (пиксель скана ≈ пикселю тайла);
  `minzoom` по умолчанию — уровень, где скан занимает около одного тайла. Если
  `maxzoom` задан ниже родного, скан сначала уменьшается.
- Пересчёт: для каждого пикселя тайла верхнего уровня — обратное преобразование
  в пиксель скана, билинейная интерполяция; вне скана — прозрачно. Нижние уровни
  собираются из четырёх дочерних тайлов. Полностью прозрачные тайлы не хранятся.
- Тайлы — PNG (или WebP, если формат карты `webp`): нужна прозрачность.
- Большие сканы: если декодированный скан больше `RASTER_MEMORY_MB` (256 МБ
  RGBA ≈ 8000×8000), он раскладывается во временный файл, и на каждый тайл
  читается только нужная полоса; в памяти — одна полоса и один тайл.
- Повторная нарезка (перепривязка) заменяет все тайлы карты.

## Граница карты (`coverage`)

Контур `[[долгота, широта], …]` (≥ 3 точки, замыкать не обязательно). Пирамида
на диске не меняется; при раздаче:

| Тайл | Ответ |
|---|---|
| целиком внутри | как хранится |
| целиком снаружи | прозрачный PNG |
| пересекает границу | PNG с прозрачностью за контуром; строится один раз и кэшируется на диске |

Кэш обрезанных тайлов удаляется при смене границы (и после каждого задания,
меняющего тайлы); ключ кэша — хеш контура, поэтому старые тайлы не отдаются
даже в момент смены. Граница задаётся в `PATCH /cartography/maps/{id}`.

## Раздача тайлов

`GET /cartography/maps/{id}/tiles/{z}/{x}/{y}.{ext}`

- **Нет тайла — 204 No Content** (MapLibre рисует пустое место без ошибки;
  кэш 60 с). Решено так, а не прозрачным тайлом: не тратится трафик, и видно,
  что тайла нет. Прозрачный PNG отдаётся только за границей карты.
- `Content-Type` — по фактическому формату; расширение в адресе не важно
  (обрезанный по границе тайл JPEG-карты придёт как PNG).
- `ETag` + `If-None-Match` → 304. `Cache-Control`: с параметром `?v=` (версия
  карты, его ставят TileJSON, стиль и клиент) — год, `immutable`; без него — час.
  Версия меняется с каждым изменением карты, так что после перенарезки или смены
  границы клиент сразу видит новое.
- **Адрес тайлов в TileJSON/стиле** — путь от корня сайта:
  `{X-Forwarded-Prefix}/cartography/maps/{id}/tiles/{z}/{x}/{y}.png?v=…`.
  Шлюз передаёт `X-Forwarded-Prefix: /api` (он снимает `/api` с
  `/api/cartography`), поэтому через шлюз получается `/api/cartography/…`, при
  прямом обращении к сервису — `/cartography/…`. Редактор открыт с того же
  адреса, что и шлюз, поэтому путь от корня работает без знания имени хоста.
- При `AUTH=keys` запросы тайлов MapLibre должны нести ключ: заголовок через
  `transformRequest` или `?api_key=` (`api.cartography.tileUrl(map, { withKey: true })`).

## Задания и события

`GET /cartography/jobs?mapId=`, `GET /cartography/jobs/{id}`,
`POST /cartography/jobs/{id}/cancel` (202; уже завершённое — 409).

`MapJob`: `status` (`queued → running → done | failed | cancelled`), `done` из
`total` (обработано тайлов, включая пропущенные и ошибки), `skipped`, `errors`,
`message`, `result`.

Задания выполняются внутри процесса сервиса: у каждой организации своя очередь,
задания одной организации — по одному. Импорт пакета идёт сразу, вместе с
загрузкой архива (ответ — после окончания). После перезапуска сервиса
незавершённые задания помечаются `failed` — загрузку XYZ можно просто повторить.

События (SSE) `GET /cartography/events[?mapId=]`: `map.created`, `map.updated`,
`map.deleted`, `job.progress` (не чаще раза в 0,5 с), `job.done`, `job.failed`
(также для отменённых — смотрите `job.status`).

## Масштаб

`GET /cartography/scale?lat=52.5&zoom=12&tileSize=512[&maxPx=120]` →
`{ metersPerPixel, denominator, label: "1:41 500", bar: { meters, px, label, ticks } }` —
тонкая обёртка над ядром для систем, которым нужен численный масштаб и линейка.

## Уважение к источникам

Загрузка тайлов — это копирование чужой работы. Перед загрузкой:

- **Проверьте условия использования** сайта-источника: разрешено ли
  сохранение и офлайн-использование, для каких целей, нужна ли договорённость
  с владельцем. Сканы старых карт часто свободны, а их оцифровка и
  тайлы — нет. Если условия запрещают — не загружайте, свяжитесь с
  владельцем.
- **Не нагружайте сервис:** берите только нужный район и уровни, частоту
  оставляйте по умолчанию (4 запроса/с) или ниже для небольших сайтов;
  не запускайте параллельно несколько загрузок с одного источника. Предел
  `MAX_TILES_PER_JOB` защищает от случайной выкачки «всего мира».
- **Не обходите ограничения:** сервис представляется честным `User-Agent`;
  подменять его, обходить ограничения частоты или авторизацию нельзя.
  `Referer` передавайте только если источник требует его для обычного показа.
- **Сохраняйте подпись:** заполняйте `attribution` (сайт, архив, издание) и
  `date` — они переносятся в пакет, TileJSON и стиль и должны быть видны на
  карте.
- **Повторная загрузка** докачивает только недостающее — не удаляйте карту,
  чтобы «обновить» её.
