# Переигровка операций: запуск у себя

Как запустить симуляцию на своём компьютере, посмотреть ход операции на карте и
сравнить его с историей. Всё работает локально, интернет нужен только для `npm install`.

## Что нужно

- Node.js 22 или новее (`node -v`), npm;
- репозиторий на ветке `claude/tactical-map-step1`;
- для «немецкого штаба» (необязательно) — LM Studio с загруженной моделью (см. ниже).

Docker, Python и исходные данные местности не нужны: карты местности (`packages/sim/data/theatres/*.json`)
и сценарии уже собраны и лежат в репозитории.

## 1. Установка

```bash
git checkout claude/tactical-map-step1
git pull
npm install
```

## 2. Переигровка в приложении (проще всего)

```bash
npm run dev            # http://localhost:5173/
```

Слева — колонка разделов: **Редактор**, **Переигровка**, **Карты** (подложки), **Знаки**
(справочник), **Штаб** (связь с моделью, которая командует противником в игре). Откройте **Переигровку**:

1. Выберите сценарий — Берлинская операция, бой в Берлине или контрольная Висло-Одерская.
2. **Правила** — откалиброванные (по умолчанию) или исходные, до калибровки: так видно, что дала калибровка.
3. **Seed** — номер случайного прогона (один seed — один и тот же расчёт); **Прогонов** — сколько
   прогонов с разными seed посчитать, чтобы увидеть разброс.
4. **«Рассчитать»** — расчёт идёт прямо в браузере (5–30 с, сервер не нужен). Справа — карта с
   плеером времени, кнопки слоёв «История», «Фронт», «Бои», «Рубежи» и выбор подложки. Слева — доля
   положений в допуске, сколько событий совпало с историей и расхождение в сутках по каждому прогону
   (зелёный — ±1, жёлтый — ±2, красный — больше, «—» — не случилось).
5. **«Отчёт»** — полный отчёт о сравнении с историей (можно скачать); **«В редактор →»** — открыть
   результат в редакторе для правки, экспорта и сохранения на сервер.

## 3. Прогон всех сценариев одной командой (терминал)

```bash
npm run sim:demo
```

Около минуты. Три сценария, по 5 прогонов каждый (разные случайные числа — видно, насколько результат устойчив):

| Сценарий | Что это | Чем проверяется |
|---|---|---|
| `berlin-1945-tasks` | Берлинская операция 16.04–2.05.1945: армии и корпуса, на Зееловских высотах — дивизии | 10 ключевых событий (прорыв к Мюнхебергу, котёл 9-й армии, кольцо у Кетцина, Торгау, Штеттин, Рейхстаг…) и ~220 исторических положений |
| `berlin-city-1945` | Бой в Берлине 24.04–2.05: корпуса и гарнизоны секторов, клетка 250 м | Темпельхоф, Александерплац, мост Мольтке, Рейхстаг, Рейхсканцелярия; положения ±2 км |
| `vistula-oder-1945` | Висло-Одерская операция 12.01–3.02.1945 — **контрольная**: правила Берлинской операции без подгонки | 13 событий и ~150 положений |

Обе стороны получают **исторические задачи** (наступать на…, держаться, отходить), а не
исторические положения: темпы, окружения и исходы боёв считает арбитр. В конце — сводка:
доля положений в допуске и сколько событий совпало с историей в пределах двух суток.

Варианты:

```bash
npm run sim:demo -- --only berlin          # только Берлинская операция (city, vistula — другие)
npm run sim:demo -- --runs 1               # быстрее: по одному прогону
```

Результаты — в `evals-out/demo/<сценарий>/`:

- `report.md` — сравнение с историей: события (история / расчёт), отклонения по дням и
  формированиям, наибольшие расхождения, журнал боёв с факторами (соотношение сил,
  местность, укрепления, подготовленная оборона, случайность);
- `map.json` — карта для редактора.

## 4. Посмотреть на карте

```bash
npm run dev            # редактор: http://localhost:5173/
```

В редакторе — **«Открыть / импорт…»** → `evals-out/demo/berlin-1945-tasks/map.json`.

- ползунок времени внизу — ход операции (знаки двигаются, на каждом — состояние:
  «наступает», «обороняется», «ОТРЕЗАНО», боеприпасы);
- слои: расчёт (знаки, линия фронта, стрелки боёв) и история (бледные «призраки» на
  исторических местах, исторические линии фронта) — их можно включать и выключать в
  панели слоёв, чтобы сравнивать;
- линия фронта расчёта — граница территорий сторон: территория переходит к стороне
  только там, где прошли её войска.
- когда в расчёте взят Рейхстаг (в радиусе 1 км нет противника), над ним появляется
  **Знамя Победы** (слой «особые отметки»); бледное знамя в слое истории — историческое
  время, 30.04, 22:40.

С платформой целиком (хранение карт на сервере):

```bash
./scripts/start-local.sh                                  # http://localhost:8080/ (нужен Docker)
npm run sim:demo -- --publish http://localhost:8080       # карты сразу сохраняются на сервер
```

## 5. Отдельные команды

```bash
# один сценарий, свои параметры
npm run sim:history -- --scenario berlin-1945-tasks --runs 5 --out evals-out/my-run
#   --rules ww2-berlin-cal   правила (по умолчанию — указанные в сценарии)
#   --seed 3                 случайные числа
#   --tolerance 10           допуск, км

# пересобрать сценарий после правки рецепта (задачи, численность, события)
npm run sim:scenario -- packages/sim/data/scenarios/src/berlin-1945-tasks.recipe.json

# перекалибровать правила по Берлинской операции (~12 минут)
npm run sim:calibrate -- --evals 200 --seeds 2

npm test                # тесты
```

Где что лежит:

| Путь | Что |
|---|---|
| `packages/sim/data/scenarios/src/*.recipe.json` | рецепты сценариев: соединения, численность, **исторические задачи** с источниками, события для проверки, источники подвоза |
| `packages/sim/data/rules/` | правила арбитра: `ww2-draft` — исходные, `ww2-berlin-cal` — откалиброванные (с блоком `calibration`: на чём и как подобраны) |
| `packages/sim/data/profiles/` | профили сторон: РККА-1945, вермахт-1945 (типы частей, скорости, полосы обороны, снабжение, задержка доведения приказов) |
| `packages/sim/data/theatres/` | карты местности: покров, реки, дороги, мосты и переправы, оборонительные полосы |
| `docs/sources/` | исторические данные с источниками и достоверностью (A/B/C) |

## 6. Игра: вы — советская сторона, модель — немецкая

С любого момента переигровки командование можно взять на себя и вести операцию до конца.

1. **LM Studio** → загрузить модель (сейчас — Qwen3.8 27B 4-bit) → вкладка Developer → **Start Server**
   (по умолчанию `http://localhost:1234/v1`). Длина контекста — не меньше 16 000 токенов.
2. `npm run dev`, раздел **Штаб** → «Проверить связь»: должна появиться модель. Там же — выбор модели и
   режим размышления. Без размышления решение занимает 1–2 минуты, с ним — в разы дольше.
3. **Переигровка** → «Рассчитать» → ползунком выбрать момент → кнопка **«Принять командование»** на карте.
   Командование передаётся с начала хода (в Берлинской операции ход — сутки, в бою в городе — 12 ч).

С этого момента — **без конечной даты**: игра идёт до победы или поражения.

- **Победа** — Знамя Победы над рейхстагом (событие «Рейхстаг взят»: в радиусе 1 км нет противника); на карте
  появляется знамя, время и карта переходят к нему. В контрольной Висло-Одерской — выход к Одеру у Кинитца.
- **Поражение** — войска потеряли боеспособность (в строю меньше 35 % численности на момент принятия
  командования) или вышел предельный срок: Берлин не взят к 15 мая (бой в городе — к 10 мая).
  Условия — `packages/sim/data/scenarios/catalog.json`, поле `game`.

Кроме того:

- **советской стороной командуете вы.** Вернуть командование историческому плану нельзя. Исторические
  приказы после этого момента отменяются; приказы, отданные раньше и ещё не дошедшие до войск, остаются в силе;
- **немецкой стороной командует штаб на модели.** Он вступает в игру одновременно с вами. На каждом ходу
  ему уходит своя обстановка: доклады своих соединений, противник в пределах разведки, итоги суток,
  пункты вблизи войск, ограничения сверху (приказы фюрера). Обе стороны решают одновременно — модель
  думает, пока вы пишете приказы;
- **противник виден только в пределах разведки** (туман войны): около 24 км от ваших войск в операции,
  6 км в городе.

Вся штабная работа советской стороны — на вас. Что до передачи командования шло по историческому
графику, дальше — только по вашим распоряжениям: исторические приказы, наводка переправ и ввод резервов
Ставки после этого момента сняты, тыл переходит под ваше управление.

| Вкладка | Что там |
|---|---|
| Доклады | оперативная сводка на утро: объединения в строю, укомплектованность, отрезанные; донесения за ход; достигнутые контрольные рубежи; доклады объединений по фронтам — положение, задача (историческая или ваша), состав, боеприпасы, горючее, усталость, бои за ход, приказы в пути |
| Разведка | разведсводка: обнаруженные соединения противника, где, что делают, оценка сил (округлённо), расстояние до наших; «новое» — обнаружено за последний ход |
| Решение | решение на ход — те же части, что у штаба противника: **оценка обстановки**, замысел противника, **решение (замысел действий)**, риски, **боевое донесение в Ставку**. Без выделенных полей ход не проводится. Замысел и риски переносятся с прошлого хода для правки; для донесения есть черновик по докладам |
| Приказы → Войска | боевое распоряжение: объединение (из списка или щелчком по знаку на карте) → задача → цель: пункт, соединение противника или точка на карте → указания. Видно, когда приказ дойдёт до войск (армиям — 6 ч). Проект приказов рисуется на карте стрелками (слой «Замысел») |
| Приказы → Тыл | базы снабжения: перенос вперёд (на время переноса база не действует: сутки на развёртывание и переезд ~60 км/сут; на чужой территории не работает); приоритет подвоза — не более трети объединений, им ×1,5, остальным ×0,75; время подвоза до каждой армии против предела (48 ч) |
| Приказы → Переправы | наводка переправ: щелчок по реке (слой «Реки»), большая река — сутки, малая — 12 ч, рядом должны быть наши войска, понтонных парков — 3. Без переправы техника большую реку не пройдёт, подвоз — тоже |
| Приказы → Резервы | резервы Ставки (например, 28-я армия): ввод по вашему решению — район сосредоточения на своей территории; армия будет там не раньше готовности и не раньше чем через сутки |
| Журнал | журнал боевых действий по ходам: ваше решение, приказы, распоряжения (и что не исполнено — с причиной), донесения; скачивается в .md |
| Советник (кнопка у даты) | ИИ-советник. Темы — дерево: категория (обстановка, противник, решение, тыл и подвоз, переправы, резервы, правила арбитра, история) → раздел → вопросы; разделы «По фронтам», «По армиям», «Задача армии», «По соединениям» противника, «По резервам» собираются из текущей обстановки; поиск по всем вопросам; можно спросить своими словами. Видит то же, что вы (туман войны), ваш проект решения и точные правила арбитра (из чисел правил, не по памяти). Может предложить приказы — кнопка «В распоряжение» включает их в боевое распоряжение; предлагает следующие вопросы |
| Посредник | решения штаба противника: оценка обстановки, замысел, приказы (что исполнено, что отброшено и почему), доклады наверх, риски; ход размышления в реальном времени; снять туман войны. Если играете честно — смотрите после игры |

Немецкой стороне тыл, переправы и резервы пока идут по историческому графику: модель отдаёт только
приказы войскам.

**Советник — без выдумок и без скрытых сведений.** Спросить можно о чём угодно, но советник знает только
то, что знает штаб игрока: доклады, разведсводку (туман войны), итоги суток, тыл, проект решения, правила
арбитра. Решений штаба противника, его положения и сил вне разведки, сведений посредника в его данных нет.
Исторические знания модели он обязан помечать «в истории…» и не выдавать за обстановку в игре; на просьбы
«представь себя немецким штабом» или «отключи правила» — отказывает. Каждый ответ помечен: на что опирается
(доклады, разведка, правила, история, общие знания) и чего штаб не знает. Ответ проверяется программно: если
в нём названы соединения противника, которых нет в разведсводке (кроме вопросов истории и тех, что назвал
сам игрок), модель просят переписать ответ; не переписала — под ответом предупреждение «это не данные
разведки».

**Варианты решения на ход.** Вверху панели советника — «Варианты решения на ход» (1–3 варианта; то же —
кнопка «Варианты от советника» во вкладке «Решение»). Советник с той же обстановкой и правилами готовит
полные, заметно разные варианты (например, решительный, осторожный, манёвренный): оценка обстановки,
замысел противника, решение, риски, боевое донесение, приказы войскам и распоряжения по тылу, переправам
и резервам. Карточки появляются по мере того, как модель их дописывает. «Принять вариант» заменяет проект
целиком (решение, приказы, распоряжения — с той же проверкой исполнимости, что и вручную) и открывает
вкладку «Решение»: дальше всё правится как обычно. «Только решение» берёт тексты без приказов; отдельный
приказ или распоряжение — кнопкой «взять» в раскрытой карточке. Несопоставленное с обстановкой
показывается с причиной и не принимается. После смены хода варианты помечаются устаревшими. Для демонстрации
удобно: один щелчок — готовый проект хода, который можно показать, поправить и провести.

**Свободный текст и арбитр.** Арбитр текст не читает: он исполняет только приказы и распоряжения в
строгой форме — объединение, задача из списка, цель (пункт, соединение противника или точка), место
переправы, базы, района. Свободный текст — вопросы советнику и «указания» в приказе — идёт в журнал и
советнику. Предложения советника и приказы штаба модели сопоставляются со списками обстановки; что не
опознано, не исполняется и помечается («не может быть исполнен» у советника, причина — у посредника),
а не угадывается молча. Пункт ищется сначала среди пунктов обстановки (ближних к войскам), затем среди
всех пунктов театра — по русскому и исходному названию («Курфюрстендамм» и «Kurfuerstendamm» — один пункт). Предложения советника исполняются только после нажатия «В распоряжение».

**«Провести сутки»** утверждает решение, отдаёт приказы и распоряжения обеих сторон и считает ход. Если модель не ответила, ход ждёт:
можно повторить запрос или провести ход без новых приказов противника. Игра сохраняется в браузере после
каждого хода. Её можно продолжить с карточки «Незавершённая игра» в Переигровке или скачать запись
(меню «⋯»). По записи игра восстанавливается целиком: движок детерминирован.

Без LM Studio стенд можно проверить на **подставной модели** — её решения простые, только для проверки
интерфейса:

```bash
npm run llm:mock        # в отдельном терминале: отвечает на http://localhost:1234/v1, как LM Studio
```

Или при взятии командования выбрать «Без штаба» — противник держится прежних приказов.

Проверка модели на контрольных обстановках (без игры):

```bash
npm run llm:quick                       # одна обстановка, приказы печатаются по мере готовности
npm run llm:quick -- --only 04 --full   # другая обстановка и полный доклад с размышлением
npm run llm:eval                        # все контрольные обстановки и отчёт
```

Настройки — переменные окружения: `DEFOPS_LLM_URL` (куда сервер разработки направляет `/llm`),
`DEFOPS_LLM_MODEL`, `DEFOPS_LLM_THINKING` (`off` / `low` / `medium` / `xhigh`), `DEFOPS_LLM_TIMEOUT_S`.
В собранном приложении (без `npm run dev`) в разделе «ИИ» укажите адрес `http://localhost:1234/v1`
и включите в LM Studio CORS (Developer → Settings → Enable CORS).

**Разбор операции.** По окончании игры (кнопка «Разбор операции») или в любой момент (меню «⋯» → «Разбор операции»)
модель пишет отчётный документ по записи игры — разделами от лица экспертов: замысел и ведение операции
(командующий), разведка и оценка противника (сравнение вашего «замысла противника» с действительными решениями
немецкого штаба), тыл и снабжение, переправы, управление и штабная культура, резервы (представитель Ставки),
сравнение с историей и итог с оценкой по пятибалльной шкале и уроками. Разделы пишутся по очереди, текст виден
по мере написания, любой можно переписать; модель и размышление выбираются в окне разбора. Готовый документ —
«Скачать PDF» (окно печати → «Сохранить как PDF»: титульный лист, ключевые события, разделы) или .md; разбор
сохраняется в браузере для этой игры.

**Участки.** Кнопка «Участки» на карте (и в переигровке, и в игре): ключевые районы операции — Зееловские
высоты, Франкфурт, Нейсе, Шпрее, котёл у Хальбе, Цоссен, обход Берлина с севера, Берлин, кольцо у Кетцина,
Эльба, нижний Одер, Гёрлиц (бой в городе — Цитадель, Тиргартен, Александерплац…; Висла — Одер — плацдармы,
Варшава, Познань, Силезия) — или свой, выделенный двумя щелчками по карте. Карта приближается к участку и
обводит его; подложка подбирается сама: локальная карта, покрывающая участок, ближе по году к операции и
крупнее масштабом (историческая), иначе — из интернета (город — OpenStreetMap, местность — топографическая);
отключается там же. В игре доклады, разведка и приказы показываются только по участку (переключатель), у
советника появляется категория вопросов «Участок». Участки сценария —
`packages/sim/data/scenarios/src/<сценарий>.sectors.json` (пункты театра и запас, км), сборка — `npm run sim:sectors`.

На телефоне экран командования переключается: «Штаб», «Карта», «Советник» (на весь экран).

## 7. Знания: база по операциям — для обучения и для модели

Раздел «Знания» (значок книги слева). База собрана из `docs/sources` и описания модели — около 1440 записей.

**Рубрикатор** — нумерованное дерево тем (`packages/knowledge/src/rubrics.ts`): 1 Операции и сражения (1.1 Висло-Одерская,
1.2 Берлинская → 1.2.1 подготовка … 1.2.6 штурм Берлина, 1.2.7 итоги), 2 Войска сторон (по сторонам и ступеням),
3 Военное искусство (оперативное, тактика — наступление, оборона, бой в городе, форсирование…; рода войск; нормативы
и опыт), 4 Вооружение и техника, 5 Тыл и обеспечение, 6 Театр военных действий, 7 Управление, 8 Хронология,
9 Источники и историография. Запись может стоять в нескольких рубриках (бой за рейхстаг — 1.2.6 и 3.2.3); у рубрики
видно число записей, пустые рубрики — что стоит дополнить документами. Модель при разборе документа назначает рубрики.

**Типы записей** (что это за запись) — фильтр внутри рубрики; у каждого типа свой набор полей:

| Категория | Что в ней | Подгруппы |
|---|---|---|
| Операции | замысел, силы сторон, ход, итоги | стратегические, фронтовые |
| Сражения и бои | место, участники, ход, исход, потери | прорыв обороны, котлы, бои в городе, форсирование… |
| Формирования | подчинённость, состав, численность, командиры, путь | фронты, армии, корпуса, дивизии… |
| Командование | звание, должность, решения в операции | по сторонам |
| Организация и доктрина | тактика, нормативы (темпы, плотности, тыл, переправы) | Красная армия, вермахт, как устроено в модели |
| Вооружение и техника | назначение и характеристики | танки и САУ, артиллерия, пехотное оружие, авиация |
| Театр | реки, высоты, города, рубежи обороны | |
| Хронология | события по дням | |
| Источники | книги и статьи, достоверность | книги, интернет |

**Материалы.** Слева — рубрикатор и поиск (по основам слов, по-русски); в середине — карточка: описание,
таблица фактов с источником и достоверностью (A — документ/надёжный, B — вторичный, C — оценка), цитаты,
«Нет сведений» — каких полей каркаса не хватает, связи и «Упоминается в». Карточку можно поправить и отметить
«проверено». Справа — **строка обращения к модели**: «Ответить на вопрос» или «Рассказать по теме» (связный
рассказ для обучения). Модель отвечает только по найденным материалам базы и ссылается на них `[1]`, `[2]` —
ссылка открывает карточку; чего в базе нет, так и говорит.

**Документы.** Вкладка «Документы»: загрузить PDF (с текстовым слоем), Word (.docx), HTML, txt, md с пометкой
достоверности. Текст сразу участвует в поиске и ответах. «Обработать моделью» — документ режется на части,
модель выписывает из каждой сведения по каркасу, каждый факт — с дословной цитатой; факты, чьей цитаты нет в
тексте, отбрасываются. Получаются предложения: «новая запись» или «дополнение» существующей — их принимают или
отклоняют (по одному или все). Обработку можно остановить и продолжить. Всё хранится в браузере (IndexedDB);
обмен с другим компьютером — «Выгрузить мои материалы» / «Загрузить выгрузку».

**Смысловой поиск (эмбеддинги).** Кроме поиска по словам (BM25) база ищет по смыслу — моделью эмбеддингов
**Qwen3-Embedding** (родная для Qwen: та же основа Qwen3, многоязычная, русский понимает; 32K контекста):

1. В LM Studio найдите «Qwen3 Embedding» и скачайте GGUF: **0.6B** (Q8_0, ~0,6 ГБ — быстро, места мало) или
   **4B** (точнее; 8B — лучшая в линейке, но тяжёлая рядом с основной моделью). В настройках модели тип —
   Embedding (старые версии LM Studio ошибочно показывали её как обычную LLM).
2. Загрузите её рядом с основной моделью — сервер отдаёт её по `/v1/embeddings`.
3. Раздел «Знания» → «Документы» → «Смысловой поиск»: модель подхватывается сама (или выберите), идёт
   самопроверка (перефразировка должна быть ближе постороннего текста — так ловятся неверно собранные GGUF с
   пулингом не last) и расчёт векторов всех записей и документов (один раз; кэш в браузере, пересчитываются
   только изменённые). Дальше поиск, ответы по базе и справка советнику — гибридные: выдачи по словам и по
   смыслу сливаются по рангам (RRF).

Подробности: запрос идёт с инструкцией `Instruct: … Query:` (по-английски — так модель обучалась), записи — без
неё; длина вектора (MRL) урезается на нашей стороне (LM Studio параметр `dimensions` не соблюдает), по
умолчанию 1024; нужно ли добавлять `<|endoftext|>`, решает самопроверка. Без модели эмбеддингов всё работает
по словам. Подставная модель (`npm run llm:mock`) отдаёт и эмбеддинги — для проверки стенда.

**В игре.** Советник получает справку из базы по теме вопроса: в обычных вопросах — только доктрину, нормативы
и технику (ход боёв и исторические позиции — нет: игра уже разошлась с историей и это не разведка); в вопросах
категории «История» — и операции, сражения, формирования с пометкой «история». В опоре ответа — «база знаний».

Пересобрать начальное наполнение после правки `docs/sources` или `packages/knowledge/data/curated/*.json`:

```bash
npm run kb:seed          # → packages/knowledge/data/seed.json
```

С подставной моделью (`npm run llm:mock`) можно проверить и ответы по базе, и обработку документов.

## 9. Посредник на модели — нюансы к боям по базе знаний

В игре: вкладка «Посредник» → «Посредник на модели». Перед каждым ходом модель смотрит на ожидаемые бои и по
справкам из базы знаний добавляет то, чего правила не учитывают (видимость, взаимодействие родов войск,
заграждения, качество обороны), — множители 0,8–1,25 с причиной и опорой. Они видны там же по ходам и в
журнале боя («посредник: …»), записываются в игру. Ход занимает на один запрос к модели больше.

Становится ли симуляция реалистичнее — проверяется так (модель — та же, что в LM Studio):

```bash
npm run llm:umpire                                   # Берлинская и Висло-Одерская: с посредником и без
npm run llm:umpire -- --scenario berlin-city-1945 --seeds 2 --thinking low
```

Отчёт — `evals-out/umpire/<дата>/report.md`: положения в допуске, события ±2 сут, средняя ошибка дат и
нормативы (как `sim:norms`) — без посредника и с ним, плюс все поправки с обоснованием. Посредник стоит
включать, если он улучшает сверку и нормативы, а контрольная Висло-Одерская не хуже. Подставная модель
(`npm run llm:mock`) отвечает и за посредника — только чтобы проверить, что всё работает; её поправки ничего
не значат.

## 10. Моделирование: модели, сравнение с историей, калибровка, новые операции

Раздел «Моделирование» в приложении. Всё считается в браузере пулом фоновых потоков (по числу ядер, до 8),
свои наборы правил и операции хранятся в браузере (IndexedDB) и сразу видны в «Переигровке».

| Вкладка | Что делает |
|---|---|
| Модели | Наборы правил арбитра (встроенные и свои) словами: бой, оборона, снабжение, движение — значение и что оно значит; откуда набор (калибровка: по какой операции, мерило до и после, множители), где используется. Профили сторон: вес сил, качество войск, марш, доведение приказов, подвоз, переправы. Языковые модели по ролям (штаб противника и посредник, советник, разбор, база знаний) — с выбором модели |
| Сравнение | До четырёх наборов правил на одной операции, N прогонов каждый: положения в допуске, медиана превышения, мерило калибровки (обучение / проверка / даты событий), график отклонения от истории по дням, даты ключевых событий против исторических, чем наборы различаются; отчёт .md |
| Настройка | Свой вариант поверх любого набора: множители (те же, что подбирает калибровка) и параметры (соприкосновение, разброс, подготовка обороны, окружение, реки, усталость, боеприпасы, горючее). Проверка «было — стало» на операции, сохранение своим набором — для одной операции или для всех |
| Калибровка | Подбор множителей по истории операции, как `npm run sim:calibrate`, но параллельно: 40 % вариантов — широкий поиск, остальное — уточнение вокруг лучшего. Мерило — отклонение положений до середины операции («обучение») + 3 × ошибка дат событий; вторая половина («проверка») в подборе не участвует и показывает подгонку. Итог — свой набор с блоком калибровки |
| Операции | Загрузка новой операции: файлы сценария, театра и истории (и по желанию — участков, настроек штаба модели, записи каталога, своих правил и профилей) или один файл-пакет; части узнаются по полям. Проверка ссылок (стороны, профили, правила, районы приказов и событий, формирования истории), настройка игры (победа — событие истории, поражение — потеря сил или срок, допуск, наборы правил) и штаба модели (какой стороной командует модель, роль, опорный пункт, ограничения, роль советника), контрольный прогон, «Подготовить к переигровке» |

Образец формата — встроенная операция одним файлом: «Операции» → «Образец формата» → «Скачать».
Театр (местность, дороги, реки по WorldCover и Natural Earth) собирается инструментом
`npm run sim:scenario` (см. `packages/sim/tools/scenario`); в браузере его не построить.

Общая часть калибровки, описаний и проверки пакетов — в движке (`packages/sim/src/calibrate.ts`,
`describe.ts`, `operation.ts`): консольная калибровка и раздел считают одно и то же мерило.

## 11. Карта: уровни, подписи, театры

**Уровни карты** (переигровка и игра): тактический — соединения и бои за ход; оперативный — объединения
(армии) в центре своих соединений, направления действий за сутки, рубежи обороны; стратегический — фронты и
группы армий, главные удары за двое суток. **Подписи** — кнопкой на карте: все на карте или только при
наведении; при наведении на знак, стрелку или линию — название и что с ним (численность, танки, что делает).

**Театры** («Карты» → «Театры»): местность (растр классов), дороги, железные дороги, реки, мосты и переправы,
районы, рубежи — то, на чём считает арбитр. Область — весь театр, текущий вид или выделенная на карте (два
угла) — и выгрузка по ней: каждый слой в GeoJSON (кнопка ↓ у слоя), все слои одним файлом, растр местности PNG
с файлом привязки .pgw и легендой, театр-фрагмент в формате движка, документ редактора. Новый театр по
области: «Рецепт» — заготовка для сборщика `packages/sim/tools/theatre/build_theatre.py` (ESA WorldCover,
Copernicus DEM, OpenStreetMap); готовый театр загружается сюда же и становится доступен своим операциям.

**Сборка нового театра на сервере** — кнопка «Собрать на сервере»: сервис картографии запускает сборщик в
отдельном процессе, в окне — ход сборки, готовый театр сохраняется в списке. Новые театры собираются без
справочника: большие реки — названные реки длиной в охвате не меньше `rivers.autoMajorKm`, районы — населённые
пункты OpenStreetMap (`areas.fromOsm`). Подготовка (один раз): `npm run theatre:setup` (Python 3 с numpy и
rasterio в `.venv`), затем `npm run dev:services`. Исходные данные кэшируются в `~/.cache/def-ops-theatre`
(`THEATRE_CACHE`); первый раз скачиваются тайлы WorldCover (до сотен МБ на 3°×3°). Свой Python — `THEATRE_PYTHON`,
выключить — `THEATRE_BUILD=off`.

**Что извлекать** — в панели перед сборкой: местность (WorldCover), рельеф — класс «высоты» (порог перепада, м)
и сетка абсолютных высот, реки (с порогом «большой» реки), дороги (какие классы), железные дороги, мосты,
районы (какие типы пунктов). Выключенные слои не скачиваются. В рецепте — поле `layers`.

**Рельеф по высотам.** Театр хранит сетку средних высот клетки (`heightGrid`, Copernicus DEM, шаг 5 м); на
вкладке «Театры» — слой «Рельеф: высоты» (отмывка), высота под курсором, выгрузка PNG/.pgw/CSV. Во всех трёх
встроенных театрах сетка уже есть; добавить её к своему театру без пересборки:
`npm run theatre:height -- <id театра>` (рецепт в `data/theatres/src`). В бою учитывается правило
«Превышение» (`rules.heightAdvantage {perM, bonus, max}`): оборона выше наступающих сильнее на `bonus` за каждые
`perM` м, не больше ±`max`. Во встроенных правилах оно выключено (калибровка — без него); включить и проверить
на истории — «Моделирование» → «Настройка», ползунок «Превышение».

## 12. Исторический слой и состояние инфраструктуры

**Исторический слой по карте** («Карты» → «Театры» → «Исторический слой по карте»). Подложите историческую
карту в «Карты» → «Подложки» (скан с привязкой по углам или точкам, тайловый архив .sqlitedb / .mbtiles, OziExplorer
.map), выберите её и нажмите «Показать подложкой». Как распознавать — готовая легенда (дорожная карта РККА
1:1 000 000, «План г. Берлин» 1945 г.) или **образцы цвета**: выберите класс (дороги, шоссе, вода, застройка, лес,
болото) и щёлкайте по нему на карте — по 2–5 образцов; порог (доля пикселей класса в клетке) и допуск цвета —
там же. «Распознать» сводит карту на сетку театра в фоновом потоке, на карте — клетки по классам. Применение:
дороги карты — в растр дорог театра, современные дороги в охвате карты — убрать (дороги или и шоссе), вода,
застройка, лес — поверх местности, послевоенная застройка — в открытую. «Сохранить театр» — новый театр
(`<id>-hist`), на него ссылаются свои операции; «Поправка JSON» — тот же результат для сборщика (рецепт,
`overlays`). Встроенный театр «Одер — Берлин» уже собран с дорогами карты РККА и планом Берлина 1945 г.

**Анализ дорог карты.** После распознавания — сравнение с дорогами театра в охвате карты: клеток с дорогой
на карте и в театре (≈ км), совпадает (и какая доля дорог театра есть на карте), только на карте (дороги того
времени, которых в театре нет, — добавятся), только в театре (послевоенные или не распознанные — уберутся или
останутся, по выбору), список дорог театра, которых на карте почти нет. Переключатель «классы / сравнение
дорог» показывает различия на карте: серое — совпадает, оранжевое — только на карте, синее — только в театре.
Мало совпадений — признак того, что распознаны не дороги (надписи, реки): поправьте образцы. Дороги растром
(по исторической карте) показываются в слое «Дороги и шоссе» театра.

**Пути движения.** Марш, продвижение в бою и отход идут путём, которым прошли бы войска: по дорогам и улицам
(по растру дорог театра, в том числе исторических), через мосты и переправы, в обход воды; не напрямик через
кварталы. В переигровке и в игре знак между ходами идёт **по линиям дорог и улиц** театра: путь расчёта
(по клеткам сетки) заменяется для показа кратчайшим путём по графу дорог (перекрёстки достраиваются из
пересечений линий), из квартала — к ближайшей улице. Где дороги есть только растром (исторические дороги
театра «Одер — Берлин»), знак идёт по клеткам с дорогой, сглаженно. В журнале у перемещения — путь расчёта. Продвижение в бою считается по длине пути, поэтому по смещению оно на извилистых улицах
меньше, чем напрямую.

**Разброс путей** (правило «Разброс выбора пути», `routeVariety`, по умолчанию 0,2). Путь выбирается не всегда
самый быстрый: у каждого формирования и приказа своё «как кажется выгоднее» — плавный шум районами в несколько
км; одни идут дорогой, другие лесом или полем напрямик. На время движения разброс не влияет (идут по
местности), меняется только выбор. Разный seed — разные пути, один seed — тот же расчёт. На карте вне города
путь показывается как в расчёте (полем — полем, лесом — лесом), по улицам — там, где войска и в расчёте шли
дорогами или городом. 0 — всегда самый быстрый путь («Моделирование» → «Настройка»).

**Состояние инфраструктуры операции** («Моделирование» → «Операции» → операция → «Материалы операции»; есть и у
операций стенда). Загрузите документы (донесения, журналы боевых действий, книги) и обработайте моделью: кроме
записей базы знаний модель выписывает сведения о мостах, переправах, дорогах и железных дорогах — что, где, в
каком состоянии, с какой даты, чьими силами, с дословной цитатой (без цитаты сведение отбрасывается). Видно, что
извлеклось из каждого документа: записей, дополнений, сведений об инфраструктуре; у каждого сведения — где оно на
театре (мост театра у пункта, точка на реке, круг у пункта) и что меняет в расчёте. Принятое ложится поверх
театра при расчёте, в игре и в сравнении: мост не действует с даты, наведённая переправа действует, перекрытая
или заминированная дорога не даёт дорожного темпа (как вне дорог); повреждённый, но проходимый мост, рубежи,
железные дороги — сведения (в расчёт не входят). Сведения можно добавить вручную и убрать (✕). Пакет операции
при скачивании включает их (`infrastructure`).

**База знаний по операциям.** Документы, загруженные в операцию (или в «Знаниях» при выбранной операции),
относятся к ней: новые записи — в её разделе, дополнения общих записей отмечают операцию. В «Знаниях» вверху —
«Операция»: все материалы, общие (без операции) или одна операция — записи из её документов и относящиеся к ней
по периоду и рубрикам. Записи из документов одной операции другие операции не дополняют и в справку советника
другой операции не попадают. Принятые сведения об инфраструктуре пишутся и в запись «Состояние инфраструктуры»
операции (раздел «Театр», рубрики «Переправы и мосты», «Дороги и транспорт»).

## 13. Полнота материалов операции

Перед моделированием видно, насколько полно набраны материалы, — не оценка модели, а проверка по каркасу базы
знаний: для каждого элемента операции известно, какие сведения должны быть, и считается, какие есть (по фактам
записей).

| Группа | Элементы | Что должно быть |
|---|---|---|
| Войска | каждое формирование сценария (запись — по id сценария в синонимах или по названию) | подчинённость, командир, состав, численность, танки и САУ, орудия, боевой путь в операции (армии и фронты — без подчинённости) |
| Командование | командующие армий и фронтов (по фамилии из записи формирования) | звание, должность в операции, ключевые решения |
| Пункты и районы | места событий истории, опорный пункт, главные цели приказов (до 15) | что это, где, особенности, оборона (гарнизон, укрепления), значение |
| Рубежи и укрепления | полосы и позиции театра в районе действий | где, устройство, оборона, значение |
| Реки и переправы | большие реки в районе действий | особенности, переправы и мосты, значение |
| Операция | запись операции | даты, театр, стороны, командование, замысел, силы, итог, потери |
| Ход событий | события истории | запись хроники или боя на ту же дату (±1 сут) о том же |

Элемент заполнен на долю найденных сведений, группа — в среднем, операция — взвешенно (войска 30 %, события
20 %, пункты 15 %, командование, рубежи, операция по 10 %, реки 5 %). Уровни: от 75 % — достаточно для
моделирования, 45–75 % — частично, меньше — сначала собрать материалы. Отдельно — качество: доля фактов с
источником или цитатой и с достоверностью A/B.

Где видно: «Моделирование» → «Операции» (у каждой операции, по группам и элементам — каких сведений нет),
«Знания» → «Полнота» (для выбранной операции), «Переигровка» (строка над расчётом). «Что собрать (.md)» —
недостающее списком, задание на поиск материалов. Документы, загруженные в операцию, разбираются моделью по тем
же ключам (у пунктов и рубежей — и «оборона», у рек — «переправы и мосты»), полнота пересчитывается сама. Своя
операция с малой полнотой готовится к переигровке только после подтверждения.

## Что модель пока не умеет (известные ограничения)

- Подвоз: исправлено — окружение считалось по положению после хода, и наступающие армии «отрезались»; теперь
  отрезанными оказываются лишь армии, прорвавшиеся далеко в глубину, когда коридор за ними держит противник.
- Местность — современные спутниковые данные и OSM с историческими поправками только для
  Берлинской операции (автобаны 1945 г., дорожная карта РККА, план Берлина 1945 г.).
- Соединения — точки с полосой обороны; в городском бою гарнизоны секторов представлены
  точками, поэтому события в центре Берлина наступают раньше истории.
- На контрольной операции (Висла — Одер) модель повторяет прорыв первых дней, но во второй
  половине расходится: на юге мало немецких соединений в данных, пехотные армии отстают от
  передовых отрядов, по которым записаны исторические положения.
