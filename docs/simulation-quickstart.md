# Переигровка операций: запуск у себя

Как запустить симуляцию на своём компьютере, посмотреть ход операции на карте и
сравнить его с историей. Всё работает локально, интернет нужен только для `npm install`.

## Что нужно

- Node.js 22 или новее (`node -v`), npm;
- репозиторий на ветке `claude/tactical-map-step1`;
- для «немецкого штаба» (необязательно) — LM Studio с загруженной моделью (см. ниже).

Docker, Python и исходные данные местности не нужны: карты местности (`packages/sim/data/theatres/*.json`)
и сценарии уже собраны и лежат в репозитории.

## 1. Установка

```bash
git checkout claude/tactical-map-step1
git pull
npm install
```

## 2. Переигровка в приложении (проще всего)

```bash
npm run dev            # http://localhost:5173/
```

Слева — колонка разделов: **Редактор**, **Переигровка**, **Карты** (подложки), **Знаки**
(справочник), **Штаб** (связь с моделью, которая командует противником в игре). Откройте **Переигровку**:

1. Выберите сценарий — Берлинская операция, бой в Берлине или контрольная Висло-Одерская.
2. **Правила** — откалиброванные (по умолчанию) или исходные, до калибровки: так видно, что дала калибровка.
3. **Seed** — номер случайного прогона (один seed — один и тот же расчёт); **Прогонов** — сколько
   прогонов с разными seed посчитать, чтобы увидеть разброс.
4. **«Рассчитать»** — расчёт идёт прямо в браузере (5–30 с, сервер не нужен). Справа — карта с
   плеером времени, кнопки слоёв «История», «Фронт», «Бои», «Рубежи» и выбор подложки. Слева — доля
   положений в допуске, сколько событий совпало с историей и расхождение в сутках по каждому прогону
   (зелёный — ±1, жёлтый — ±2, красный — больше, «—» — не случилось).
5. **«Отчёт»** — полный отчёт о сравнении с историей (можно скачать); **«В редактор →»** — открыть
   результат в редакторе для правки, экспорта и сохранения на сервер.

## 3. Прогон всех сценариев одной командой (терминал)

```bash
npm run sim:demo
```

Около минуты. Три сценария, по 5 прогонов каждый (разные случайные числа — видно, насколько результат устойчив):

| Сценарий | Что это | Чем проверяется |
|---|---|---|
| `berlin-1945-tasks` | Берлинская операция 16.04–2.05.1945: армии и корпуса, на Зееловских высотах — дивизии | 10 ключевых событий (прорыв к Мюнхебергу, котёл 9-й армии, кольцо у Кетцина, Торгау, Штеттин, Рейхстаг…) и ~220 исторических положений |
| `berlin-city-1945` | Бой в Берлине 24.04–2.05: корпуса и гарнизоны секторов, клетка 250 м | Темпельхоф, Александерплац, мост Мольтке, Рейхстаг, Рейхсканцелярия; положения ±2 км |
| `vistula-oder-1945` | Висло-Одерская операция 12.01–3.02.1945 — **контрольная**: правила Берлинской операции без подгонки | 13 событий и ~150 положений |

Обе стороны получают **исторические задачи** (наступать на…, держаться, отходить), а не
исторические положения: темпы, окружения и исходы боёв считает арбитр. В конце — сводка:
доля положений в допуске и сколько событий совпало с историей в пределах двух суток.

Варианты:

```bash
npm run sim:demo -- --only berlin          # только Берлинская операция (city, vistula — другие)
npm run sim:demo -- --runs 1               # быстрее: по одному прогону
```

Результаты — в `evals-out/demo/<сценарий>/`:

- `report.md` — сравнение с историей: события (история / расчёт), отклонения по дням и
  формированиям, наибольшие расхождения, журнал боёв с факторами (соотношение сил,
  местность, укрепления, подготовленная оборона, случайность);
- `map.json` — карта для редактора.

## 4. Посмотреть на карте

```bash
npm run dev            # редактор: http://localhost:5173/
```

В редакторе — **«Открыть / импорт…»** → `evals-out/demo/berlin-1945-tasks/map.json`.

- ползунок времени внизу — ход операции (знаки двигаются, на каждом — состояние:
  «наступает», «обороняется», «ОТРЕЗАНО», боеприпасы);
- слои: расчёт (знаки, линия фронта, стрелки боёв) и история (бледные «призраки» на
  исторических местах, исторические линии фронта) — их можно включать и выключать в
  панели слоёв, чтобы сравнивать;
- линия фронта расчёта — граница территорий сторон: территория переходит к стороне
  только там, где прошли её войска.
- когда в расчёте взят Рейхстаг (в радиусе 1 км нет противника), над ним появляется
  **Знамя Победы** (слой «особые отметки»); бледное знамя в слое истории — историческое
  время, 30.04, 22:40.

С платформой целиком (хранение карт на сервере):

```bash
./scripts/start-local.sh                                  # http://localhost:8080/ (нужен Docker)
npm run sim:demo -- --publish http://localhost:8080       # карты сразу сохраняются на сервер
```

## 5. Отдельные команды

```bash
# один сценарий, свои параметры
npm run sim:history -- --scenario berlin-1945-tasks --runs 5 --out evals-out/my-run
#   --rules ww2-berlin-cal   правила (по умолчанию — указанные в сценарии)
#   --seed 3                 случайные числа
#   --tolerance 10           допуск, км

# пересобрать сценарий после правки рецепта (задачи, численность, события)
npm run sim:scenario -- packages/sim/data/scenarios/src/berlin-1945-tasks.recipe.json

# перекалибровать правила по Берлинской операции (~12 минут)
npm run sim:calibrate -- --evals 200 --seeds 2

npm test                # тесты
```

Где что лежит:

| Путь | Что |
|---|---|
| `packages/sim/data/scenarios/src/*.recipe.json` | рецепты сценариев: соединения, численность, **исторические задачи** с источниками, события для проверки, источники подвоза |
| `packages/sim/data/rules/` | правила арбитра: `ww2-draft` — исходные, `ww2-berlin-cal` — откалиброванные (с блоком `calibration`: на чём и как подобраны) |
| `packages/sim/data/profiles/` | профили сторон: РККА-1945, вермахт-1945 (типы частей, скорости, полосы обороны, снабжение, задержка доведения приказов) |
| `packages/sim/data/theatres/` | карты местности: покров, реки, дороги, мосты и переправы, оборонительные полосы |
| `docs/sources/` | исторические данные с источниками и достоверностью (A/B/C) |

## 6. Игра: вы — советская сторона, модель — немецкая

С любого момента переигровки командование можно взять на себя и вести операцию до конца.

1. **LM Studio** → загрузить модель (сейчас — Qwen3.8 27B 4-bit) → вкладка Developer → **Start Server**
   (по умолчанию `http://localhost:1234/v1`). Длина контекста — не меньше 16 000 токенов.
2. `npm run dev`, раздел **Штаб** → «Проверить связь»: должна появиться модель. Там же — выбор модели и
   режим размышления. Без размышления решение занимает 1–2 минуты, с ним — в разы дольше.
3. **Переигровка** → «Рассчитать» → ползунком выбрать момент → кнопка **«Принять командование»** на карте.
   Командование передаётся с начала хода (в Берлинской операции ход — сутки, в бою в городе — 12 ч).

С этого момента и до конца операции:

- **советской стороной командуете вы.** Вернуть командование историческому плану нельзя. Исторические
  приказы после этого момента отменяются; приказы, отданные раньше и ещё не дошедшие до войск, остаются в силе;
- **немецкой стороной командует штаб на модели.** Он вступает в игру одновременно с вами. На каждом ходу
  ему уходит своя обстановка: доклады своих соединений, противник в пределах разведки, итоги суток,
  пункты вблизи войск, ограничения сверху (приказы фюрера). Обе стороны решают одновременно — модель
  думает, пока вы пишете приказы;
- **противник виден только в пределах разведки** (туман войны): около 24 км от ваших войск в операции,
  6 км в городе.

Вся штабная работа советской стороны — на вас. Что до передачи командования шло по историческому
графику, дальше — только по вашим распоряжениям: исторические приказы, наводка переправ и ввод резервов
Ставки после этого момента сняты, тыл переходит под ваше управление.

| Вкладка | Что там |
|---|---|
| Доклады | оперативная сводка на утро: объединения в строю, укомплектованность, отрезанные; донесения за ход; достигнутые контрольные рубежи; доклады объединений по фронтам — положение, задача (историческая или ваша), состав, боеприпасы, горючее, усталость, бои за ход, приказы в пути |
| Разведка | разведсводка: обнаруженные соединения противника, где, что делают, оценка сил (округлённо), расстояние до наших; «новое» — обнаружено за последний ход |
| Решение | решение на ход — те же части, что у штаба противника: **оценка обстановки**, замысел противника, **решение (замысел действий)**, риски, **боевое донесение в Ставку**. Без выделенных полей ход не проводится. Замысел и риски переносятся с прошлого хода для правки; для донесения есть черновик по докладам |
| Приказы → Войска | боевое распоряжение: объединение (из списка или щелчком по знаку на карте) → задача → цель: пункт, соединение противника или точка на карте → указания. Видно, когда приказ дойдёт до войск (армиям — 6 ч). Проект приказов рисуется на карте стрелками (слой «Замысел») |
| Приказы → Тыл | базы снабжения: перенос вперёд (на время переноса база не действует: сутки на развёртывание и переезд ~60 км/сут; на чужой территории не работает); приоритет подвоза — не более трети объединений, им ×1,5, остальным ×0,75; время подвоза до каждой армии против предела (48 ч) |
| Приказы → Переправы | наводка переправ: щелчок по реке (слой «Реки»), большая река — сутки, малая — 12 ч, рядом должны быть наши войска, понтонных парков — 3. Без переправы техника большую реку не пройдёт, подвоз — тоже |
| Приказы → Резервы | резервы Ставки (например, 28-я армия): ввод по вашему решению — район сосредоточения на своей территории; армия будет там не раньше готовности и не раньше чем через сутки |
| Журнал | журнал боевых действий по ходам: ваше решение, приказы, распоряжения (и что не исполнено — с причиной), донесения; скачивается в .md |
| Посредник | решения штаба противника: оценка обстановки, замысел, приказы (что исполнено, что отброшено и почему), доклады наверх, риски; ход размышления в реальном времени; снять туман войны. Если играете честно — смотрите после игры |

Немецкой стороне тыл, переправы и резервы пока идут по историческому графику: модель отдаёт только
приказы войскам.

**«Провести сутки»** утверждает решение, отдаёт приказы и распоряжения обеих сторон и считает ход. Если модель не ответила, ход ждёт:
можно повторить запрос или провести ход без новых приказов противника. Игра сохраняется в браузере после
каждого хода. Её можно продолжить с карточки «Незавершённая игра» в Переигровке или скачать запись
(меню «⋯»). По записи игра восстанавливается целиком: движок детерминирован.

Без LM Studio стенд можно проверить на **подставной модели** — её решения простые, только для проверки
интерфейса:

```bash
npm run llm:mock        # в отдельном терминале: отвечает на http://localhost:1234/v1, как LM Studio
```

Или при взятии командования выбрать «Без штаба» — противник держится прежних приказов.

Проверка модели на контрольных обстановках (без игры):

```bash
npm run llm:quick                       # одна обстановка, приказы печатаются по мере готовности
npm run llm:quick -- --only 04 --full   # другая обстановка и полный доклад с размышлением
npm run llm:eval                        # все контрольные обстановки и отчёт
```

Настройки — переменные окружения: `DEFOPS_LLM_URL` (куда сервер разработки направляет `/llm`),
`DEFOPS_LLM_MODEL`, `DEFOPS_LLM_THINKING` (`off` / `low` / `medium` / `xhigh`), `DEFOPS_LLM_TIMEOUT_S`.
В собранном приложении (без `npm run dev`) в разделе «Штаб» укажите адрес `http://localhost:1234/v1`
и включите в LM Studio CORS (Developer → Settings → Enable CORS).

## Что модель пока не умеет (известные ограничения)

- Подвоз: в Берлинской операции часть советских армий 17–22.04 числится отрезанной от подвоза (на
  плацдармах у Франкфурта и на Нейсе в данных не хватает переправ). В игре это видно в докладах.

- Местность — современные спутниковые данные и OSM с историческими поправками только для
  Берлинской операции (автобаны 1945 г., дорожная карта РККА, план Берлина 1945 г.).
- Соединения — точки с полосой обороны; в городском бою гарнизоны секторов представлены
  точками, поэтому события в центре Берлина наступают раньше истории.
- На контрольной операции (Висла — Одер) модель повторяет прорыв первых дней, но во второй
  половине расходится: на юге мало немецких соединений в данных, пехотные армии отстают от
  передовых отрядов, по которым записаны исторические положения.
