# Сборка комплекта для Windows x64

Процедура и скрипт `scripts/portable-build-win.ps1` подготовлены, но на Windows не запускались.
Готового проверенного Windows-релиза эта инструкция не подтверждает. Целевая приёмка — Windows 10 x64,
RTX 4060 Ti 16 ГБ, три независимых дисплея. Объём RAM целевого компьютера нужно выяснить до сборки.

## Готовый набор для переноса и запуска сборки

Архив `defops-windows-build-kit.zip` распаковывают на локальный SSD Windows и открывают
`BUILD-WINDOWS.cmd`. Это набор для сборки, а не готовый EXE. Скрипт проверяет SHA256 входных файлов,
использует комплектный Node, устанавливает отсутствующие Microsoft C++ Build Tools с системным запросом
администратора и подготавливает закреплённый Rust 1.99.0 MSVC. На этой стадии нужен интернет:
инструменты, npm и Cargo ещё получают зависимости. Голосовые модели и wheels уже включены.
Набор после исправления TBB содержит 112 wheels, включая закреплённые `tbb` и `tcmlib`.

Если ранний комплект остановился с `Невключённая DLL: tbb12.dll`, используйте малый патч
`defops-tbb-fix.zip`: распакуйте его и запустите `FIX-TBB.cmd` для комплекта в `D:\k`.
Другой путь задаётся через `FIX-TBB.ps1 -KitRoot <путь>`. Патч проверяет версии изменяемых файлов,
сохраняет резервные копии манифестов и исходников, добавляет два wheel и обновляет только связанные
контрольные суммы. Проверка остальных файлов и DLL не отключается. Повторная сборка создаёт новую попытку.
Нативные DLL из `Library/bin` переносятся рядом с Python, отладочный `tcm_debug.dll` не включается.
Microsoft C++ runtime берётся из `VCToolsRedistDir` установленного Build Tools. Необязательные адаптеры
Torchaudio для shared FFmpeg 4–6 исключаются; работоспособность чтения WAV через SoundFile проверяется
на целевой Windows перед продолжением сборки.
Полный WebView2 включён; перед его использованием проверяется подпись Microsoft.

Каждая попытка создаёт отдельную папку `work`, журнал сохраняется в `logs`. После успеха
`LAST-BUILD.txt` указывает готовую папку в `output`; в ней запускают `launch.cmd`. Переносить на
другой компьютер нужно всю папку готового приложения. LM Studio и выбранные LLM/embeddings остаются
внешними зависимостями. Рекомендуемый запас места для сборки — 60 ГБ; повторные попытки занимают
дополнительное место, старые файлы автоматически не удаляются.

Стартовый сценарий явно включает `-DiagnosticCandidate`: два известных падения `expo-turns.test.ts`
по монотонности оценки промедления допускают только приёмочную сборку с `test_status=diagnostic-candidate`.
Полные сообщения остаются в `test-assessment.json`; это не успешный тестовый прогон и не исправление
модели. Иная причина падения, другой тест или неполный отчёт останавливают сборку. Прямой вызов
`portable-build-win.ps1` без этого параметра остаётся строгим. Перед тестами собирается свежее ядро
`agents-game.exe`, его отсутствие теперь не приводит к молчаливому пропуску обязательной проверки.

Результат сборки — папка приложения, которую целиком копируют с флешки на локальный диск и открывают через
`launch.cmd`. Пользователю не нужны Node, Python, FFmpeg, Rust или инструменты разработчика. LM Studio
устанавливают отдельно; основную модель, модель голосового диалога и embeddings выбирают в мастере
приложения. Интернет нужен заранее для получения этих моделей, затем работу проверяют без сети.

## Сборочная машина и входные файлы

Сборка выполняется на Windows x64 с NVIDIA GPU, достаточной для одновременной проверки голосового стека.
Установите Visual Studio Build Tools с разработкой классических приложений на C++ и Windows SDK,
Rust MSVC `x86_64-pc-windows-msvc`, Node с npm. Откройте **Developer PowerShell for VS**:
в нём должен находиться `dumpbin.exe`. Это зависимости сборочной машины.
Требования к Windows-сборке описаны в [документации Tauri](https://v2.tauri.app/start/prerequisites/).

Подготовьте до отключения сети:

1. Исходники той же версии, `package-lock.json` и `Cargo.lock`. На Windows используйте отдельную чистую
   рабочую копию: не переносите `node_modules`, Python venv, macOS runtime и скомпилированные библиотеки Mac.
2. Полную автономную **CPython 3.12 x64**, например соответствующую сборку
   [python-build-standalone](https://github.com/astral-sh/python-build-standalone/releases).
   У `PythonRoot` должен находиться `python.exe`; каталог не должен быть venv. Сохраните исходный архив,
   его SHA256 и тексты лицензий. Само наличие Python 3.12 не доказывает автономность DLL.
3. Полную Windows-сборку FFmpeg с `ffmpeg.exe`, её DLL, лицензиями и требуемыми материалами распространения.
   Сохраните точный архив и SHA256. Каталог `FFmpegDirectory` передаётся целиком.
4. Windows wheelhouse голоса из `services/voice/setup.ps1` с `manifest.json` и CUDA wheels.
   Он отличается от набора Python-пакетов macOS. Скрипт сверяет состав и контрольные суммы каждого wheel.
5. Веса из `services/voice/prepare_models.py`: qwen3-ru-stress, речевой токенизатор, GigaAM,
   Smart Turn. Скрипт закрепляет ревизии и создаёт контрольный манифест. Каталог моделей копируют целиком;
   Windows использует исходные Torch-веса, а не MLX-веса Mac.
6. Папку пользовательских данных приложения и экспорт JSON из «ИИ → Модели, словарь и перенос библиотеки →
   Библиотека». Одной папки файлов недостаточно: JSON содержит пользовательский слой IndexedDB.
   Удалённые записи из другого профиля не восстанавливаются автоматически; для исходного комплекта нужен
   актуальный полный экспорт. Секреты, настройки LM Studio, PIN и назначения дисплеев не входят в экспорт.
7. Автономный установщик **WebView2 Evergreen Standalone Installer x64**, полученный на
   [сайте Microsoft](https://developer.microsoft.com/en-us/microsoft-edge/webview2/).
   Нужен полный установщик, а не маленький сетевой bootstrapper. Сохраните файл и утверждённый SHA256:
   сборщик проверяет SHA256 и действительную подпись Microsoft.
8. Голосовой WAV-образец и его точную текстовую расшифровку для реального smoke-теста синтеза и распознавания.
   Используйте образец, право включения которого в комплект подтверждено владельцем.

Подготовка wheels и весов на Windows, из корня репозитория:

```powershell
# Эти операции выполняются с интернетом. Пути могут содержать пробелы и кириллицу.
.\services\voice\setup.ps1 `
  -Python 'D:\Сборка\python\python.exe' `
  -VenvPath 'D:\Сборка\подготовка-голоса' `
  -PrepareWheelhouse 'D:\Сборка\voice-wheels'

.\services\voice\setup.ps1 `
  -Python 'D:\Сборка\python\python.exe' `
  -VenvPath 'D:\Сборка\подготовка-голоса' `
  -Wheelhouse 'D:\Сборка\voice-wheels'

& 'D:\Сборка\подготовка-голоса\Scripts\python.exe' `
  .\services\voice\prepare_models.py --models-dir 'D:\Сборка\voice-models'
```

Сборка приложения также выполняет `npm ci` и Cargo с `--locked`; первая сборка скачивает зависимости.
Официальный Node для конечного приложения получает `scripts/portable-node.mjs`, с закреплёнными версией
и SHA256. Поэтому передачу исходников и компиляцию на Windows завершите **до** перехода целевого стенда
в автономный режим. Сборка самих исходников без сети требует отдельно подготовленных npm/Cargo-кэшей
и здесь не аттестована. Готовое приложение использует собственные runtime и ресурсы.

## Запуск единой сборки

Пример; значения SHA256 и расшифровки замените своими:

```powershell
.\scripts\portable-build-win.ps1 `
  -DataDirectory 'D:\Перенос\данные' `
  -LibraryArchive 'D:\Перенос\user-library.json' `
  -PythonRoot 'D:\Сборка\python' `
  -Wheelhouse 'D:\Сборка\voice-wheels' `
  -ModelsDirectory 'D:\Сборка\voice-models' `
  -FFmpegDirectory 'D:\Сборка\ffmpeg' `
  -WebViewInstaller 'D:\Сборка\MicrosoftEdgeWebView2RuntimeInstallerX64.exe' `
  -WebViewSha256 '<64 шестнадцатеричных символа утверждённого SHA256>' `
  -ReferenceAudio 'D:\Перенос\образец.wav' `
  -ReferenceText 'Точная расшифровка голосового образца.' `
  -Output 'D:\Готовые комплекты\Тактическая карта Windows'
```

Скрипт останавливается, если уже существуют выходная папка, `release/windows-build`,
`apps/desktop/portable/runtime` или `apps/desktop/portable/library`. Он не удаляет прежнюю сборку или
пользовательскую библиотеку. Для повторения сохраните результаты и используйте чистую рабочую копию.
Если сборка упала, незавершённые папки остаются для диагностики; перед следующей попыткой их нужно
перенести отдельно. Не принимайте наличие папки за признак успешного завершения.

Последовательность: `npm ci` → официальный Node → venv из wheelhouse → автономный runtime с проверкой DLL
и CUDA → библиотека с SHA256 → каталог слов и подсказок → загрузка Cargo-зависимостей и лицензии → свежее ядро, TypeScript и тесты → Tauri release без упаковки → папка ресурсов →
реальный голосовой smoke из конечного runtime с запрещёнными исходящими сокетами → полный манифест.
Журналы проверок и результат голосового smoke сохраняются в `release/windows-build`.

Параметр `-RuntimeSourceLock <прежний runtime/manifest.json>` требует точного совпадения файлов runtime
при повторной сборке. Сохраняйте вместе исходники, lock-файлы, версии Rust/Node, исходные дистрибутивы,
wheelhouse, модели и полный `build-report.json`. Это повторяемая процедура с контролем входов;
побитовая воспроизводимость Windows-бинарника не проверена.

## Структура готовой папки и запуск

```text
launch.cmd
launch.ps1
defops-desktop.exe
node.exe
server/
editor/
data/packages/sim/data/
portable/runtime/
portable/library/
portable/licenses/
prerequisites/MicrosoftEdgeWebView2RuntimeInstallerX64.exe
build-report.json
manifest.json
```

Пути ресурсов соответствуют `apps/desktop/src-tauri/tauri.conf.json` и запуску служб в `main.rs`.
Большие runtime, карты и модели остаются отдельными файлами. Стандартный NSIS ограничен размером
установщика около 2 ГБ; его документация рекомендует держать большие данные отдельно.
Поэтому полная поставка здесь собирается папкой, без единого NSIS EXE.
[Ограничение NSIS](https://nsis.sourceforge.io/I_get_an_error_when_compiling_large_installers).

`launch.cmd` вызывает собственный `launch.ps1`. Он сообщает об объёме RAM и проверяет наличие WebView2 через значение `pv`
в HKCU/HKLM с обеими разрядностями представления реестра. Если runtime отсутствует, сверяет SHA256
комплектного установщика и запускает `/silent /install` обычным пользователем, затем повторяет проверку.
При отказе установки приложение не стартует. Так устроена
[рекомендованная Microsoft проверка и автономная установка WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution).
Политики конкретной организации могут запрещать пользовательскую установку — это проверяется на приёмке.

Скопируйте всю папку на локальный SSD, затем открывайте `launch.cmd`. Работа непосредственно с флешки
не является проверенным режимом. Флешка должна поддерживать файлы больше 4 ГБ, например exFAT;
при переносе сохраняйте комплектный `manifest.json`. Не удаляйте вложенный Python или файлы моделей.
Первый импорт пишет только недостающие пользовательские данные; неудачный импорт блокирует запуск
до повторной попытки. Обновление не должно заменять ручные изменения уже установленного профиля.

## RAM, VRAM и три экрана

Сборщик и launcher сообщают об объёме RAM. Параметр `MemoryWarningGB` по умолчанию равен **32 ГБ**
и управляет только справочным предупреждением: он не блокирует сборку или запуск и не задаёт
подтверждённый минимум. Минимальный объём RAM не измерен; его следует определить для выбранного набора
моделей. Указанные для RTX 4060 Ti **16 ГБ относятся к видеопамяти**, а объём RAM целевой машины
пока неизвестен. Окончательная конфигурация Windows 10 / RTX 4060 Ti не подтверждена.

16 ГБ видеопамяти делят основной LLM, голосовая LLM, embeddings и TTS/ASR. Даже успешный импорт Torch
и отдельный синтез не доказывают, что весь набор поместится одновременно. Приёмка должна измерить
свободную RAM/VRAM, пиковое потребление при совместной работе и задержку полного ответа. Можно назначить
один и тот же LLM основной и голосовой роли, уменьшить контекст и выгрузить лишние модели LM Studio;
после изменения конфигурации повторите реальный прогон. Размер модели выбирается по измерению,
а не только по обозначению видеокарты.

Подключите все три дисплея, в Windows выберите **«Расширить эти экраны»**, проверьте их порядок.
Дублирование рабочего стола не даёт трёх независимых экранов. В меню оператора выберите число экранов,
назначьте мониторы и покажите их номера. Порядок старой машины не переносится. Launcher сообщает,
если Windows видит меньше трёх экранов; приложение остаётся доступным для настройки.

## Приёмка до передачи посетителям

Проводится на отдельном чистом профиле Windows без Node, Python и FFmpeg в PATH:

- Копирование в путь с пробелами и кириллицей, другая буква диска; запуск обычным пользователем без сети.
- Отсутствующий WebView2 устанавливается из комплекта; уже установленный не переустанавливается.
- Первая установка библиотеки, прерванный импорт и повторный запуск; сохранённые пользовательские правки
  остаются после обновления. Проверить файлы карт, аудио и реальный смысловой поиск.
- Выбор моделей LM Studio, оба настоящих запроса диалога и embeddings; смена embeddings вызывает
  переиндексацию. Проверить совместную память LLM и голоса, затем работу с отключённой сетью.
- Новое слово словаря, ручная правка и подсказка, живая озвучка и переозвучка; результат сохраняется
  после перезапуска. Готовые записи не меняются лишь от сохранения словаря.
- Оба фронта, интро, три перелома, итог, распознавание речи и полный звук без обрывов.
- Три независимых дисплея, повторный запуск с другим порядком мониторов, занятые служебные порты.

`build-report.json` сохраняет `clean_machine_test: required` даже после успешной компиляции и голосового
smoke на сборочной машине. Отдельный протокол этой приёмки нужен до объявления Windows-комплекта готовым.

Продолжение сохранённой подготовки: `RESUME-BUILD.cmd` из малого комплекта продолжения.
Полный прогон включает тесты символических ссылок: в Windows нужны права создания ссылок
(режим разработчика или запуск сборочного CMD от администратора). Тестовые файлы запускаются
последовательно, порог скорости ядра сохраняется. Для подставного сборщика театра используется
комплектный Python через `THEATRE_PYTHON`, без зависимости от системного `python3`.
