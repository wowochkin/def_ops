# Движок переигровки (`@def-ops/sim`)

Универсальный: операция, эпоха и стороны — данные, а не код (план —
`docs/plans/simulation.md`, раздел 3а). Детерминирован при заданном
начальном числе: один seed — один и тот же прогон.

## Пакеты данных (`data/`)

| что | файл | содержит |
|---|---|---|
| профиль стороны и эпохи | `profiles/<id>.json` | типы формирований и их качество; вклад в силу людей, танков, орудий; темпы по местности и дорогам; расход боекомплектов и заправок по видам действий; задержки доведения приказов |
| правила (калибровка) | `rules/<id>.json` | расстояние соприкосновения; темп продвижения и потери от соотношения сил (таблицы); поправки обороны (местность, подготовка, укрепления); снабжение, усталость, разброс; переправы |
| театр | `theatres/<id>.json` (`TheatreData`) | растр местности (`terrainGrid`, RLE) и контуры поверх; дороги, реки, мосты и переправы (с моментом наведения и разрушения), районы, рубежи с укреплённостью; источники и оговорки |
| сценарий | `Scenario` | стороны и кто их ведёт; формирования на начало; приказы (исторический план или изменения эксперта); длительность хода |

Числа в `rkka-1945`, `wehrmacht-1945`, `ww2-draft` — **черновик до
калибровки** (этап 2).

## Театр из открытых данных (`tools/theatre`)

Театр собирается по «рецепту» (`data/theatres/src/<id>.recipe.json`):
охват и шаг сетки, правила классификации, большие и малые реки, какие
магистрали считать шоссе, исторический слой (рубежи, переправы, разрушенные
мосты, районы).

```
python3 -m venv .venv && .venv/bin/pip install -r tools/theatre/requirements.txt
.venv/bin/python tools/theatre/build_theatre.py data/theatres/src/oder-berlin-1945.recipe.json
```

- **Местность:** ESA WorldCover 2021 (10 м) — доли классов по клетке
  (вода, застройка, болото, лес); «высоты» — по Copernicus DEM GLO-90:
  перепад в окне 3×3 клетки и уклон после сглаживания (модель поверхности
  включает лес и здания). Вне покрытия — море.
- **Реки, дороги, железные дороги:** OpenStreetMap (Overpass). Шоссе —
  только автобаны, существовавшие в 1945 г. (список в рецепте); остальные
  магистрали — дороги. Линии склеиваются и упрощаются.
- **Мосты:** пересечения дорог и железных дорог с большими реками; правила
  рецепта ставят даты разрушения, переправы задаются с моментом наведения.
- **Районы:** каждый пункт справочника — малый район (по нему ставятся
  приказы), плюс крупные: Берлин, Зееловские высоты, Шпревальд и др.

**Исторические поправки по растровым картам** (`overlays` в рецепте):
`raster_overlay.ts` распознаёт классы на исторической карте из тайлового
архива по правилам легенды (`tools/theatre/legends/*.json`: тон,
насыщенность, яркость пикселя; порог доли на клетку) и пишет маски на сетку
театра; сборщик кладёт их поверх современного покрова:

```
npm run theatre:overlay -- rkka10km.sqlitedb --legend rkka-road-1m --bbox 11.0,50.9,15.6,54.45 --zoom 10 \
  --out packages/sim/data/theatres/src/overlays/rkka-road-1m.json
npm run theatre:overlay -- retromap_151944.sqlitedb --legend berlin-plan-1945 --zoom 14 \
  --out packages/sim/data/theatres/src/overlays/berlin-plan-1945.json
```

- дорожная карта РККА 1:1 000 000 — сеть дорог 1940-х (`roadGrid`) вместо
  современных основных дорог в её охвате; реки на ней нарисованы шире, чем
  есть, — для местности не берутся;
- «План г. Берлин» 1945 г. — застройка, парки, вода того времени;
  послевоенная застройка в охвате плана понижается до открытой местности.

Рядом с маской пишется `*-preview.png` — распознанные пиксели цветом,
чтобы проверить легенду глазами. Нет файла поправки — театр собирается без неё.

Данные скачиваются один раз в `~/.cache/def-ops-theatre`. Современный
покров и сеть дорог — приближение к 1945 г.; оговорки — в файле театра.

## Сценарий из данных (`tools/scenario`)

Сценарий собирается из рецепта (`data/scenarios/src/<id>.recipe.json`) и
набора исторических данных (положения по дням, формат
`docs/sources/*-positions.json`):

```
npm run sim:scenario -- packages/sim/data/scenarios/src/berlin-1945.recipe.json
```

- **Состав:** какие формирования действуют, их тип из профиля, ввод позже
  (`enterAt`). Положение на начало — из набора данных.
- **Силы:** где по армии нет цифр, численность, танки и орудия фронта
  делятся между армиями пропорционально числу дивизий (после вычета заданных
  явно; доля боевых войск — `combatShare`). Такие цифры — оценка (C).
- **Исторические приказы:** к следующему известному положению; длинные
  промежутки делятся на суточные промежуточные цели. Советские — «наступать»,
  немецкие — «обороняться» или «отходить»; ручные приказы («держаться до…»)
  перекрывают автоматические.
- Рядом пишется `<id>.history.json` — положения и линии фронта для сравнения.

## Исторический прогон (`tools/run/history.ts`)

```
npm run sim:history -- --scenario berlin-1945 --runs 20 [--publish http://localhost:8080]
```

Обе стороны действуют по историческим приказам, арбитр считает движение и
бои; отчёт `report.md` — отклонения от истории по дням и формированиям
(сверх неопределённости исторического положения), бои с исходами и
факторами, итог по силам. `map.json` — карта для редактора (`Файл → Открыть`
или `--publish` в сервис документов): слои «Переигровка: свои / противник»
(знаки с ключевыми кадрами по ходам), «линия фронта», «бои за ход»,
«История: положения» («призраки») и «История: линия фронта», «Театр:
рубежи и переправы». Ползунок времени показывает ход операции.

## Исторические задачи и калибровка

Два сценария одной операции:

- `berlin-1945` — приказы «иди в историческую точку следующего дня»:
  проверка темпов и боёв, совпадение с историей почти «бесплатное».
- `berlin-1945-tasks` — **исторические задачи** армий и корпусов (166
  приказов): направления и рубежи, «держаться», «отходить», «прорываться»,
  цель-формирование («@de_v_ss»), со ссылками на источники. Темпы,
  окружения и сроки событий должны получаться в расчёте — это честное
  мерило модели.

Мерила (`report.md`): отклонения положений по дням сверх их
неопределённости и **ключевые события** с датами (прорыв Зееловских
высот, Шпрее у Шпремберга, Цоссен, окраины Берлина, окружение 9 А,
кольцо у Кетцина, Торгау, Штеттин, Рейхстаг): в расчёте раньше или позже
истории и на сколько суток.

```
npm run sim:calibrate -- --scenario berlin-1945-tasks --evals 120 --seeds 2
npm run sim:history -- --scenario berlin-1945-tasks --rules ww2-berlin-cal --runs 10
```

Калибровка подбирает множители к правилам (темп продвижения, потери,
подготовленная оборона, укрепления, местность, темп марша): сначала
широкий случайный поиск, затем уточнение вокруг лучшего. Подбор — только
по дням до `--train-until` (по умолчанию 25.04), дни после — проверка на
переобучение; итог и параметры записываются в `rules/ww2-berlin-cal.json`
(раздел `calibration`). Доказательство универсальности — прогон на
контрольной операции без подбора.

## Снабжение и окружение

Источники подвоза сторон задаются в сценарии (`supply`): переправы и
станции, тыловые районы. Подвоз идёт автотранспортом по дорогам в обход
зон влияния противника (клетки, где противник ближе 2 × расстояния
соприкосновения и ближе своих войск). Если подвоз не доходит за
`profile.supply.rangeHours`, формирование отрезано: не пополняется, не
может отойти (держится с повышенными потерями), в журнал — «окружено».
Отходящие отходят к своим тылам (где подвоз ближе), а не просто прочь от
наступающих.

## Ход (`step`)

1. Приказы, дошедшие до исполнителя (задержка — по ступени). Приказ можно
   подать в любой момент (`issueOrder`) — от эксперта, модели или сценария.
2. Бои: наступающие в соприкосновении; соотношение сил × поправки обороны ×
   случайный разброс → продвижение и потери по таблицам. «Удерживать любой
   ценой» — не отходят, повышенные потери, наступающие проходят только при
   прорыве. В журнал — все составляющие («почему так»).
3. Движение по маршрутам: сетка проходимости + дороги, A*; большая река —
   технике только по уцелевшему мосту или наведённой переправе. Встреча с
   противником останавливает: наступающие входят в соприкосновение (бой —
   в следующий ход), остальные останавливаются, не доходя.
4. Снабжение (расход и подвоз, окружение), усталость, подготовка обороны,
   потеря боеспособности (< 15 %).

`frontLine` — линия фронта по полю влияния сторон (положение важнее силы).

## Ограничения текущей версии

- Подвоз снабжения не моделируется (только расход) — следующий шаг.
- Маршрут пересчитывается каждый ход (A* по сетке): для сотен прогонов —
  кэш маршрутов и более крупная сетка.
- Линия фронта — между двумя сторонами (`sides[0]`, `sides[1]`).
